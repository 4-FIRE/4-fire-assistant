# 工具与业务职责重构设计

状态：前一次职责重构已实施。本文保留该次重构的行为基线、文件名和实施顺序，不代表后续 API 没有变化。完整能力接入与受控变更已按[能力设计](capability-design.md)调整；当前验证见[迁移记录](migration-plan.md)。

长期规则见[架构设计与开发要求](architecture-guidelines.md)。现有行为边界见[技术设计](technical-design.md)，已完成及待完成验证见[迁移记录](migration-plan.md)。本文不是一次新的 Pi 平台迁移。

## 1. 目标和非目标

首要目标是修正职责与依赖关系，其次才是调整文件组织。维护者应能根据变更类型找到负责人，不必通读整个插件才能修改一个功能。

本次采用两个主要层次：对外工具 API 与业务服务。业务模型使用贫血数据类；行为归服务。命令、生命周期、确认队列和技术接入一起整理。

保持以下约定不变：

- 工具名称、参数、输出结构、执行方式和可用范围。
- `/ffa` 命令行为和 Pi 资源发现、启用、重载语义。
- 初始化条件、专家权限、交易复核与单次发送边界。
- 工作区文件、数据库记录、审计事件和业务状态格式。
- 来源绑定与身份计算语义、CLI 参数传递和 MCP 调用路径。
- 计算限制、产物路径、失败与取消行为。

不新增业务功能、目录扫描、第三方工具扩展、ORM、通用任务运行时或兼容层。不迁移、删除用户工作区和历史记录。内部模块导入路径允许变化，不保留旧文件作转发入口。

重构中发现独立缺陷时，记录并单独说明，不静默改变上述行为。

## 4. 工具契约与注册

### 4.1 一工具一完整定义

每个工具文件导出工厂。工厂接收实际需要的服务与生命周期检查能力，返回 Pi 工具定义。

工具文件包含名称、说明、输入输出 schema、执行方式、`execute` 和专属渲染。专属请求响应在本文件定义或由 schema 推导。共同的工具结果包装放在 `tools/result.ts`。

执行意图输出同时供准备交易、执行交易和状态工具使用，放在 `tools/schemas/trade.ts`。只为真实共用的结构创建此类文件，不再建立全局 `outputs` 对象。

### 4.2 显式能力集合

保留当前工具集合和状态语义：

| 使用范围 | 工具 |
| --- | --- |
| 活动初始化与就绪工作区共用 | `ffa_sources`、`ffa_source_read`、`ffa_record`、`ffa_configure_source` |
| 活动初始化阶段 | `ffa_finish_initialization` |
| 就绪工作区主助手 | `ffa_python`、`ffa_status`、`ffa_prepare_trade`、`ffa_execute_trade`、`ffa_delegate`，加共用工具 |
| 专家基础能力 | `ffa_sources`、`ffa_source_read`、`ffa_record`、`ffa_python` |
| 本次独立复核专用 | 在专家基础能力上增加 `ffa_submit_review` |

此表列出 FFA 业务工具，不替代专家现有的完整资源约束。未开始或中断初始化时，不因文件被导入而注册业务工具。

`tools/register.ts` 显式组合主助手工具，设置公共 namespace 和指导信息。专家工具由 Pi 专家接入按服务提供的角色和受限调用能力装配，不自动继承主助手工具。

关闭时保持现有隐藏方式，同时使旧调用失效。完成初始化后继续通过原生 `/reload` 刷新，不在工具中新增热加载机制。

## 5. 服务与业务规则

### 5.1 来源服务

接管来源解析与业务校验、已确认操作查询、读写权限、绑定有效性、配置更新和查询证据保存。

CLI、Pi 数据 MCP 和私有 MCP 分别实现具体调用。通用进程执行供 CLI 与计算服务共用，不再从来源服务导出。

Pi MCP 接入封装实际工具查找和调用。工具侧或装配侧绑定本次宿主调用能力，服务接收普通数据和窄函数，不接收 `ExtensionToolContext`。不要另建统一行情接口。

配置流程仍需要撤销旧交易许可、用户确认和确认后的复查。这些顺序由明确的配置业务操作负责，不散落在工具或 UI 中。来源与交易服务不得相互依赖；需要撤销许可时由上层协调操作连接，或注入明确的失效通知能力。

### 5.2 初始化服务

接管入口中的完成条件：独立成功回执、当前来源绑定、必要目录和手册、用户确认、确认后重新核对，以及可靠保存完成状态。

工具只提供参数和确认能力。初始化命令也调用服务，不直接实现第二套初始化规则。向主会话发送引导消息和调用原生重载仍属于命令适配。

保留既有资料，不覆盖用户 `AGENTS.md`。初始化中断后不自动接续，也不提前发布投资资源。

### 5.3 交易服务与账本

交易服务接管准备交易入口中的写权限、参数预览、绑定取得与账本准备。复核、授权有效性、并发约束、发送和失败处理仍由服务控制。

`trade-ledger.ts` 管理执行意图状态及其持久记录。交易服务与账本直接取得必要存储依赖，不再通过 `sources.store` 间接访问数据库。

确认函数只返回用户选择。确认结束后检查请求、绑定、取消和健康状态。实际接入在写调用前检查并消费单次许可；账本发送前记录可靠提交后才可放行。

来源配置变化、请求变化、取消和相关会话事件使旧许可失效。执行回执不能覆盖；结果未知时阻止新写入；人工结案不授权重发。

### 5.4 专家服务

接管当前分支引用校验、研究员追问条件、独立复核必须使用新上下文、精确意图绑定、本次证据集合和异常撤销。

宿主适配读取当前分支并传入业务引用和请求范围。服务不直接遍历 Pi 会话对象。

Pi 专家接入负责模型配置、会话创建与接续、资源加载、实际工具集合和进度转换。它接收服务提供的本次受限能力，不反向导入专家服务实现。

`ffa_submit_review` 独立为工具文件。它调用本次复核能力；证据归属、会话有效性和交易复核规则不能只藏在工具闭包中。登记返回仍保持原契约。

新增专家引用写入 Pi 分支由宿主接入完成。专家会话和证据必须绑定原调用范围，不能在主会话切换后误挂到新分支。

### 5.5 计算和记录

计算服务负责归属路径、源码输入、运行记录、日志和产物保存。进程接入只执行程序并返回运行观察结果。保留当前取消、超限和产物语义，不增加计算调度器。

记录服务负责允许读取的记录类别和存在性。工具负责分页 API 与文本片段包装。业务失败与抛错的既有区别保持不变。

## 6. 模型与序列化

`model/` 包含来源、调用约定、查询回执、执行观察、执行意图、工作区状态和专家引用等业务数据类。请求范围是业务调用数据，不带 Pi 对象。

模型没有业务方法、持久化方法或 TypeBox 声明。必要构造只完成字段赋值。业务检查和状态变化归服务，工具不能修改服务内部对象。

当前 `canonical()` 只接受普通 JSON 对象。引入类后，必须显式转换为普通数据再进入以下边界：

- `json()`、规范化序列化和绑定摘要计算。
- SQLite 保存、审计记录和工作区状态文件。
- Pi `structuredContent`、工具详情及确认数据。
- 外部 CLI/MCP 参数和专家传递材料。

不放宽 `canonical()` 接受任意原型，不使用 `as Model` 代替构造。只在需要实例的业务入口明确还原，不增加通用映射框架。

保持原持久数据格式，不保存类名或原型信息。通过真实读写和序列化验证字段、可选值与枚举，不增加文件哈希校验。

## 7. 生命周期和装配

`index.ts` 只连接具体实现并注册命令、事件和资源入口。生命周期模块负责打开、关闭、请求范围以及活动实例有效性，不承接研究或交易工作流。

每次打开工作区创建独立实例及其取消控制。工具工厂绑定该实例，并检查其仍有效。旧工具引用不能通过可变全局 `get()` 静默访问后来打开的新实例。

请求范围在调用时取得，不在工具注册时永久捕获。专家证据集合每次新建。未消费许可不进入持久存储。

关闭时先使实例和许可失效，再取消活动调用并释放连接、存储和工具暴露。清理中的单个失败不能跳过其他必要清理；报告失败，但不能重新启用旧实例。重载、切换和异常打开路径都使用同一释放责任。

确认窗口和排队归 `ui/confirmation.ts`。队列只串行安排交互，不承担业务锁或流程编排。排队请求携带取消信号，已失效请求不能弹窗或继续业务。

## 8. 依赖检查的落地

实施时选择现成依赖分析工具，验证它与当前 TypeScript ESM、相对 `.js` 导入和类型导入兼容，再作为开发依赖接入检查命令。

至少检查：

- 模型不得引用服务、工具、存储、Pi 和 UI。
- 服务不得引用工具、UI、装配入口或 Pi SDK。
- 工具和命令不得直接引用底层存储与交易传输实现。
- 通用基础模块不得反向引用业务与宿主模块。
- 业务实现不得循环依赖。

Pi 专家接入装配专家工具是明确的宿主职责，不能误写成“所有接入模块禁止引用工具”。服务约定的类型引用也需要明确允许，不能为方便而豁免整套实现依赖。

不自建检查框架，不用业务测试断言源文件排列。已采用 dependency-cruiser 18.5.0。规则放在 `.dependency-cruiser.cjs`，通过 `npm run check:dependencies` 执行，并纳入 `npm run check`。

检查使用 TypeScript 配置解析相对 `.js` 导入，同时检查类型与动态导入。服务仅直接使用不含 Pi 的进程接入；其他宿主能力通过窄约定传入。接入模块允许类型引用服务约定，但不得运行服务实现。

实施时用临时文件验证了服务中的 Pi 类型导入和动态工具导入会失败。临时文件已删除，不建立源代码结构测试。

- 更新 `AGENTS.md` 的模块导航与架构文档入口。

每一步保持类型检查和相关本地测试可运行。临时拆分状态不作为最终提交结果。

## 10. 验收计划

| 风险 | 验证方式 |
| --- | --- |
| API 契约漂移 | 真实 SDK 加载工具，校验输入输出结构、结构化失败和分页行为 |
| 模型序列化变化 | 真实 JSON、SQLite 往返；核对字段、可选值和规范化输入 |
| 业务规则只存在于工具 | 直接调用服务与真实本地存储，验证非法准备、复核和状态变化被拒绝 |
| 未启用却产生资源或暴露工具 | 保留未初始化、中断和非交互场景的 SDK 与文件系统测试 |
| 旧实例和许可复用 | 真实会话生命周期、取消及重开场景；核对旧调用不能访问新实例 |
| 权限扩大 | 核对主助手、初始化和专家工具集合；保留嵌套调用边界验证 |
| 交易记录丢失或重发 | 真实账本事务、恢复、未知义务与人工结案测试；不发送真实交易 |
| 计算路径或进程行为变化 | 真实 Python、取消、越界、产物和失败记录测试 |
| 模块移动破坏包资源路径 | 从源码与生成测试导入验证资源路径，执行打包预览 |
| 依赖再次混杂 | 执行静态依赖检查，审查例外及责任归属 |
