# 完整能力接入与受控变更

本文说明当前能力目录与执行规则。验证范围与未完成的验收见[技术设计](technical-design.md#8-验证状态与验收边界)。

## 边界

能力目录记录当前凭据可见的全部工具，不按当前任务或服务名称裁剪。业务用途使用开放描述，不增加固定业务分类。

状态影响为 observe、change、unresolved。未分析和分析后仍不明确分别记录。已理解的操作记录用途、依据、后果和跨接口关系。变更另有 confirmation 或 independent 执行要求；订单、资金、后续自动执行、权限和重要资料破坏要求 independent。impacts 可以扩展；非空标签一律要求 independent，不能因未知标签自动降级。明确禁止的工具仍保留，记录原因。

模型分析是接入建议，不是对服务行为的证明。MCP annotations 只是线索。用户确认调用约定；实际入口检查约定、绑定、参数和许可。

## 目录与发现

ffa_discover_source 负责能力发现。MCP 使用 SDK listTools 的全部分页，保留原生工具定义。重复名称、分页错误或取消不能保存为完整发现。范围仅限当前连接和凭据；无法证明服务未公布的接口已覆盖。

首次 MCP 配置只确认连接，operations 为空。发现后新增工具为 unresolved/unassessed，不自动取得权限。分析通过 ffa_configure_source 提交，必须覆盖当前目录，不能改写原生定义。CLI 从服务文档建立完整已知目录，必须记录覆盖依据及缺口，不宣称自动枚举完整。

重新发现保留未变化工具的分析；原生定义变化或重新出现的工具撤销原分析。消失的工具保留为 unavailable。发现失败保留旧目录，但禁止调用，直到重新发现成功。每次 MCP 调用前重新核对全部目录；通知或凭据变化使绑定失效。修改连接后保留旧目录为不可用，必须重新发现。

## 宿主边界

FFA 管理的 MCP 全部使用私有连接，不向 Pi 注册原生工具。查询与变更都经 FFA 工具进入，同一连接校验目录和执行许可，避免 Pi 原生暴露绕过动态定义检查。

代价：FFA 来源不显示在 Pi /mcp 中；使用 ffa_sources 与 ffa_discover_source 查看和刷新。不实现 OAuth 管理，只支持环境变量凭据。其他 Pi MCP 服务不变。本地代码、Bash 和 Python 仍不是沙箱。

## 执行

ffa_source_read 只接受已确认 observe。ffa_prepare_change 与 ffa_execute_change 处理所有变更，共用执行服务和账本。

confirmation 变更须有当前请求准备记录和用户确认。independent 变更还需当前请求内的独立证据复核。确认展示用途、后果、依据、执行要求、连接和全部参数。所有变更使用同一发送前记录、单次许可、未知结果和人工结案规则。未知义务暂时阻止工作区所有新变更，查询继续可用，不做资源级锁框架。

当前工作区格式为 ffa-pi/2，业务数据库版本为 2。不兼容历史工作区。来源必须使用当前分类，意图必须明确 execution，不提供转换、降权适配或默认补全。旧格式直接拒绝，不自动迁移、重建或删除用户数据。

完成初始化前，所有可见能力均须有分析状态；无法确定的可记录依据并标为 uncertain，保持不可执行。更换来源类型必须使用新 ID，不覆盖旧目录。

## 验证

本地使用真实 SQLite、CLI、文件和 Pi SDK。验证完整目录合并、原生定义变化、未知和禁止能力、不支持的格式拒绝、确认要求、独立复核、取消、请求失效和未知义务。不得用模拟 MCP 服务或假模型替代外部验收。

外部 MCP 分页、通知、动态变化、真实模型分析、交互确认后的执行仍需获准环境。完整存储故障和进程终止场景也尚未完成验收。
