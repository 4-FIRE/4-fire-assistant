# 能力与权限设计

本文说明完整目录、工具权限和调用账本。接入方法见[接入技能](../resources/skills/provider-connections/SKILL.md)，配置字段与示例见[配置参考](../resources/skills/provider-connections/references/configuration.md)，宿主与验证边界见[技术设计](technical-design.md)。

## 1. 分开记录事实、验证和许可

provider（能力提供方）指外部 CLI 或 MCP，不指 `src/services/` 业务逻辑层。

| 概念 | 含义 | 不代表 |
| --- | --- | --- |
| 注册 | 已保存连接与配置 | 连接成功或接口可用 |
| 能力目录 | 当前凭据可见或文档已知的原生接口 | 每个接口都已验证或获准执行 |
| 验证 | 某次调用及其回执支持特定结论 | 后续调用仍可用或获准执行 |
| 权限 | 用户指定的调用批准方式 | 接口只读、低风险或业务成功 |

目录不按当前任务、能力提供方名称或业务类别裁剪。禁止、不可用、缺少绑定和待核实的接口仍保留，并明确限制。

手册记录资料依据、字段含义、接口关系、覆盖缺口和验证回执，不复制权限表。接入报告分别说明已注册、已验证、需确认和暂不可执行的内容。

## 2. 接入与发现

### MCP

使用 `ffa_provider_manage` 的 register 注册连接，不提交 operations、native 或 discovery。用户确认并保存后，程序发现当前凭据可见的全部工具分页。发现不调用业务操作，也不授予权限。

取得目录后，读取 permissions 对象及版本，通过 update permissions 的 suggest 模式提交初始建议并单独确认。发现失败保留注册和旧目录，但旧目录不能发送；仅刷新目录使用 discover，不重复注册。连接更新只提交完整连接配置，保留旧目录并使其失效，保存后自动发现。同样配置也可重新确认以修复认证并重建连接。

目录合并保留原生定义。变化接口更新定义，消失接口保留为不可用。重复名称、分页失败或发现期间的目录变化不能保存为完整发现。

### CLI

CLI 配置保存 PATH 中可直接执行的命令名，不保存本机绝对路径。注册和发送前解析并检查可执行文件；批准绑定当前 PATH 和解析目标，实际发送使用已核对的本机路径。更换机器需准备对应软件、PATH 与认证。

CLI 没有统一发现协议。依据完整帮助和可信文档建立已知目录，记录 `coverage.basis` 与 `coverage.limitations`，不声称自动覆盖所有接口。

可调用操作必须有完整参数绑定；没有绑定的接口保留为不可用。首次注册的连接、目录与初始权限可以一次确认。参数按原生 schema 校验，不自动转换类型或补默认值。

已有目录按接口增量维护：add 只新增，replace 只替换已知接口的完整可编辑定义，未列出的接口不变。不能通过遗漏删除接口，也不自动深层合并字段。整批校验和版本检查通过后一次保存；可附 coverage 一起保存，也可单独修改 coverage。

结果契约首次新增时可附带，后续通过 outcomes 分支设置或清除。replace 不接受 outcomes；输入或参数绑定变化时清除可能失配的旧契约，并在确认前展示。仅说明变化保留旧契约；MCP 原生契约变化不默认沿用。历史回执不重新分类。

### 连接与凭据

先检查原生认证及已有 profile。配置中的凭据字段只接受环境变量引用，不保存凭据值；这一限制不禁止复用原生 profile。ffa 不另建 OAuth 管理。

连接或凭据受阻时，继续完成不依赖连接的目录分析、手册和注册。只暂停必须通过连接验证的部分，不把注册成功写成验证成功。初始化主动引导用户提供工具信息，但信息暂缺或接入未完成不阻塞工作区启用；启用不改变接口的验证状态或执行许可。

ffa MCP 使用私有连接，不向 Pi 注册原生工具，也不显示在 `/mcp`。官方 MCP 由 Pi 和服务管理，其调用不受 ffa 审批或记录。

### 管理契约与变更结果

`ffa_provider_manage` 负责管理，`ffa_providers` 查询能力，`ffa_provider_call` 发送业务调用，`ffa_provider_record` 读取记录。管理工具使用 read/register/update/discover 四个 action；read/update 通过 target 区分 connection、operations、coverage、outcomes、permissions。完整字段见[配置参考](../resources/skills/provider-connections/references/configuration.md)。

可编辑数据与目录展示分开。管理读取返回对应对象与不透明 revision，更新提交 expectedRevision。版本按对象及相关契约依赖核对，接口 A 的编辑不无故阻塞接口 B；读取后变化和确认期间变化均阻止沿用旧数据。版本是当前工作区实例内的快照标识，重载后重新读取；不修改持久格式或进行文件哈希校验。

能力查询默认返回全部已知操作的用途摘要、身份、有效权限和可用状态；指定 provider 与 operation 返回完整契约。摘要投影只在工具返回层进行，不裁剪内部目录、原生缓存或调用绑定。所有读取不连接、不刷新、不创建发送意图。

变更分别报告 configSaved、configFiles、permissions 和 discovery。configFiles 仅列出本次已确认可靠保存的配置文件阶段；未列出不证明失败写入未发生。权限先于配置保存，二者不建立跨文件事务：权限已保存而配置失败时必须保留权限阶段的已完成事实。无法核实写入时报告 unknown 或 null，不猜成未写入。发现阶段的存储故障不伪装成远端发现失败；内部发现错误继续阻断发送。

参数错误定位字段，版本冲突指向重新读取。拒绝、取消、部分完成和未知结果不统一报告成功。可交付的阶段失败保留结构化结果并标记 isError，脚本须检查阶段状态而不只看 Promise 是否拒绝。取消不回滚已保存数据，不自动重试写入或发送。恢复指引不授予执行许可。

## 3. 目录缓存与绑定

完整 MCP 原生目录只在当前连接内缓存，不跨重启复用。首次连接、重连、目录通知或主动刷新触发发现；稳定调用不反复请求 `tools/list`。

连接关闭、发现失败或目录通知使缓存失效。凭据引用值变化时，旧连接拒绝复用，需重新确认配置和发现。

发送前核对连接与目录绑定。批准后的发送不刷新目录后继续沿用旧批准；绑定变化时停止本次发送。下次显式调用可以先重新发现。

持久目录只是最近保存的事实，不证明连接在线。服务静默改变接口且不通知时，ffa 不能立即发现；主动刷新或重连只能重新核对可见定义。

## 4. 工具权限

`.ffa/permissions.json` 是唯一权限来源，不在其他配置或手册保存副本。

```json
{
  "default": "ask",
  "tools": {
    "market/quote": "allow",
    "reports/export": "ask",
    "qmt/submit_order": "review",
    "qmt/transfer": "deny"
  }
}
```

工具 ID 为 provider ID、`/` 和经 `encodeURIComponent` 编码的操作名。只精确匹配，不使用通配符、参数表达式、优先级或配置继承。未配置工具使用 `default`，初始为 `ask`。

| 权限 | 程序行为 | 助手约定 |
| --- | --- | --- |
| `allow` | 直接调用 | 不要求 `review` 的方案复核 |
| `ask` | 请求本次用户批准 | 说明调用目的及参数 |
| `review` | 请求本次用户批准 | 事先组织独立方案复核 |
| `deny` | 拒绝调用 | 不绕过权限 |

独立复核针对方案，可以覆盖多个操作。报告不是单次调用许可，程序不核验复核是否完成。这样可避免把方案评估绑定到每次底层发送。专家失败不能当作复核通过。

交易接入建议 `review`，资料不足时建议 `ask`。管理工具的 permissions 分支统一接收原生操作名，由程序生成内部工具 ID。suggest 只添加显式建议中的缺失规则，保留已有设置；未建议操作继续继承 default，不提前固化逐操作规则。

set 用于明确修改规则，null 表示移除显式规则、恢复继承默认权限。两种模式均需用户确认，展示旧规则、目标规则和有效权限。读取区分 default、explicit 与 effective。接入或发现不能覆盖用户规则；管理工具不提供默认权限修改、通配符或权限分组。

用户可以用外部编辑器修改配置，模型不得直接编辑内部状态。提供方配置修改后须 `/reload`；发送前检测到文件快照变化时拒绝沿用旧批准。权限文件不依赖重载：调用和实际发送前均重新读取权限。文件缺失、损坏或非法时停止调用。

批准绑定完整有效权限快照。批准期间配置变化则停止发送；仅 JSON 排版或 key 顺序变化不影响批准。文件由存储层可靠写入，不依赖后台监视器或文件哈希校验。权限写入失败后，当前实例停止后续授权与写入；仍可读取文件核对，但读取成功不能消除写入结果的不确定性。核对后通过 `/reload` 重新加载。

## 5. 批准与发送

日常调用统一使用 `ffa_provider_call`，只接受必填的 `provider`、原生 `operation`、对象 `parameters`，无参数也提交 `{}`。记录读取使用独立的 `ffa_provider_record {kind,id}`，不会连接、刷新、批准或发送。

```text
校验参数、权限与绑定
  → 保存 pending 记录
  → 必要时请求用户批准
  → 实际发送入口复查
  → 可靠保存 dispatched 与发送尝试
  → 一次原生调用
  → 保存回执与结果状态
```

实际发送入口检查取消信号、存储健康、当前权限、完整参数及连接目录绑定，再消费单次发送许可。提示词或工具钩子不能代替这一检查。

所有确认串行排队。调用确认展示工具、连接、权限和完整参数。用户中断会取消尚未完成的批准，暂停期间的新请求等待下一次输入；恢复及队列轮到本次请求时，在展示前复查当前权限、参数和连接目录绑定，变化则停止。发送入口仍再次复查。没有确认通道时，`ask`、`review` 拒绝发送；`allow` 不需要确认通道。

TUI 确认窗口默认选中“确认”，Enter 执行当前选项；须先核对内容，Tab 切换选项，Esc 或 Ctrl+C 取消。↑↓ 滚动详情，PgUp/PgDn 翻页，Home/End 到首尾；窗口过小时不能确认。有配置摘要时，D 切换摘要与完整配置，并重置为选中“确认”，切换本身不会批准。RPC 使用客户端的原生确认界面。

专家使用相同入口与权限，批准由主会话用户提供。复核员按角色约定只查询，但角色要求不构成只读隔离。

每份记录最多发送一次。相同参数的新调用仍是新请求，不自动去重，不恢复旧批准，也不重试可能已发送的操作。

## 6. 结果与恢复

调用返回 `intentId`、可选 `receiptId`、权限、状态、数据及已保存结果的 `dataPath`。大结果提供 16,000 字符预览和 `truncated=true`。`ffa_provider_record` 返回 `record` 元数据；回执包含 `dataPath`，不包含正文，也不提供字符串分页。完整结果文件含 `data` 和可选 `raw` 诊断，使用原生文件工具或计算按需读取。正常退出按调用时权限保留 ask/review 散文件，归档 allow 记录。读取归档回执会按需恢复正文；旧路径缺失时重新读取回执，不重新执行原调用。归档不改变权限、结果分类或 unknownCalls。

可选 `outcomes` schema 区分业务受理与拒绝。完整成功返回且恰好匹配一个条件时，结果才明确；传输失败、条件冲突或不匹配保持 `unknown`。

没有 `outcomes` 时，协议完整成功返回记为 `accepted`。此状态不证明业务完成，更不证明成交。

| 情况 | 处理 |
| --- | --- |
| 用户拒绝或发送前失败 | `pending` 转为 `declined`，不记录发送尝试 |
| 可能已发送，结果不明 | 保存 `unknown` 与记录 ID，不自动重发 |
| 回执保存失败 | 停止后续发送，要求核对记录 |
| 重开账本发现 `pending` | 转为 `declined`，不继续发送 |
| 重开账本发现 `dispatched` | 转为 `unknown`，等待核对 |

`unknownCalls` 列出调用时结果不明的历史记录，不是必须清零的核对待办，也不表示当前订单状态。核对结论保存在所属项目或交易资料并引用调用 ID，不改变原调用事实。不提供人工结案入口或结案状态。未知记录不自动阻塞其他调用，后续操作仍按当前权限处理。未知不等于失败，也不构成重发依据。

账本独立于聊天分支。会话切换、fork、重载或重启不回退记录，不复制批准。取消不回滚外部副作用。

结果正文先可靠保存，再原子提交调用状态、回执引用与审计。正文或账本写入失败均停止后续发送；正文已保存而账本提交失败时保留未关联正文，不自动附加或重发。文件布局、持久化顺序与所有权见[文件存储](feat/file-storage.md)。工作区所有权保护本地记录，不保证同一账户跨工作区防重，也不保证外部业务恰好执行一次。Python、Bash 和其他扩展可以访问宿主；ffa 不声称控制这些路径。
