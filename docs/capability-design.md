# 完整能力接入与工具权限

本文说明能力目录、文件权限和发送规则。验证边界见[技术设计](technical-design.md#8-验证状态与验收边界)，实施方案见[调用精简方案](permission-implementation-plan.md)。

## 目录与权限分离

能力目录记录当前凭据可见的全部工具，不按任务、能力提供方名称或业务类别裁剪。目录保存接口事实、参数绑定和可选结果契约。禁止和不可用接口仍保留。

唯一权限文件为 `.ffa/permissions.json`。tools 以工具唯一 ID 为 key，值为 allow、ask、review 或 deny；default 初始为 ask。操作名使用 encodeURIComponent 编码。只精确匹配，不增加通配符、优先级、参数授权或配置继承。

接入流程依据能力提供方资料提出初始权限，经用户确认后只添加缺失规则，保留已有值。资料不明确的接口使用 ask。用户可以维护配置，模型不能自行降低权限。

权限不证明能力提供方行为。allow 可以包含业务变更。review 要求助手在方案层面组织独立复核，但程序不核验复核完成；ask 和 review 在执行上都要求本次用户批准。交易接入建议 review。

## 接入与发现

ffa_configure_provider 接受完整 provider 配置，或 provider ID 与初始 permissions。ID 模式使用已注册目录，不要求重新提交连接和 operations，不重连，也不覆盖已有权限。

首次 MCP 配置确认连接，operations 为空。连接保存后自动读取完整工具分页，返回目录和发现状态。发现失败保留注册和旧目录，报告 discoveryError；不能称为已验证。取消不报告成功。取得目录后，仅提交 ID 和初始权限建议，单独确认权限。发现不修改权限。

ffa_discover_provider 用于主动刷新或修复。重复名称、分页错误或取消不能保存为完整发现。范围仅限当前连接和凭据。变化工具替换原生定义，消失工具保留为不可用，未变化工具保留已有配置。

CLI 按完整帮助和文档建立已知目录，记录 coverage.basis 与 limitations。不宣称协议级自动全量发现。没有绑定的接口保留为不可用。连接、目录和初始权限可以一次确认。

## MCP 缓存与发送检查

完整原生目录只在当前私有连接内缓存，不跨重启复用。首次连接、重连、工具列表变化通知及主动刷新触发发现。稳定连接下，业务调用不重复请求 tools/list。

连接关闭、发现失败、目录通知或凭据变化使旧缓存失效。批准后的发送只核对缓存和绑定，不在刷新后沿用旧批准继续发送。下次显式调用可以先完成必要刷新。

持久目录是最近保存的发现结果，不等于连接仍在线。服务静默改变接口且不通知时，ffa 不能立即发现；主动刷新和重连可以重新核对定义。

## 文件与用户维护

PermissionFile 负责可靠读写；PermissionService 负责结构校验和精确规则。调用及实际发送前重新读取配置，不使用后台监视器或文件校验散列。缺失、损坏、非法值或非规范 ID 停止调用。

本次调用比较完整有效配置快照。批准期间配置变化则停止发送；仅改变 JSON 排版或 key 顺序不影响批准。

权限不复制到数据库或手册。模型通过配置工具提出建议，程序展示、确认并保存。Pi write/edit 不得直接修改内部状态；用户可以用外部编辑器维护权限。Bash、Python 和其他扩展仍有宿主权限，不声称强隔离。

## 调用与结果

日常调用和记录读取只使用 ffa_provider_call：

- provider、operation、parameters 发起新调用。
- record={kind,id,offset?,limit?} 分页读取已有 intent 或 receipt，不发送。
- 两种输入互斥。调用返回 intentId、可选 receiptId、permission、state、outcome、success 和数据。
- 大数据返回预览和 truncated=true；通过同一工具读取完整记录。

allow 直接发送；ask/review 请求本次批准；deny 拒绝。批准绑定本次精确参数、权限和连接目录版本，不能复用。执行服务不保存准备表、请求级许可或复核证据绑定。

专家使用同一入口和权限。批准窗口交给主会话用户。独立复核通过普通报告交付决定、依据和缺口，不登记程序许可，也不授权调用。

所有调用在实际发送前可靠保存尝试，一份调用记录最多发送一次。相同参数的新调用是新的显式请求，不自动去重、恢复或重试。

可选 outcomes 区分受理与拒绝。没有结果契约时，只记录协议完整返回，不证明业务完成或成交。传输失败、回执冲突或不匹配保持 unknown。未知结果返回记录 ID 和结构化失败状态，已取得回执仍保存。

未知事项不自动阻塞其他调用，也不授权重发。用户核对外部事实后通过 /ffa resolve 人工结案。回执保存失败停止后续发送；重启后核对账本，不把保存失败解释为未执行。

## 宿主与格式边界

ffa MCP 使用私有连接，不向 Pi 注册原生工具，不显示在 /mcp。官方 MCP 由 Pi 和服务管理；ffa 不拦截、不审批、不记录其调用。不要把这些调用当作 ffa 已验证或已记录的证据。

工作区格式为 ffa-pi/1，业务数据库版本为 1。开发期不递增版本。不支持历史格式，不转换、不补默认字段，不迁移、重建或删除用户资料和记录。

初始化仍检查完整目录、有效权限、资料与当前成功的行情及历史回执，不要求逐项能力分析。

## 验证

本地使用真实文件、SQLite、CLI、Pi SDK 和确认组件。检查四种权限、默认值、精确 ID、用户规则保留、配置损坏、批准期间变化、取消、单次发送、回执存储失败、未知恢复和人工结案。

不使用模拟 MCP、假模型、个人凭据或真实交易。真实 MCP 缓存、分页、通知、重连、动态定义和外部取消，仍需获准环境验收。
