# 专家协作

ffa 直接使用 Pi SDK 运行专家会话，不依赖其他子代理扩展。主会话与原生 codemode 负责并行、依赖和汇总；模型作专业判断，代码管理并发、取消、批准与记录。

模块边界见[技术设计](../technical-design.md)，provider 调用规则见[能力与权限](../capability-design.md)。本地验证不证明真实模型能够完成协作，验收范围见本文末节。

## 1. 职责与上下文

只有主会话可以委派专家，专家不取得委派工具。不建立第二个主 Agent、固定研究流水线、定时调度或任务重放。

包内 `resources/agents/` 提供 `general-purpose`、`researcher`、`reviewer` 和主会话 `coordinator`。工作区 `agents/<name>.md` 可补充同名职责或定义新专家，名称取自文件名；`coordinator` 不可委派。初始化只创建空的 `agents/`，不复制包内职责。

每次启动或接续使用当时的主模型和原生认证，运行中不切换。不保存专家独立模型配置或 OAuth 凭据副本。专家读取工作区资料入口和委派引用，不默认克隆主会话历史、系统提示或任意扩展。

专业方法通过技能入口使用。专家加载工作区 `.agents/skills/` 和包内技能，同名工作区技能优先；不复制技能正文，也不跨技能引用内部参考文件。工作区补充不能扩大用户授权或取消独立复核约定。

## 2. 工具与资料修改

Linux 下的 Pi 基础工具 read、Bash、write、edit、grep、find、ls 不按专家角色裁剪。ffa 工具显式绑定当前工作区，只提供能力目录、受控调用、记录读取和 Python 计算，不继承管理工具或全部扩展。

专家默认交回报告、证据和产物引用，由协调者汇总并维护正式资料。只有用户要求修改资料时，专家才修改相应内容。协调者可分配文件责任，不能扩大用户的修改要求。会话记录和计算产物正常保存，不属于正式资料维护；计算未指定归属时使用 `scratch/`。

write/edit 保留 Pi 原生解析、结果及同文件修改队列，在实际写入前检查共享规则：内部状态必须通过专用入口维护，工作区外修改需要确认。批准绑定真实目标和完整修改内容，路径变化则拒绝；目录创建在批准之后进行。

同文件队列不能防止分析结论互相覆盖，也不约束 Bash、Python。多专家写入须分配文件责任；不建立 worktree、工作区副本或沙箱。角色约定不构成宿主隔离。

## 3. 工具契约

统一工具为 `ffa_agent`。`agent` 是职责名，`runId` 是单次执行标识，也是控制与接续的唯一目标；`message` 是任务或补充信息。

| action | 输入与行为 |
| --- | --- |
| `start` | `agent`、`message`；新建执行 |
| `continue` | 已结束的 `runId`、`message`；从其检查点新建一轮，返回新的 `runId`，职责沿用原记录 |
| `steer` | `runId`、`message`；向已启动且仍运行的专家补充信息 |
| `list` | 返回职责 `agents` 和当前主分支的 `runs`，不领取完成通知 |
| `read`、`wait` | `runId`，可选 `offset/limit`；读取或等待报告 |
| `stop` | `runId`；取消排队或运行执行 |

只有 `start/continue` 接受 `mode=foreground/background`，默认前台阻塞；后台在返回执行 ID 后继续运行。参数按 action 校验，不静默忽略无关字段。运行中不能 `continue`；排队、启动或已停止的执行不能 `steer`。补充回执 `messageStatus=queued/handled` 来自 Pi SDK，入队不等于模型已阅读，也不立即终止当前工具。

结果提供执行身份、状态、报告、错误和用量。`checkpoint` 仅为会话文件及叶节点引用，不是目标参数。报告用 `totalLength/nextOffset` 分页，运行中预览不代表完整交付。`read/wait` 领取完成结果后不再自动通知；取消等待不会取消显式后台执行。`/ffa agents` 的观察不领取模型结果，停止操作使用同一服务。

## 4. 执行与并发

| 状态 | 含义 |
| --- | --- |
| `queued` | 等待名额 |
| `running` | 已取得名额，包括启动、回答、工具调用和等待批准 |
| `completed` | 本次交付完成 |
| `failed` | 启动或执行失败，或没有有效最终回答 |
| `cancelled` | 排队或运行期间取消 |
| `interrupted` | 恢复的记录没有完成节点，不自动重跑 |

前台、后台与接续共用 5 个名额。异步启动前取得名额，真正退出后释放一次。排队取消立即解除等待；活动任务取消仍等待 SDK 与工具退出。同一专家会话不能同时处理两次请求，不另设会话串行队列。

只提取当前检查点之后的新回答与用量，不以旧报告充当新交付；空的最终回答不算完成。失败、取消和中断保留已有报告、会话及计算产物。报告不强制使用统一的专业 JSON 格式。

`completed` 只表示交付完成，不表示复核通过或获得执行许可。独立复核每次使用 `start` 新上下文，不能接续旧复核。程序不解析自然语言报告来授予许可，专家失败也不算复核通过。

不自动重跑整个委派。协调者决定停止、补充证据或新建显式请求。保留 Pi 原生模型请求重试，不增加外部业务调用重发。

## 5. 后台交付与生命周期

| 事件 | 行为 |
| --- | --- |
| 默认前台委派 | 等待结果，取消绑定本次主会话操作 |
| 显式后台委派 | 绑定工作区和会话导航生命周期，不绑定已返回的工具调用 |
| 主会话正常结束本轮或收到普通输入 | 后台继续，前台随其操作取消 |
| 后台完成，主模型忙碌 | 在 `turn_end` 或最终收束边界交付 |
| 后台完成，主会话空闲 | 短时间合并结果，再自动启动协调者处理 |
| 用户中断主会话 | 取消前台；后台继续，自动推进暂停 |
| 下一次普通输入 | 恢复待交付结果和批准请求 |
| 会话切换、fork、树导航、重载、关闭 | 取消任务并等待退出，保留已有结果 |

交付前核对工作区实例、主会话和分支，合并通知，不重复交付已领取结果，也不注入另一分支或新实例。

后台完成后自动推进，使综合、复核和交付不必等待用户反复输入。但只能推进原请求，不产生无关业务、不重发未知调用，也不增加执行授权。

工作区关闭先取消任务和批准等待，等待专家、计算与关联调用退出，再释放连接和存储。关闭幂等，旧工具与控制入口失效。

## 6. 批准与发送

专家 provider 调用经过与主会话相同的权限、确认队列和独立账本；开放基础工具不修改权限。用户中断时取消正在显示或排队的批准，新请求等待下一次输入。恢复后、轮到展示时和实际发送前重新核对权限、参数与绑定，变化则停止，不复用旧批准。

停止专家、导航和关闭会解除批准等待。没有确认通道时，`ask/review` 拒绝发送；`allow` 按当前规则执行。取消不回滚副作用，可能已发送的操作保留结果不明记录，不自动重发。完整规则和确认操作见[能力与权限](../capability-design.md#5-批准与发送)。

Bash、Python 和其他扩展具有宿主权限，不能声称这些路径都受 ffa 的文件检查、批准或账本控制。

## 7. 分支、恢复与用量

执行记录为主会话原生 `ffa.agent-run` 条目，保存子会话文件及历史叶节点，正文保存在子会话。接续从当前主分支可见的检查点创建新的子会话文件，不修改另一分支的后续历史。不另建会话索引、任务数据库或专家存储版本。

恢复只重建可读状态，不恢复执行、批准或发送许可。未完成记录标为 `interrupted`，用户可查看已有交付并决定后续。报告和接续引用按当前分支读取；历史会话文件保留，不提供旧工具或参数适配。交易账本独立于聊天分支，不随导航或恢复回退。

用量保留输入、输出、缓存、成本及可用的原生细分字段，通过工具结果归入主会话。当前扩展 API 没有直接写入原生 usage entry 的公开入口，不承诺后台用量即时进入宿主统计。

`ffa.agent-usage` 收据关联持久化的父工具结果：codemode 去掉子工具详情不会丢失去重依据，未持久化结果不算归集完成。Pi 统计同一会话文件中的废弃分支，用量去重也读取全部条目；这不开放其他分支的报告或接续引用。fork 后遵循 Pi 原生历史复制范围。

## 8. UI 与验证边界

委派卡片显示目标、状态、活动、耗时、用量和报告摘要，展开显示本页正文。紧凑看板只显示排队和运行执行，没有任务时隐藏。

TUI 的 `/ffa agents` 提供列表、报告、会话查看和停止。查看器支持跟随、滚动和 End 恢复跟随，异步读取并缓存，渲染不做文件 I/O。退出、导航或关闭释放订阅。批准优先于观察界面，新的批准会关闭查看器，不接管编辑器。

RPC 和无 UI 模式可通过结构化 `ffa_agent` 工具读取与控制，不依赖终端组件；需要批准而无确认通道时仍拒绝发送。

本地测试覆盖真实 SDK 与会话文件、并发取消、关闭清理、检查点与旧报告隔离、通知合并与暂停、批准复查、文件保护、用量去重和查看器组件。结构化历史记录只验证状态契约，不证明模型完成了专业任务。

真实模型交付、动态依赖、运行中指令、复核、后台推进、实际用量及完整 TUI/RPC 交互仍需获准环境验收。统一测试要求和外部 provider 限制见[验证边界](../technical-design.md#6-验证边界)。
