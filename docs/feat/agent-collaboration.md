# 专家协作设计

状态：本地实现已完成；真实模型协作、自动推进和宿主 TUI/RPC 交互仍需获准环境验收。本文是当前功能说明，不再保留实施方案或完成清单。

ffa 直接使用 Pi SDK，不依赖 pi-subagents 运行。设计参考其 [0.21.0 实现](https://github.com/tintinweb/pi-subagents/tree/e819a82ae364a2b0432881b89b0c784b413a88c1)，但不引入其跨扩展运行时、脚本工作流、扩展继承或私有 SDK 字段访问。领域术语见 [CONTEXT.md](../../CONTEXT.md)，模块边界见[技术设计](../technical-design.md)，业务发送规则见[能力与权限设计](../capability-design.md)。

## 1. 协调方式

主会话和 Pi 原生 codemode 负责独立任务并行、依赖任务串行和显式汇总。模型作专业判断，代码管理执行状态、并发、取消、批准和记录。

第一版只有主会话可以委派专家。专家侧不注入委派工具，不建立第二个主 agent、脚本工作流运行时、定时调度或任务重放。研究、计算和复核不固化为所有任务必须经过的流水线。

每次委派启动时使用当时的主会话模型及其原生认证，运行中不切换。新委派或显式接续使用当前主模型。不保存专家独立模型配置、登录状态或 OAuth 凭据副本。

## 2. 专家定义与资源

包内职责放在 `resources/agents/`，提供 `general-purpose`、`researcher`、`reviewer` 和主会话 `coordinator`。工作区 `agents/<name>.md` 可以补充同名内置职责，也可以定义新专家。名称由文件名确定；`coordinator` 不作为可委派专家。

职责在文档中表达，专业方法通过技能入口使用。专家加载工作区技能与包内技能，同名工作区技能优先。不复制技能正文，不跨技能引用另一技能的内部参考文件。

专家读取工作区资料入口和委派引用，不默认克隆主会话历史、系统提示或任意扩展。工作区补充不能扩大用户授权，不能取消独立复核要求。

只使用 `agents/` 入口，不读取旧 `roles/`，不提供回退、转换或自动搬迁。用户已有文件保留。新初始化创建空 `agents/` 目录，不复制包内职责；现有工作区可按用户要求自行创建定义。

## 3. 工具、资料修改与报告

原生基础工具不按专家角色裁剪，Linux 下包括 read、Bash、write、edit、grep、find、ls。ffa 工具显式绑定当前工作区，提供能力目录、受控调用、记录读取和 Python 计算，不继承全部扩展或工作区管理工具。

专家默认交回报告、证据和产物引用，由协调者汇总并维护正式资料。只有用户指令要求修改资料时，专家才修改相应内容。协调者可以细化文件责任，不能自行扩大用户的修改要求。这是委派约定，不是宿主隔离。

Pi 会话记录、`ffa_python` 的源码、输入和计算结果正常保存，不视为专家维护正式资料。未指定计算归属时使用 `scratch/`。

write/edit 使用 Pi 原生解析、结果和同文件修改队列，在实际写入前执行共享工作区规则：内部状态通过专用入口维护，工作区外修改需要确认。批准绑定实际目标和完整修改内容，路径变化则拒绝写入。目录创建在批准后进行。

同文件队列不能防止分析结论互相覆盖，也不能约束 Bash、Python。明确委派写入时，协调者应分配文件责任，避免多个专家同时维护同一正文。不建立 Git worktree、工作区副本或沙箱。

报告只统一运行状态、正文或引用、错误和用量，不给各类专家规定固定 JSON 报告格式。`completed` 仅表示完成本次交付，不表示复核通过或获得执行许可。程序不解析自然语言报告来授予许可。

## 4. 会话与执行

`runId` 表示单次执行，也是全部工具控制与接续操作的唯一目标标识。`agent` 表示职责定义名，不是运行实例标识。服务内部保存会话关联与历史检查点；接续从指定执行的检查点新建一轮，返回新的 `runId`。同一会话不能同时处理两次请求，不按会话名另设串行任务队列。

| 执行状态 | 含义 |
| --- | --- |
| `queued` | 等待名额 |
| `running` | 已取得名额，包括启动、回答、工具调用和等待批准 |
| `completed` | 本次交付完成 |
| `failed` | 启动失败、没有有效最终回答或执行失败 |
| `cancelled` | 运行或排队期间被取消 |
| `interrupted` | 恢复的记录没有完成节点，不自动重跑 |

前台、后台与接续共用 5 个名额。异步启动前取得名额，真正退出后释放一次。排队取消立即解除等待；活动任务取消仍等待 SDK 与工具退出，不提前释放名额。

只提取本次执行检查点之后产生的回答和用量。没有新回答时不能返回旧报告；空的最终回答不算完整交付。失败、取消和中断保留已有报告、会话和计算产物。

不自动重跑整个委派。后续依赖由协调者决定停止、补充证据或发起新的显式请求。复核失败不算通过。本实现保留 Pi 原生模型请求重试，不增加外部调用重发。

## 5. 工具与控制

统一入口为单数 `ffa_agent`，集合目录和管理命令保持 `agents/`、`/ffa agents`。参数按 `action` 校验必要字段和禁止字段，不静默忽略与操作无关的参数：

- `start`：用 `agent`、`message` 新建执行。
- `continue`：用已结束的 `runId`、`message`，从该执行的历史检查点新建一轮。职责从该记录取得，不重复传入。
- `steer`：用 `runId`、`message` 向已启动的运行专家补充信息，不重启执行。
- `list`：返回 `agents` 职责定义与 `runs` 当前分支执行，报告只给预览，不领取完成通知。
- `read/wait`：用 `runId` 读取或等待报告，可选 `offset/limit` 分页。取消等待不取消显式后台专家。
- `stop`：用 `runId` 取消排队或运行执行。

`start/continue` 可选 `mode=foreground/background`，默认前台阻塞。后台返回执行标识后继续运行。其他操作不接受 `mode`。结果统一使用 `runId/agent/message/mode/state`、报告、错误和用量；可用的 `checkpoint` 只提供会话文件与叶节点引用，不作为工具目标参数。

运行中不能使用 `continue`，错误给出当前执行 ID 与等待或补充入口。排队、启动或已停止的执行不接受 `steer`。补充回执 `messageStatus` 按 Pi SDK 返回 `queued/handled`；入队不等于模型已阅读，也不立即停止当前工具。独立复核每次使用 `start` 新上下文，不接续旧复核。

执行和用量保存为 Pi 原生 `ffa.agent-run`、`ffa.agent-usage` 条目，不另存一份会话索引。历史聊天、子会话文件和交易记录保留，不改写、不提供旧工具或旧参数适配；旧聊天的原始报告仍可通过 Pi 查看。工作区与业务数据库版本保持 1。

`read/wait` 领取完成结果后不再自动通知。大报告通过 `nextOffset` 分页；运行中的预览不代表完整交付。`/ffa agents` 的会话观察不领取模型结果，停止操作则使用同一服务。

## 6. 前后台生命周期

| 事件 | 行为 |
| --- | --- |
| 默认委派 | 阻塞等待，取消信号绑定本次主会话操作 |
| 显式后台委派 | 绑定工作区与会话导航生命周期，不绑定已返回的工具调用 |
| 主会话正常结束本轮或收到普通输入 | 后台继续，前台工作仍随其操作取消 |
| 后台完成且主模型忙碌 | 在 `turn_end` 或最终收束边界交付 |
| 后台完成且主会话空闲 | 短时间合并结果，再自动启动协调者处理 |
| 用户中断主会话 | 取消前台，后台继续，但暂停自动推进 |
| 下一次普通用户输入 | 恢复待交付结果和批准请求 |
| 会话切换、fork、树导航、重载、关闭 | 取消运行任务，等待退出，保留已有结果 |

结果交付前检查工作区实例、主会话和所属分支。通知合并发送，已领取结果不重复通知。后台输出不会转用新实例或注入另一分支。

自动推进只处理原用户请求，可以安排必要的综合、复核和后续委派，不产生无关的新业务任务，不重发未知调用，也不增加执行授权。原因见[后台交付决策](../adr/0001-background-results-advance-coordination.md)。

工作区关闭先取消任务和批准等待，等待专家、计算及关联调用退出，再释放连接与存储。关闭幂等，旧工具和控制入口拒绝访问新实例。

## 7. 批准与发送

开放基础工具不修改 `.ffa/permissions.json`。专家的 provider 调用使用原有 `allow/ask/review/deny`、主会话确认队列和独立账本。角色中的查询与业务变更约定不构成强隔离。

用户中断时取消正在显示和排队的批准。暂停期间的新请求等待下一次用户输入，不弹新窗口。恢复后，在展示批准前重新核对权限、完整参数和连接目录绑定；变化则停止本次调用。批准后仍在实际发送入口复查。

不复用旧批准。停止专家、导航或关闭会解除等待；没有确认通道时，`ask/review` 拒绝发送。`allow` 按现有规则执行。取消不回滚已发生的副作用，可能已发送的调用保留结果不明记录，不自动重发。

Bash、Python 和扩展具有宿主权限，不是沙箱。ffa 不宣称这些路径都受自己的文件检查、批准或账本控制。

## 8. 分支、恢复与用量

专家引用记录子会话文件及其历史叶节点。接续通过 Pi 原生分支能力，从当前主分支可见的检查点创建新的子会话文件；后续追问不修改另一分支的子历史。

执行起止与已保存检查点保存在主会话原生自定义条目，正文保存在子会话。恢复只重建可读状态，不恢复运行、批准或发送许可。未完成记录标为 `interrupted`，可查看已有交付并显式决定后续。

报告和接续引用按当前分支读取。交易账本独立于聊天分支，不因导航、fork 或恢复回退。工作区格式与业务数据库版本保持 1，不增加通用任务数据库或历史适配。

用量保留输入、输出、缓存、成本及可用的原生细分字段。当前扩展 API 没有直接写入原生 usage entry 的公开入口，主会话通过工具结果归集，不承诺后台用量即时进入宿主统计。

用量收据关联持久化的父工具结果，因此 codemode 去掉子工具详情不会丢失去重依据；未持久化的结果不作为归集完成。Pi 的会话统计包含同一文件的废弃分支，用量去重也读取该文件的全部条目，但不据此开放另一分支的报告或接续引用。fork 后的统计遵循 Pi 原生历史复制范围。

## 9. 基础 UI

委派卡片显示目标、状态、活动、耗时、用量和报告摘要，展开时显示本页正文。紧凑看板只显示排队和运行执行，没有任务时隐藏。

`/ffa agents` 提供基础列表、报告阅读、会话查看和停止。查看器支持实时跟随、滚动和 End 恢复跟随；内容异步读取并缓存，渲染不读取文件或数据库。退出、导航和关闭释放订阅。

批准优先于列表和查看器；新的批准请求关闭观察界面，不接管编辑器。使用 Pi 原生主题、宽度和滚动能力，不提供 FleetView、`@agent`、双栏检查器、指令编辑器或前后台快捷切换。运行中补充指令通过工具完成。

RPC 与无 UI 模式保留结构化工具能力，不依赖终端组件开展业务。需要批准但没有确认通道时，仍拒绝发送。

## 10. 验证边界

本地测试使用真实 Pi SDK、会话文件、文件修改、SQLite、进程和 UI 组件，覆盖并发与取消、关闭清理、检查点接续、旧报告隔离、通知合并与暂停、批准复查、内部状态保护、用量收据和查看器缓存滚动。

不使用 mock、stub、假模型、模拟 provider、个人凭据或真实交易。恢复的结构化会话和用量记录只验证解析与状态契约，不证明模型完成了专业任务。

以下仍需获准环境验收：真实模型成功交付、动态依赖判断、运行中指令、独立复核、后台自动推进、实际模型用量，以及 TUI/RPC 的焦点、批准、主题切换、长时间运行和导航。外部 provider 的连接、目录通知与取消继续受既有验证限制约束。本地通过不代表实盘安全。
