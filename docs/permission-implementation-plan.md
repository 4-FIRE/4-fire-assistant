# CLI/MCP 调用精简技术方案

## 已确认的边界

本方案只调整 ffa 管理的 CLI/MCP 能力提供方。独立复核属于方案层面的工作约定，不是单次调用的程序门槛。ffa 不拦截官方 MCP，也不保证控制 Bash、Python 或其他扩展。

保留 allow、ask、review、deny。allow 免批准；ask 和 review 均要求本次用户批准；deny 拒绝。助手在 review 调用前组织方案复核，程序不证明复核已经完成。

## 工具契约

日常调用和记录读取统一使用 ffa_provider_call。调用输入为 provider、operation、parameters；读取输入为 record，其中包含 kind、id 和可选 offset、limit。两种输入互斥。调用返回 intentId、可选 receiptId、permission、state、success 和数据；大结果返回预览，完整记录通过同一工具分页读取。

删除 ffa_prepare_call、ffa_execute_call、ffa_record、ffa_submit_review。保留接入配置、主动发现、目录查看、状态、计算、专家和初始化工具。独立复核员通过报告交付决定、依据和缺口；委派不再接收 intentId。

ffa_configure_provider 接受完整 provider 配置，或 provider ID 与初始权限建议。ID 模式不重交连接和目录，不关闭连接，不覆盖已有用户规则。CLI 可以一次确认连接、目录和初始权限。

MCP 连接确认保存后自动完整发现。随后仅提交 ID 和权限建议，单独确认权限。自动发现失败保留注册配置和旧目录，返回明确的目录失败状态。取消传播，不报告发现成功。手册和其他不依赖连接的工作可以继续。

## 单次调用

执行服务只保留一个 call 方法，不维护准备表、复核许可、请求代次或可重用批准。会话 ID 仅用于记录来源，不是授权依据。

1. 克隆输入，核对当前目录与参数。
2. 读取有效权限配置，并保存本次配置快照及连接、目录绑定。
3. ask/review 展示完整调用参数并请求批准；allow 跳过批准。
4. 实际发送入口再次检查取消、存储健康、配置、绑定和目录版本。
5. 可靠提交发送尝试，消费本次传输许可。
6. 只调用一次原生工具，可靠保存回执和结果。

拒绝或发送前失败不记录发送尝试。可能已发送但结果不确定时返回 unknown 和 intentId，不抛失去记录标识的普通错误，不自动重发。回执保存失败禁用后续发送，要求核对记录。未知结果不阻塞其他调用；人工结案不授权重发。

账本记录单次批准等待、发送、回执和人工结案。每次显式调用创建独立记录，不按相同参数去重，也不提供重新执行旧记录的入口。重新打开账本把未完成发送转为 unknown，不恢复批准。工作区格式和业务数据库版本保持 1，不迁移或删除用户记录。

## MCP 目录缓存

私有 MCP 按当前连接缓存完整原生目录。首次连接、重连、目录变化通知或主动发现触发完整发现；稳定连接下业务调用不发 tools/list。

连接关闭、凭据变化、发现失败和目录变化使缓存失效。发现检查全部分页及发现期间的版本变化。目录保存保留不可用和消失的工具，不修改权限。

批准后的发送只检查当前缓存与绑定，不自动刷新后继续发送。目录变化使本次批准失效，下次显式调用先刷新。服务静默修改定义且不通知的行为不能立即发现，需主动刷新或重新连接。

## 生命周期与责任

工作区实例管理取消信号。输入、会话导航和退出取消正在进行的工作；旧工具引用关闭后拒绝调用。取消不回滚外部副作用。没有另一套请求级许可。

services 拥有业务规则和记录顺序；integrations 拥有连接、缓存、协议与发送门禁；tools 拥有输入输出和确认适配。权限文件仍是唯一来源，模型只通过接入工具提交建议。

## 实施与验证

先改执行服务、账本和目录缓存，再改工具集合、专家和生命周期。同步更新接入参考、技能、角色、README 和当前设计。

本地使用真实文件、SQLite、CLI、Pi SDK 和确认组件。检查四种权限、参数克隆、确认期间变化、取消、发送一次、回执分类、未知恢复、分页读取和初始规则保留。不使用模拟 MCP、假模型、个人凭据或真实交易。

执行 npm run check、npm test 和 git diff --check。真实 MCP 缓存、通知、重连和外部取消仍需获准环境验收；本地检查不能证明这些行为。
