# 工具权限实施方案与计划

## 目标

能力目录只记录接口事实。工具权限单独保存，接入流程生成初始规则并请求用户确认。用户可以直接维护配置文件，不要求逐项填写分析资料。

参考 [Claude Code 权限](https://code.claude.com/docs/en/permissions.md) 的程序执行与文件配置方式。ffa 只保留精确工具 ID 和四种权限，不引入多层配置、通配符、优先级或参数匹配。

## 配置

唯一权限文件为工作区 `.ffa/permissions.json`：

```json
{
  "default": "ask",
  "tools": {
    "market/quote": "allow",
    "reports/export": "ask",
    "qmt/submit_order": "review",
    "qmt/transfer": "deny"
  }
}
```

工具 ID 为能力提供方 ID 加 `/` 加操作名。操作名使用 encodeURIComponent 编码，避免分隔符歧义。简单名称保持原样。

- allow：完全访问，不请求批准。
- ask：每次调用请求用户批准。
- review：独立复核通过后，再请求用户批准。
- deny：禁止调用。

没有精确规则时使用 default，首次创建为 ask。接口资料不明确时同样使用 ask。权限不是能力提供方行为证明。

模型通过接入工具提交本能力提供方的初始权限建议。程序校验、展示规则、请求确认并保存文件。仅添加缺失的精确规则，不覆盖用户已有规则。已有规则与 default 由用户直接编辑。运行提示词、技能、共享参考和工具描述不暴露存储文件，也不要求模型手工编辑。模型的文件工具不能直接修改权限文件。发现本身不改变权限。

非法或缺失的权限文件拒绝调用。配置只保存一份，不复制到数据库或能力提供方手册。程序每次调用和实际发送前读取配置；有效规则变化撤销当前准备与复核。格式损坏也撤销许可。

## 执行

统一使用 ffa_provider_call。allow 和 ask 可直接调用并保存回执；review 使用 ffa_prepare_call、新的 reviewer 和 ffa_execute_call。显式准备也适用于 allow 和 ask。

所有调用共用发送前记录、单次发送门禁和真实回执。review 必须使用当前请求的独立证据。ask 和 review 没有用户确认通道时拒绝发送。deny 在实际发送前仍需检查。

不再根据接口业务影响自动判断权限。用户可把任何接口设为 allow，包括交易。初始化只核对目录、必要资料和两份当前真实数据回执，不要求完整能力分析。

没有业务回执 schema 时，只记录协议调用是否完整返回，不把成功返回解释为成交。配置了 accepted/rejected schema 时继续严格判断业务结果。传输中断或业务结果不明不自动重发。

结果不明记录保留在账本，阻止新的 review 调用；allow 和 ask 可继续用于核对外部事实。删除业务影响分类后，程序不能区分这些调用是否改变状态。此限制明确写入使用文档，不声称仍能阻止全部业务变更。

专家使用同一权限入口。allow 可直接调用，ask 的确认交给主会话用户，review 不能作为复核证据入口递归执行。专家不获得配置修改工具。

## 删除范围与兼容边界

删除旧接口分类、分析状态、分析内容、禁止原因和独立执行要求。删除旧工具入口，不保留适配或转换。同步更新模型、工具 schema、目录、UI、提示词、文档和测试。

工作区与数据库使用新的格式版本。旧格式直接拒绝，不迁移、不重建，不删除用户资料和历史交易记录。临时测试工作区可正常清理。

权限规则仅覆盖 ffa 管理的能力提供方。其他 Pi 工具、Bash、Python 和扩展不是沙箱，不建立全宿主权限系统。

## 实施步骤

1. 写入本方案，确认现有模块边界和调用链。
2. 实现文件配置、精确 ID、严格校验、接入初始化和规则变化撤销。
3. 删除旧字段，简化目录校验和初始化条件。
4. 统一调用、准备与执行工具，接入主会话及专家确认。
5. 更新 UI、接入技能、角色与当前设计和使用文档。
6. 用真实文件、SQLite、CLI 和 Pi SDK 测试四种权限、配置修改、非法配置、取消、防重复发送及旧格式拒绝。
7. 执行 npm run check、npm test、git diff --check，检查旧字段和旧入口残留。

## 验收限制

本地测试不使用假模型、模拟 MCP、个人凭据或真实交易。外部 MCP 动态目录、真实模型接入、主会话与专家交互确认仍需获准环境验收。
