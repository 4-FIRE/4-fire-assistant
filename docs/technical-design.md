# 技术设计

本文说明当前模块、工作区生命周期、资源加载和验证边界。开发约束见[架构原则](architecture-guidelines.md)，安装与命令见 [README](../README.md)。专题规则分别由[能力与权限](capability-design.md)、[专家协作](feat/agent-collaboration.md)和[文件存储](feat/file-storage.md)维护。

## 1. 系统边界

ffa 是按工作区启用的 Pi 扩展。模型负责分析、规划与协调；代码负责状态、工具契约、批准和可靠记录。学习、项目推进、研究与投资可以组合，不作为工作区类型，也不对应固定 Agent 流程。

Pi 提供主会话、模型配置、认证、基础工具、codemode 和原生恢复。ffa 不另建主 Agent、插件平台、登录系统、任务调度器或持久重放系统。角色定义职责，技能说明方法；资料按需读取，不把完整手册放入提示词。

## 2. 模块责任与依赖

```text
Pi 命令、工具与事件
         ↓
 tools / extension / ui
         ↓
      services
      ↙      ↘
 storage   窄能力约定
               ↑
          integrations
```

`src/ffa.ts` 装配依赖并注册入口。服务定义窄能力，宿主接入实现这些能力；服务不取得完整 Pi 上下文。

| 目录 | 责任 |
| --- | --- |
| `src/tools/` | 工具输入、输出、schema、执行适配和显式工具列表 |
| `src/services/` | 业务规则、状态转换和副作用顺序；按 providers、agents、execution、workspace 聚合 |
| `src/model/` | 数据类；无业务行为或 Pi 类型 |
| `src/integrations/` | providers 接入 CLI/MCP，pi 接入专家会话；共享进程执行 |
| `src/storage/` | 原子 JSON、领域文件、工作区状态 |
| `src/extension/` | 命令、事件、启用状态和资源生命周期 |
| `src/ui/` | 确认队列、窗口与展示 |
| `src/common/` | JSON、校验、文件、包路径和版本辅助逻辑 |
| `resources/` | 角色、技能、提示词、模板和操作参考 |

保持单一扩展包，不按领域建立独立插件或转发入口。工具契约与执行适配共同维护，命令和工具调用同一服务，不直接访问存储或协议实现。进入 JSON、存储和工具结果前，数据类显式转为普通数据。确认界面接收副本，只返回用户选择，不修改待保存方案或决定发送许可。

| 责任主体 | 拥有的规则 |
| --- | --- |
| `ProviderRegistry`、`provider-edits.ts` | 接入、增量编辑、对象快照、确认与保存顺序、原生绑定和发送前检查 |
| `PermissionService` | 权限规则、差异计划和权限文件写入 |
| `ExecutionService`、`Ledger` | 批准、单次发送、结果判定和调用状态转换 |
| `InitializationService` | 初始化完成条件与最终状态提交 |
| `PythonEnvironmentService` | 共享 venv 自动准备、依赖检查、错误状态及取消等待 |
| `AgentService` | 专家队列、并发、控制、恢复与交付状态 |
| `Store`、领域存储 | 严格加载与可靠保存；不决定业务状态 |

`ProviderCallStrategy` 只抽象 CLI/MCP 的连接检查、环境事实、预览、原生绑定和发送。`ProviderConnections` 显式装配 `CliProvider` 与 `PrivateMcp`，通过 `ProviderAccess` 提供给服务。预览不连接、不读取凭据值。实际发送调用服务传入的检查能力；批准、权限保存与账本规则不下放给协议策略。

专家工具与批准回调由 `extension/agent-run.ts` 装配。`integrations/pi/agent-context.ts` 提取原生会话记录和分支归属，入口显式要求服务恢复状态；`integrations/pi/agent-tools.ts` 适配原生文件工具，在实际写入前调用授权能力。

依赖由 `.dependency-cruiser.cjs` 检查：服务不依赖 Pi SDK、工具或 UI；共享进程执行可以直接使用，其他宿主能力通过窄约定传入。接入层可引用服务类型，不运行服务实现或依赖入口层。服务领域依赖为 `agents → execution → providers`；workspace 初始化可使用 providers，providers 不反向依赖其他业务服务领域。

## 3. 工作区生命周期

### 3.1 加载范围与格式

仅使用启动目录作为工作区根目录，不向父目录搜索。包清单只静态加载扩展入口，角色、技能和业务工具按状态提供。

发布版本来自 `package.json`，当前为 `0.3.2`。`common/version.ts` 将其用于 MCP 客户端标识，并推导唯一的工作区兼容标识：

| 发布版本 | 工作区 format |
| --- | --- |
| `0.MINOR.PATCH` | `ffa/0.MINOR`，当前为 `ffa/0.3` |
| `MAJOR.MINOR.PATCH`，MAJOR ≥ 1 | `ffa/MAJOR` |

同一兼容线保持同一持久化契约，不因补丁更新改写工作区。需要转换持久化数据的变更必须切换兼容线，不能隐藏在补丁版或稳定主版本的次版本更新中。

不发布独立的 Python 计算包。Python 计算直接使用 requirements.lock 中的第三方库原生 API；Pi、Node、Python 解释器和依赖包的版本独立于插件管理。

运行时只加载当前 JSON 工作区，不保存独立的 storage 标识、数据库版本或升级计数。正常加载严格校验，不迁移、不补字段、不读取升级进度。不支持或损坏的工作区拒绝启用，已有文件不改写。0.3.0 的 `ffa/0.3` 工作区可直接使用，不转换记录字段或改写格式标识。归档目录首次使用时创建，启动不补建；更早的不兼容目录和历史记录须保留，不在原目录重新初始化。

### 3.2 启用与初始化

| 状态 | 启动行为 |
| --- | --- |
| 无状态 | 仅提示 `/ffa init`；不创建目录、打开存储或连接，不注入角色与业务工具 |
| `pending` | 仅提示；再次执行 `/ffa init` 才接续 |
| `ready` | 自动打开工作区，准备共享 Python venv 并激活；环境异常时提醒，其他能力仍可使用，等待用户请求 |

用户确认目录后，初始化创建状态和资料目录，从包内模板补建缺失的根 `AGENTS.md`，不覆盖已有文件。外部服务与目标市场均可省略；注册、发现、连接验证和手册补齐不作为启用条件。接入引导只请求工具信息、文档或配置位置，不索取凭据值。

完成初始化时：

1. 检查根 `AGENTS.md` 非空；缺失时从同一模板补建。
2. 检查权限文件。无接入时可创建默认 `ask` 的空配置；已有接入而权限文件缺失或损坏时拒绝完成，不补默认值。
3. 展示已注册配置与权限，由用户确认。
4. 再次核对配置、权限和根资料，然后提交 `ready` 及可选 market；确认期间变化则停止。

这些检查只证明结构符合要求，不证明接口可用或资料正确。初始化中断保留资料，不自动继续或清理。完成后执行 Pi 原生 `/reload` 刷新工具与资源。

| 工具 | 可用阶段 |
| --- | --- |
| `ffa_provider_manage`、`ffa_providers`、`ffa_provider_call`、`ffa_provider_record` | 显式初始化期间及就绪工作区 |
| `ffa_finish_initialization` | 初始化期间 |
| `ffa_status`、`ffa_agent` | 就绪工作区 |

工具范围不是宿主隔离，也不替代调用权限。

### 3.3 独立升级脚本

插件没有升级命令、工具、版本链或备份服务。后续转换由 `scripts/` 中用户手动运行的版本脚本负责，不由插件生命周期调用。实际转换必须声明源与目标，要求工作区停止并取得排他所有权，备份后修改，验证后提交格式，并支持中断后显式接续。

当前 `upgrade-0.3.0.mjs` 仅为空基线，不读写工作区，无需运行。0.3.2 不提供实际转换脚本。命名、适用性和后续要求统一见[脚本说明](../scripts/README.md)；不将历史读取重新引入运行时。

### 3.4 取消与关闭

工具绑定一个工作区实例；关闭后旧引用失效，不能转用新实例。新输入和主会话操作结束取消前台工作，不取消显式后台专家。用户中断后暂停自动推进和新的批准，下一次普通输入恢复。会话切换、fork、树导航、重载和关闭取消全部专家。

关闭先取消工作和批准等待，等待专家与环境 setup 退出，再等待活动调用、关闭连接，恢复本扩展修改的进程环境变量，最后关闭存储。仅在正常退出时，于关闭存储前归档历史 allow 调用；ask/review 保留散文件，重载和会话替换不归档。规则、可靠发布和按需恢复见[文件存储](feat/file-storage.md#退出归档)。关闭幂等。取消阻止尚未发送的调用，不回滚外部副作用；专家交付与分支规则见[专家协作](feat/agent-collaboration.md)。

## 4. 资源与资料

| 资源 | 加载与维护方式 |
| --- | --- |
| `resources/prompts/workspace.md` | 仅启用期间加载的公共协作提示词；主会话与专家共用 |
| `resources/initialization.md` | 显式初始化期间加载，说明阶段边界并引导读取接入技能 |
| `resources/agents/`、工作区 `agents/` | 就绪后加载协调者职责；委派时加载对应专家职责 |
| `resources/skills/` | 就绪后通过 `resources_discover` 提供；专家同时加载工作区技能 |
| `resources/templates/workspace-agents.md` | 只用于补建缺失的根资料入口，模板更新不覆盖已创建文件 |

主会话通过 `before_agent_start` 增加独立提示词 section，保留 Pi 原生 `AGENTS.md` 加载。初始化不提前启用技能发现。资源使用时读取，缺失报错，不回退到代码内副本。公共提示词更新通过 `/reload` 或重启加载，不自动改写用户资料或内部状态。

职责、专业方法、运行时提示词和说明文档分开维护。技能通过入口协作，不跨技能引用内部参考文件：接入、调用、交易和项目维护分别由对应技能负责。项目整理依赖模型判断，不增加定时扫描、自动结项或追改资料的升级步骤。

工作区资料只保存一份正文，用引用连接证据；包内角色与技能不复制到工作区。目录用途见 [README](../README.md#工作区资料)，内部格式、配置修改和复制规则见[文件存储](feat/file-storage.md)。

模型通过专用工具修改内部状态。Pi `write/edit` 对内部状态的修改会被拦截，工作区外修改需要确认；这些规则不隔离 Bash、Python、外部编辑器或其他扩展。

## 5. 专家、计算与 codemode

专家通过 Pi SDK 会话运行，启动时使用主模型及其原生认证，不复制独立登录状态。主会话组织依赖与汇总，专家不能继续委派。默认交回报告，仅用户要求时维护正式资料；provider 调用继续经过同一批准与账本入口。完整执行契约见[专家协作](feat/agent-collaboration.md)。

ffa 不提供 Python 计算执行工具。已有脚本、模块和临时代码通过原生 Bash 执行，使用当前环境的 python 或 python3 与项目工作目录；模块导入、命令行参数和数据路径遵循 Python 与项目原有约定。ffa 不复制源码、不创建计算运行目录、输入文件或执行记录，不提供独立的研究进程超时管理。脚本和结果按任务保存，已有历史产物不自动重算或清理。

`PythonEnvironmentService` 负责共享 venv 的准备、状态与取消等待。就绪工作区 `session_start` 自动调用，`/ffa python setup` 提供无路径参数的手工重试。`scripts/setup-python.py` 按用户级 Linux/macOS 路径定位环境，不存在时创建，按锁文件补齐或对齐依赖；已匹配时跳过安装。完成 pip check、库导入和基础计算检查后才标记就绪。只安装 wheel，不修改系统 Python、不编译 C 库、不安装系统软件，不自动删除或重建异常环境。

`WorkspaceInstance` 拥有激活与恢复的生命周期，`integrations/python-activation.ts` 调整当前进程的 PATH、VIRTUAL_ENV 与 Python 路径变量，供主会话和专家的原生 Bash 继承。关闭时恢复仍由本扩展持有的变量值；不改外部终端或 shell 文件。未初始化与 pending 工作区启动不准备环境，完成初始化后通过原生 reload 启用。

共享锁串行处理多个进程的 setup，获得锁后重新检查；同一服务的重叠请求合并。安装失败或取消保留环境，显示提醒并记录 error 状态；不激活失败环境，不循环重试，其他 ffa 能力仍可使用。锁不管理其他脚本，也不能保证更新不影响其他工作区的活动进程；更换插件版本或手工重试前应停止相关脚本。不同插件版本的依赖要求可能冲突。

计算源码直接导入 numpy、pandas、TA-Lib、backtesting 等原生库，不提供统一库接口或内置市场适配，避免增加模型需要理解的接口与隐含规则。市场约束、费用和实验切分由具体研究明确并验证，不在通用执行入口中固化。

主会话提示包含环境状态；主会话与专家共用的计算约定说明自动激活和异常处理，通过 python 或 python3 原生执行，失败时不自行换系统环境。项目构建测试仍遵循项目明确环境。这不是 Bash 黑名单或系统隔离，原生 Bash 不因准备失败而禁用。路径和安装限制见 [Python 说明](../python/README.md)，库用法见[计算参考](../resources/references/compute.md)。准备脚本支持 Linux/macOS，插件整体未完成 macOS 实机验收。

工具声明 `outputSchema`，由 Pi 纳入 `ffa` namespace。ffa 不强制开启 codemode，也不另建脚本运行时。脚本须检查结构化失败状态，按依赖顺序等待，并为批准和专家任务留足时间；脚本超时不回滚已完成的外部操作。

## 6. 验证边界

本地测试使用真实 Pi SDK、文件、CLI/Python 进程和 UI 组件，检查启用门槛、工具契约、版本冲突、权限与批准复查、取消、单次发送、故障停止、恢复、专家队列与分支、多进程打开同一存储。权限写入故障依赖真实目录权限，以 root 运行不能证明该操作系统限制。

- `tests/smoke/`：实际打包产物、工作区启用及独立 Python setup 脚本。
- `tests/e2e/`：独立 Pi SDK/RPC 进程中的命令、工具、确认、本地 CLI、持久化、重启和原生 Bash 执行已有 Python 脚本。驱动显式提交工具输入，不生成模型响应。
- 两组均包含在 `npm test` 中，也可执行 `npm run test:smoke`、`npm run test:e2e`。Python 原生库集成测试与环境说明见 [python/README.md](../python/README.md)；Node 测试不下载第三方 Python 依赖，也不替代其安装与运行验证。

不使用 mock、stub、假模型、模拟 provider、个人凭据或真实交易，不用文档或提示词文本断言证明行为。

以下仍需获准环境验收，不能由本地测试推定：

- 真实模型的初始化、接入、资料维护、专家交付、动态依赖、接续、运行中指令、独立复核、后台推进、解释器选择与产物保存约定遵循和实际用量。
- 外部 MCP 的分页、缓存、通知、重连、动态定义与取消。
- 完整 TUI/RPC 客户端交互，包括焦点、主题、批准、查看器、长时间运行和会话导航。
- 进程中断后的外部业务结果核对，以及断电持久性和文件系统差异；不承诺同步目录的多机并发写入。

修改后执行 `npm run check`、`npm test` 和 `git diff --check`；包内容用 `npm pack --dry-run` 检查。保留验证限制，不降低批准或存储要求来换取通过。
