# 技术设计

本文说明当前模块职责、工作区状态和运行边界。设计原则见[架构原则](architecture-guidelines.md)，调用规则见[能力与权限设计](capability-design.md)。安装与命令见 [README](../README.md)。

## 1. 系统目标

ffa 是按工作区启用的 Pi 协作扩展，不是独立应用。模型负责分析、规划与任务协调；代码负责状态、工具契约、用户批准和可靠记录。

用途包括学习与知识积累、任务与项目推进、研究与决策支持；投资是专业应用领域。用途可以组合，不作为工作区类型或模式字段，也不对应固定 Agent 流程。角色文档定义职责，技能说明专业方法与操作约定。资料按任务读取，不把完整手册塞入提示词。

Pi 提供主会话、模型配置、认证、文件工具、Bash、codemode 和原生恢复。ffa 不另建主 Agent、插件平台、登录系统、任务调度器或持久重放系统。

## 2. 模块责任与依赖

```text
Pi 主会话、命令、工具与事件
              ↓
    tools / extension / ui
              ↓
           services
          ↙        ↘
      storage    窄能力约定
                    ↑
               integrations
```

`src/ffa.ts` 装配依赖并注册入口。图中的窄能力约定由服务定义，宿主接入负责实现；服务不取得完整 Pi 上下文。

| 目录 | 责任 |
| --- | --- |
| `src/tools/` | 输入、输出、schema、执行适配和显式工具列表 |
| `src/services/` | 业务规则、状态转换和副作用顺序 |
| `src/model/` | 数据类；不包含业务行为或 Pi 类型 |
| `src/integrations/` | CLI、私有 MCP、进程与 Pi 专家会话 |
| `src/storage/` | SQLite 事务、可靠写入、工作区状态和所有权 |
| `src/extension/` | 命令、事件、启用状态和资源生命周期 |
| `src/ui/` | 确认队列、窗口与能力摘要 |
| `src/common/` | JSON、校验、文件和包路径辅助逻辑 |
| `resources/` | 角色、技能、提示词、模板和操作参考 |

关键规则的归属：

- `ProviderRegistry` 管理接入、增量目录、按对象版本、确认与保存顺序、绑定和发送前检查；`provider-edits.ts` 负责编辑计划与版本快照；`PermissionService` 拥有权限规则、差异计划和文件写入。
- `ExecutionService` 组织批准与发送；`Ledger` 管理调用记录的状态转换。
- `InitializationService` 检查完成条件；`WorkspaceUpdateService` 管理逐版升级、确认、备份顺序和完成规则。
- `ResearchService` 保存计算产物；`AgentService` 管理专家执行、统一队列、互斥、控制和结果状态。
- 存储层执行事务，不决定业务状态。UI 返回用户选择，不决定是否允许发送。

provider 工具分为 `ffa_provider_manage`、`ffa_providers`、`ffa_provider_call` 和 `ffa_provider_record`。管理输入按 action/target 严格分支，不复用内部 Provider 状态。MCP 目录由程序维护；CLI 接口按 add/replace 增量编辑。记录读取与发送入口分开，专家不取得管理工具。

编辑版本为实例内不透明快照标识。按连接、接口、coverage、outcomes 和权限分别检查，包含相关契约依赖；不增加持久字段、格式迁移或文件哈希。读取不连接，重载后旧版本失效。批量目录一次保存，权限文件与目录数据库的保存阶段分别报告，不提供跨文件事务或回滚。

工具和命令调用同一服务，不直接访问数据库或传输实现。模型实例进入 JSON、存储和工具结果前，显式转为普通数据。

`.dependency-cruiser.cjs` 检查依赖方向及循环。服务不得依赖 Pi SDK、工具或 UI；进程执行是服务可直接使用的无 Pi 接入。其他宿主能力通过窄约定传入。接入层可以引用服务类型，但不运行服务实现。

## 3. 工作区生命周期

### 3.1 加载范围与格式

仅使用启动目录作为工作区根目录，不向父目录搜索状态。包清单只静态加载扩展入口，角色、技能和业务工具按状态提供。

工作区格式为 `ffa-pi/1`，业务数据库版本为 1。正式发布前保持版本 1。不提供旧格式适配、默认字段补全或迁移；遇到不支持的格式时拒绝启用，不覆盖用户数据。

### 3.2 启用与初始化

| 状态 | 行为 |
| --- | --- |
| 无状态 | 提示 `/ffa init`；不创建业务目录，不打开数据库或连接，不注入角色与工具 |
| `pending` | 启动时仅提示；用户执行 `/ffa init` 后才加载初始化能力 |
| `ready` | 自动打开工作区并加载协作能力；等待用户请求 |

用户确认目录后，初始化创建状态和资料目录。初始化工具包括 provider 管理、目录查询、能力调用、记录读取和完成确认；正常协作与计算工具在完成后提供。工具范围不是宿主隔离，也不是独立的交易权限规则。

工作区启用不依赖外部服务。各类用途均可按任务需要选择是否接入能力提供方；不涉及目标市场时可省略市场字段。不要求行情、历史 K 线或其他业务查询回执；投资数据和交易能力均按需接入，可在初始化完成后进行。

初始化主动引导用户提供已有或希望接入的 CLI/MCP 工具名称、用途、官方文档或现有配置位置，不索取凭据值。用户可以跳过或只提供部分信息。工具提供、注册、目录发现、连接验证及手册补齐均不阻塞启用；报告未完成项与后续条件，实际调用继续执行原有安全检查。

完成工具检查：

1. 根资料入口非空。
2. 内部权限文件有效。没有接入时创建默认 `ask` 的空权限配置；已有接入的权限文件缺失或损坏时拒绝完成，不补默认权限。
3. 向用户展示已注册配置与当前权限；不把目录完整、连接成功或手册非空作为完成条件。
4. 用户确认后再次核对已注册配置、权限与根资料，再保存完成状态及可选的目标市场。确认期间配置或权限变化时停止完成。

程序检查结构，不证明接口可用、数据含义或资料质量正确。注册、验证和执行许可仍分别判断，真实模型初始化与接入流程仍需验收。市场字段省略时不补默认值；显式提供时必须是有效的非空字符串。

确认开始初始化后，在模型工作前从 `resources/templates/workspace-agents.md` 创建缺失的根 `AGENTS.md`，模板只提供目录树资料索引；完成检查时缺失则从同一模板补建。已有文件不覆盖，不另存简版模板。完成后使用 Pi 原生 `/reload` 刷新资源。中断后保留已有资料，不自动继续或清理。

### 3.3 工作区升级

`/ffa update` 仅处理初始化完成的工作区，不更新插件。当前目标工作区版本为 1；没有显式版本记录的有效工作区识别为基础版本 1。工作区版本独立于 `ffa-pi/1` 和数据库版本 1。

`src/services/upgrades/index.ts` 显式列出逐版脚本和目标版本，目前没有高于 1 的资料要求。每版声明独立说明、内部变更摘要、文件范围、只读预检查、幂等变更和验证条件。不发现或执行工作区生成的临时脚本，不建立通用迁移机制。

服务保存独立升级批次与阶段。模型通过 `ffa_update_workspace` 提交文件方案；用户确认后先备份，再执行程序阶段。阶段验证通过后才进入资料合并。声明或已确认方案改变时，需补充确认。新实例必须先显式执行命令，不依据聊天记录或启动事件自动接续。

`ffa_finish_update` 核对批次、程序效果、资料条件、报告范围和用户完成确认。确认后再次验证，并在同一 SQLite 事务中保存完成版本和该版历史。失败时保持源版本，不执行后续版本。程序检查不证明模型判断或外部事实正确。

备份按源版本、批次和确认方案分段保存。原始备份不覆盖；新增范围单独备份。`VACUUM INTO` 生成一致的数据库快照，文件及目录同步后发布备份。清单记录文件原先是否存在。不递归备份历史目录，不自动清理备份，不提供回滚。

无需升级时不保存记录、不备份、不启动模型。最后一版完成后提示原生 `/reload`，不自动重载或开展业务。日常业务暂停只是建议，不是隔离保证。完整流程及版本脚本要求见[工作区升级设计](feat/workspace-update.md)。

### 3.4 取消与关闭

每个工具绑定一个工作区实例。实例关闭后，旧工具引用拒绝调用，不能转用新实例。

新输入和主会话操作结束会取消当前前台工作，不取消显式后台专家。用户中断后，后台继续，但自动推进和新的批准暂停；下一次普通输入恢复。会话导航、fork、重载和关闭取消全部专家。取消阻止尚未发送的调用，不撤销外部副作用。

关闭先发出取消信号并解除批准等待，等待专家与计算退出，再关闭连接并等待活动调用结束，最后关闭存储。旧工具引用不能转用新实例。

完成初始化后，技能通过 `resources_discover` 提供，包内 `resources/agents/coordinator.md` 与工作区 `agents/coordinator.md` 的补充通过 `before_agent_start` 加入。显式初始化期间及就绪工作区的主会话与专家统一加载包内公共协作提示词 `resources/prompts/workspace.md`。主会话通过 `before_agent_start` 增加独立提示词 section，保留 Pi 原生工作区 `AGENTS.md` 加载；专家在自己的提示词装配入口加载公共提示词和工作区资料。初始化阶段另注入 `resources/initialization.md`，由它明确引导读取接入技能，不提前启用技能发现。未启用时不注入公共提示词。工具关闭时隐藏，执行入口仍检查实例状态。资源在使用时读取；缺失时报告错误，不回退到代码内副本。

## 4. 资料与内部状态

工作区资料目录及用途见 [README](../README.md#工作区资料)。资料正文只保存一份，通过引用连接证据，不另建知识库。包内角色和技能不复制到工作区。

| 内部文件 | 责任 |
| --- | --- |
| `.ffa/workspace.json` | 初始化状态与可选的目标市场 |
| `.ffa/permissions.json` | 唯一工具权限配置 |
| `.ffa/business.sqlite` | 能力提供方、设置、回执、调用记录、审计事件及独立的工作区版本和升级进度 |
| `.ffa/upgrades/` | 每版升级前备份与追加范围的备份；永久保留 |
| `.ffa/owner.lock` | 同一真实工作区的写入所有权 |

模型通过专用工具修改内部状态。活动扩展拦截 Pi `write`、`edit` 对内部状态的修改；工作区外文件修改需要确认。这不是对 Bash、Python 或其他扩展的强隔离。

`provider-connections` 拥有接入方法、手册要求和配置参考；`provider-calls` 拥有调用、回执读取与未知结果核对方法；`trading` 负责交易方案与复核。跨技能协作引导使用对应技能，不引用另一技能的内部参考文件。

初始化说明只负责阶段授权、工作区资料布局和启用条件。角色保留日常执行边界，不要求普通查询加载接入技能。

包内 `resources/templates/workspace-agents.md` 只用于创建缺失的根目录索引，工作区 `AGENTS.md` 后续独立维护。`resources/prompts/` 保存公共协作提示词、阶段请求与公共工具指导。公共提示词随插件更新，通过原生 `/reload` 或重新启动加载，不需要工作区升级；提示词更新不自动改变已有资料或内部状态。需要改变工作区资料或内部状态的要求另行明确处理。模板更新不追溯覆盖已创建的用户资料。

## 5. 专家与计算

### 专家协作

自有文件、类型和函数统一使用 `agent/Agent` 命名；集合使用 `agents`，中文业务说明仍称“专家”。Pi 原生协议名称和其他业务领域的标识保留，不按文本相似性替换。

`ffa_agent` 是唯一工具入口，通过 `action` 区分新建、接续、运行中补充、查看、等待和停止。职责名用 `agent`，所有目标操作用 `runId`，任务与补充文本用 `message`，前后台用 `mode`。默认前台阻塞，前后台与接续共用 5 个名额；主会话及原生 codemode 组织依赖与汇总，专家不继续创建子专家。

职责使用包内 `resources/agents/` 与工作区 `agents/`，支持通用专家和自定义方向。启动时跟随主模型与原生认证，不复制登录或主会话全部上下文。专家加载工作区及包内技能，工作区同名技能优先，不继承任意扩展。

专家会话与单次执行分离。原生自定义条目保存执行和子会话检查点，接续创建独立子分支。报告只取本次执行内容，失败保留部分交付；恢复未完成记录不自动重跑。独立复核每次新建上下文，不生成许可。

基础工具全部可用，write/edit 使用共享文件保护；默认交回报告，仅用户要求时维护正式资料。provider 调用继续经过同一批准、发送和账本入口。后台交付、用量统计、最小 UI 与验收限制的完整契约见[专家协作设计](feat/agent-collaboration.md)。

### Python 计算

`ffa_python` 使用共享解释器，默认 `/usr/bin/python3`。每次运行创建独立目录，保存源码、输入、运行状态、输出与进程记录。失败或取消也保留已有产物。

普通计算可重新运行并形成新记录；业务变更不得借此重放。Python 有宿主文件和网络权限，不是沙箱。环境、运行限制和算法适用范围见[计算参考](../resources/references/compute.md)。

### codemode

活动工具声明 `outputSchema`，返回结构化对象，并由 Pi 纳入 `ffa` namespace。ffa 不强制开启 codemode，也不另建脚本运行时。

脚本必须检查业务失败状态。有依赖的调用顺序等待；确认和专家任务需足够等待时间。脚本超时或失败不回滚已完成的外部操作。

## 6. 验证边界

本地测试使用真实 Pi SDK、文件、SQLite、CLI、Python 进程和确认组件。主要检查包加载、未启用时无干扰、严格工具分支、增量编辑与版本冲突、权限继承和修改、结果契约失效、取消、单次发送、部分保存与存储故障、未知恢复。权限文件写入故障使用真实目录权限；以 root 运行时不能证明该操作系统限制。

测试不使用 mock、stub、假模型、模拟能力提供方、个人凭据或真实交易。不用提示词文本断言证明模型行为。

以下行为仍需获准环境验收，不能由本地测试推定：

- 真实模型完成无外部服务的工作区初始化、按需接入、选择工具、并行专家交付、接续、运行中指令、后台自动推进和独立复核。
- 真实模型整理升级方案、合并用户资料、处理约束冲突和跨会话接续升级。
- 外部 MCP 分页、缓存、通知、重连、动态定义与取消。
- 宿主 TUI/RPC 的确认交互、专家看板与会话查看、焦点与主题切换、长时间调用及会话导航。
- 进程中断与外部业务结果核对的完整流程。

修改后执行 `npm run check`、`npm test` 和 `git diff --check`。包内容用 `npm pack --dry-run` 检查。验证失败时保留限制，不降低批准或存储要求以换取通过。
