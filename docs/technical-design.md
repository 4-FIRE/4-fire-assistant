# 技术设计

核心提供交易研究与受控执行，不绑定券商、策略服务或外部工具名称。模型、终端和持久会话复用 Pi 运行库。

## 依赖方向

领域层定义数据与状态。应用层组织用例并声明端口。基础设施实现端口。界面通过端口处理输入与确认，`main.ts` 组装模块。

| 目录 | 职责 |
| --- | --- |
| `domain` | 工作区、证据、精确调用、复核和执行状态 |
| `application` | 初始化、执行、专家委派、报告、记忆与角色权限 |
| `infrastructure` | 持久会话、存储、模型、资源、记忆、接入与计算 |
| `interfaces` | 终端、认证、配置与用户确认 |

## 会话与权限

真实启动路径确定工作区，同一工作区只允许一个实例。不同工作区不共享执行许可或未知义务。

日常角色为 coordinator、researcher、reviewer。initializer 只处理未完成的初始化。协调者决定直接处理或委派。专家报告与证据限主会话及本次委派访问，历史复用不恢复批准。

模型按当前任务阅读资料与记忆，不使用固定问卷或普通回答 JSON 协议。来源变更通过显式单来源操作提出，经用户确认后保存。

知识与系统回执保存为 Markdown 记忆。修改需要当前 revision，模型不能覆盖系统回执。记忆不替代实时证据或执行许可。

## 资源与接入

构建登记包内资源路径，不生成或校验文件哈希。启动应用工作区覆盖并加载已授权扩展，运行期间不热加载。资源文本不能授予权限。

扩展只提供角色与资料，不加载主进程代码。扩展能力限 read、prepare、compute，工作区须再次授权。来源操作权限单独检查。

MCP 保留原生 schema，CLI 保留明确参数绑定。schema 编译共用一个实现。连接约定固定操作、角色、复核要求与完整结果规则。安装、发现、接入和执行分别确认。

## 执行边界

精确方案 → 必要的独立复核 → 用户确认 → 参数、权限与绑定检查 → 持久化发送开始 → 原生调用一次。

确认后不再调用模型复核，不自动同步或重试。完整回执明确受理或拒绝时记为 `Observed`；受理不代表成交。结果不明记为 `Unknown`，阻止本工作区后续写入。

重启撤销进程内许可，无回执的 `DispatchStarted` 恢复为 `Unknown`。人工结案不重发调用。取消不能撤销已有副作用。

## 计算

计算后端不取行情或读取交易配置。模型取得获准数据后提交计算与来源证据。所有工作区共用固定依赖环境，实验各自保存输入、源码、来源、日志和结果。

普通 Python 不提供宿主隔离。超时、取消和输出上限只控制运行。失败与取消不记为成功实验。

配置格式见 [配置说明](configuration.md)。计算协议见 [计算说明](../resources/references/compute.md)。操作和验证命令见 [README](../README.md)。
