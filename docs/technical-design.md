# 技术设计

本文保留长期设计原则，并说明当前架构与运行边界。配置格式见 [配置说明](configuration.md)，领域术语见 [CONTEXT.md](../CONTEXT.md)。设计要求和本地测试通过都不等于真实业务行为已经验收。

## 核心目标与产品定位

**模型理解目标、阅读专业方法、自主组织工作；程序提供工具和必要约束。**

产品是专注交易的终端助手，提供交易、研究、技术分析、回测、交易机会分析、Agent 协作和投资工作区。策略维护属于显式授权的可选扩展。

优先解决以下问题：

- 助手像在执行固定程序，而不是理解目标后主动推进。
- 改变专业方法或工作方式，需要修改应用代码。
- 用户仍须反复提供背景、安排常规步骤和提醒助手纠正同一问题。

降低维护复杂度、减少接入成本和精简代码服务于上述目标。代码行数不是首要验收指标，不以删减比例代替行为验收。保留业务能力，不要求保留特定模块、文件格式、协议或调用路径。

### 非目标

- 不重新实现 Pi，也不复制 OpenClaw 的完整平台。
- 不建设通用 Agent 框架、插件市场、网关或常驻自动化系统。
- 不建立统一行情接口或覆盖所有市场的业务数据模型。
- 不把固定业务状态机改写成必须逐项执行的长提示词。
- 不增加强隔离、bubblewrap、cgroup 或自动降级方案。
- 不增加文件哈希校验。
- 不兼容旧数据和旧配置格式，不建设长期兼容层。

无需兼容不等于允许删除旧数据。旧格式工作区须保留，使用新工作目录运行；归档或删除旧数据由用户明确决定。

## 工作区、角色与自主判断

### 投资工作区

投资工作区独立组织接入、研究与执行记录，可覆盖多个市场。它不是单个会话，也不等于真实交易账户。

投资工作区由 FFA 初始化，建立可读的资料结构与工作约定。用户触发任务后助手才推进工作；资料中的待办不自动启用后台任务。

一个工作区可包含多个长期事务、研究项目和多次会话。专家使用该工作区的相关资料，不默认各自复制完整工作区。

工作区级交易阻塞不等于账户级全局协调。不同工作区连接同一账户时，不能声称已经防止跨工作区冲突。

### 角色与协作

| 角色 | 职责 | 执行边界 |
| --- | --- | --- |
| 交易协调者 | 理解目标，接续工作，识别决策障碍，组织专家并修正判断，跟踪操作结果 | 不强制委派；交易必须走受控工具 |
| 研究分析员 | 完成研究、技术分析、回测和机会比较，交付依据与限制 | 不执行交易 |
| 独立复核员 | 独立核实精确方案的事实、计算、约束及可执行性 | 复核通过不是用户授权；不执行交易 |

角色职责用文档定义，专业方法用技能定义。一个主助手按需委派独立专家，只有分离上下文或独立判断确有价值时才创建子 Agent。

研究专家收到目标、必要限制和材料引用，不默认复制整个主会话。专家可以读取相关接入手册和研究材料。主助手能追问原专家，恢复时继续原任务。

普通专家报告使用自然语言，附产物和依据引用，不强制固定 JSON、检查矩阵或复杂报告对象。运行机制保存必要的任务身份和结果关联。

独立复核额外绑定精确交易方案。复核员自行核实关键事实，不把主助手报告当作独立证据。通过或拒绝须经工具登记，不能仅凭报告文字取得执行资格。

### 工作连续性与判断

涉及过去工作时，先定位所属资料和适用约束，复用可核实的研究及专家结果。反复出现的问题若指向目标冲突、评价口径差异或假设失效，助手说明具体依据并提出修正建议，不推断用户心理或擅自改变目标。

新证据改变结论时更新原正文，保留必要条件和历史依据。旧结论不是新的独立证据。关键资料维护服务于后续工作，不要求每次回答建文档，也不建立强制研究阶段机。

### 用户规则与模型能力

用户没有明确交易规则时，助手仍可分析并提出交易方案。用户规则是个人偏好和补充，不是分析前置条件，也不替代模型的专业判断。

助手说明影响结论的假设。只有缺失信息会实质改变目标、风险判断、交易参数或授权范围时才澄清，不要求用户先填写完整投资规则。

已明确的用户限制必须遵守。一次方案的假设不自动成为长期规则。分析请求和复核结论都不授权交易。

不内置年化收益率、VIX、止盈比例、报价方式或截止时间等投资偏好，也不通过技能让旧默认规则继续生效。

正确公式、计算口径、市场制度、账户事实和接口限制不是个人投资偏好。保留必要知识，并按任务核实其来源和适用范围。

## 职责结构

```text
终端：输入、显示、用户确认、恢复选择
                    |
主助手与按需专家：模型自主组织工作
         |                       |
角色文档、技能、接入知识       基础工具与受控交易工具
                                  |
                         CLI / MCP / Python / 存储

SDK 运行机制支撑会话、工具调用、子 Agent 和任务恢复。
```

这是职责图，不要求照图创建等量目录或抽象层。依赖保持单向，边界保持清楚，不保留没有实际用途的转发层。

| 问题 | 职责归属 | 示例 |
| --- | --- | --- |
| 本次目标是什么，下一步做什么 | 模型 | 直接回答、补查数据、委派专家或停止 |
| 怎样开展可靠的专业工作 | 技能 | 样本划分、偏差检查、技术分析方法 |
| 具体外部服务怎样使用 | 接入知识 | 标的代码、复权、分页、原生参数、订单状态 |
| 怎样完成确定性的本地操作 | 工具或计算库 | 运行 Python、保存产物、费用计算 |
| 操作是否获准，结果是否确定 | 程序边界 | 精确确认、复核绑定、发送记录、未知结果阻塞 |
| 工作怎样跨进程中断继续 | SDK 运行机制及必要适配 | 任务、子 Agent、已保存工具结果 |

技能可以说明前提、方法、常见顺序和完成依据，但必须允许按当前目标裁剪。不能要求普通问答一律创建项目、委派专家或进入交易流程。

工具只对应必要的实际操作边界。不为减少行数合并成万能业务入口，也不为每个业务步骤创建专用工具。

调整研究方法、交付要求或角色职责，通常只改文档和技能。出现新的外部副作用、权限要求或确定性算法时，才考虑代码变更。

## 分层与运行时

领域层定义工作区、证据和执行状态。应用层处理受控执行、专家委派与报告权限。基础设施实现存储、原生接入、资料加载和计算。界面处理终端输入、认证及确认。

pi-durable Harness 是唯一任务运行时。WorkDoc 关联用户请求与 SDK submission；TeamDoc 保存专家身份、委派及报告引用，不建立第二套研究阶段机。

`src/infrastructure/assistant-integration.ts` 装配工具与角色，保留请求守卫和共享证据保存。`durable-expert-port.ts` 实现专家端口，管理专家会话、委派与报告归档。`execution-tools.ts` 处理交易工具及复核接入，核心执行规则仍在应用层 `ExecutionService`。

Pi 提供模型、终端组件、普通文件工具和技能加载函数。codemode 直接使用独立 pi-codemode 沙箱，不创建第二个 AgentSession，也不假设编码代理扩展可直接装入 durable。

任务、取消和恢复由同一个运行机制管理，不维护两套竞争的任务状态。任务级恢复是必要能力，不能退化为只恢复聊天记录。工具按实际副作用声明是否可重放。

运行保障包括同一真实工作区的存储所有权、实例锁，以及用户输入、任务身份、专家关联和已完成结果的可靠记录。交易发送前记录和回执必须可靠提交，不能仅依赖 SDK 默认设置。

## 文档、技能、记忆与工作区资料

### 资料职责

投资工作区根目录保存用户资料，`.ffa/` 保存独立应用状态。当前格式为 version=3，旧格式拒绝打开，既不迁移也不删除。程序只创建缺失的目录和入口，主助手在初始化中整合已有 AGENTS.md 与导航。

| 文档或资料 | 用途 |
| --- | --- |
| 各级 AGENTS.md | 工作约定、导航及目标与约束的入口；具体项目说明可保留 README.md |
| CLAUDE.md、.claude/skills | 导入公共约定、链接共享技能，不维护第二份正文 |
| areas/ | 长期目标、已确认约束、决策依据和复盘 |
| projects/ | 有明确完成条件的研究、源码、实验、证据和结论 |
| knowledge/ | 跨任务复用的知识与参考资料 |
| sources/AGENTS.md、sources/来源/GUIDE.md | 服务索引及实际使用知识 |
| 包内基础角色、roles/角色.md | 基础职责加工作区补充 |
| 包内技能、.agents/skills/名称/SKILL.md | 默认专业方法与工作区定制 |
| extensions/ | 扩展声明与角色资料，不能自行提升能力 |
| scratch/ | 临时计算和可重建中间文件，不自动清理 |
| .ffa/config.json、.ffa/state.sqlite | 连接权限、初始化记录、会话、任务与执行账本 |

记忆是一种利用资料的能力。memory_recall 直接检索当前 Markdown 文件并返回路径与片段；read/write/edit 维护唯一正文。没有独立知识数据库或记忆副本。原 MemoryPort 的系统记录能力已经移除，真实业务回执仍保存在现有程序账本中。

检索范围为根入口及明确资料目录，支持 query、scope 和 offset。隐藏目录只允许 .agents/skills 子树；其父目录也是符号链接时不进入。跳过其他隐藏目录、依赖、runs、符号链接和过大文件，不将程序状态当作普通知识。修改正文先读现有内容，编辑冲突时重新读取，不新增文件哈希校验。

工作区入口使用通用文件能力描述工作，不要求其他 agent 提供 FFA 工具。角色补充、扩展授权、初始化和任务恢复仍由 FFA 加载和管理。包内技能不自动导出；共享技能保存在 .agents/skills。跨 agent 入口及已有文件的整合方式见[配置说明](configuration.md#跨-agent-使用)。

长期约束在适用范围内持续生效。事实、推断、建议、已确认决策和执行结果通过清楚的正文区分，不强制统一字段。保存前判断是否能改善后续工作；详细实验留在所属工作，方法进入技能，不追加过程流水账。

### 加载与修改

- 包内 behavior.md 说明工作接续、判断和维护责任；基础角色说明各自职责；contract.md 解释运行与交易边界。
- 工作区角色作为补充，同名技能可以替换默认方法。定制不改变工具权限。
- 新请求和用户确认恢复前重读角色、AGENTS.md、可选 SOUL.md 及技能索引。同一请求的主助手和专家使用一致的角色定制，追问已有专家时也应用当前请求的指引。
- sources/AGENTS.md 在提示渲染时读取。手册和技能正文按任务读取，不将全工作区注入每轮上下文。
- 未初始化时加载包内首次引导及可选根 BOOTSTRAP.md。程序检查完整资料入口与实际查询回执，再请用户确认。初始化前禁止普通计算、专家委派和交易。
- 当前工作区 .ffa 外的内容可以直接维护。方法修正须有依据，用户偏好须有明确指示，临时条件不推广为通用要求。
- .ffa 配置经专用操作确认和校验后修改。程序自动维护会话和回执，普通文件工具不能改写内部状态。工作区外文件修改仍需确认。
- 扩展授权在启动时加载，角色集合或能力变更需要重新启动；普通角色文字补充无需重启。

程序只校验文档可读和必要入口，不判断所有正文的语义质量。行为是否减少用户管理成本，须通过真实模型场景验收，不能用提示词文本断言替代。

### 服务使用手册

每个服务保存一份手册，以 `sources/AGENTS.md` 为索引。服务名称和入口由实际接入决定，不预设外部工具名。

手册按服务实际情况记录：

- 用途、适用市场、支持能力和限制。
- 标的身份、代码查询、行情和历史 K 线的取得方式。
- 时间、时区、单位、复权、分页、缺失值和错误含义。
- 原生命令、MCP 工具及参数的使用方法。
- 交易副作用、订单身份、状态含义和查询核对方法。
- 已验证的调用示例、资料来源、验证时间和实际回执引用。
- 尚未验证的内容及已知缺口。

模板提醒模型理解必要事项，不要求所有服务使用相同字段，也不强制每轮重写手册。凭据只保存引用，不将凭据值写入提示词、手册、记忆或归档示例。

## 接入与初始化

WorkspaceServices 持有当前工作区来源。连接、移除和完成初始化串行更新并原子保存配置。新来源连接成功后替换旧实例，失败时保留原配置。独立来源故障不阻断其他查询。

来源目录刷新会重试已禁用来源，成功后重新启用。取消刷新不会改变禁用状态。CLI 入口恢复后使用新的连接版本，旧证据和许可不会重新生效。连接已关闭或配置需要变更时，仍须修复该来源。

MCP 保留原生工具和 schema，CLI 使用显式 argv 或标准输入绑定。权限只描述可调用角色及 read/write 分类，没有统一行情字段。

`application-config.ts` 只处理本机应用配置。`integrations/connection-config.ts` 校验 CLI/MCP 连接，`operation-contract.ts` 校验通用操作约定，`cli-contract.ts` 校验 CLI 参数绑定。通用约定不补造 CLI 命令、argv 或 schema。`digest.ts` 提供执行身份所需的 JSON 摘要，不依赖 MCP。

source_read 保存来源绑定、实际参数、时间和回执。finish_initialization 读取本主会话的证据，检查成功状态、当前连接、手册及根目录资料结构，再请求用户确认。模型解释数据语义；程序不伪装成通用行情解析器。

缺失或空白的必要文档会提示补齐具体文件。其他读取故障会报告路径和错误类型，不作为缺失文件处理。

## 交易

精确方案 → 独立复核 → 用户确认 → 程序绑定检查 → 持久化发送前记录 → 一次原生调用 → 明确回执或未知义务。

确认展示 CLI 入口与实际参数，或 MCP 连接、工具与参数。所有真实交易写入都需要复核。参数、权限或连接变化使旧许可失效。

业务回执恰好匹配受理或拒绝条件时记录 Observed；受理不代表成交。中断、条件冲突或不完整结果保持 Unknown，阻止本工作区新交易写入，允许查询和研究。

发送异常或远端回执无法可靠归档时，程序通知用户、向模型报错，并关闭当前进程的写入路径。DispatchStarted 不能作为成功工具结果返回。

重启清除进程内许可，将无可靠回执的 DispatchStarted 转为 Unknown。人工结案不授权重发。SQLite 保留 WAL/FULL 和单实例所有权锁。

## 研究与 codemode

普通 Python 使用共享依赖环境，接收源码和输入，不要求固定计算操作协议。每次运行保存源码、输入、证据、状态和实时日志。可选 owner 指定 projects 或 areas 下的目录，省略时写入 scratch/runs。运行列表覆盖三种归属并返回相对路径。临时运行成为正式证据时，保留完整必要记录和旧引用，不自动清理。现有指标与 A 股回测代码只是可选库，不是助手能力上限。

codemode 的嵌套调用执行同一组角色工具与请求守卫。脚本开始及每次嵌套调用前后保存记录。成功脚本的 store/load 状态按会话保存；错误不会回滚外部副作用。

codemode 和 Python 标记 unsafe，不自动重放。旧运行若不属于当前运行器，读取时将未完成状态显示为 interrupted，保留原记录。codemode 记录支持分页；脚本结束时仍未完成的调用不能计为完整成功。

可重放查询及专家委派仍由 durable 管理。脚本内不开放专家委派，避免把持久子任务隐藏在不可重放脚本中。

## 恢复与可信边界

CLI 默认启动新会话。位置参数提供请求，-p/--print 控制处理后退出。-r/--resume 选择历史会话，--session 打开指定 UUID。不再自动选择最近会话。

打开工作区和选择会话不启用 SDK 调度。有未完成任务时，交互界面先询问恢复、取消或暂不处理。用户确认后恢复原请求及原专家任务，已完成报告继续使用，不重新生成。单次输出模式拒绝自动恢复，也不提交新请求。停止、退出和业务结案是不同操作。

当前 SDK 启动调度会推进全部未完成运行。新请求、恢复和取消操作先检查当前主会话及其专家范围。其他范围有任务或输入时拒绝操作，避免未确认的旧运行被一同恢复。默认新会话仍可创建；原任务和记录保留。

启动和切换会话使用同一项模型检查。未完成请求仍绑定原模型；当前模型不匹配时拒绝进入。恢复前重读工作区指引，但保留原请求、专家身份和已完成结果。切换失败不改变活动会话。没有未完成请求的会话才应用当前模型配置。

请求关联检查包括当前主会话及其专家，不把其他主会话的输入当作当前请求的残留。当前范围的残留输入由用户执行 `/cancel` 级联取消；打开工作区不会自动取消任务。SDK 任务定义阻塞仍单独报告。

交易防重和未知义务的阻塞范围是当前工作区，不提供同一账户跨工作区的交易协调，也不保证外部服务恰好成交一次。

取消停止当前任务，关闭保留未完成工作；两者都保留记录和已发生的副作用。恢复不沿用进程内交易许可。

初始化和交易许可是程序约束，不等于宿主安全隔离。普通 Python 具有当前用户的宿主访问能力；不能宣称它无法绕过受控路径。

源码与依赖不做新增文件哈希校验。操作和参数摘要只用于执行身份绑定，不用于验证文件内容。
