# Pi 扩展技术设计

本文说明当前架构、行为边界和验证状态。本地逻辑与真实 SDK 加载已有测试；真实模型、外部服务与宿主交互尚未完成验收。

[CONTEXT.md](../CONTEXT.md)只维护领域术语。通用开发原则见[架构要求](architecture-guidelines.md)，完整能力接入与执行分类见[能力设计](capability-design.md)。

## 1. 目标与边界

**模型负责分析与规划；FFA 提供资料入口、可追溯工具和执行保障。**

FFA 支持交易、研究、技术分析、回测、机会分析与专家协作。角色只提供职责、交付边界和关键执行限制。包内技能说明 FFA 服务接入与交易约定；通用分析方法由模型选择。计算环境和实际库限制通过工具说明指向参考资料。

模型所需资料按任务读取。服务手册记录原生文档依据、字段含义、接口关系、覆盖缺口及验证回执；当前能力和权限由工具提供。提示词不承担开发历史记录，也不以重复通用知识代替资源与契约。提示词效果通过任务审阅判断，不用文本或数量断言证明模型行为。

FFA 直接使用 `pi`，以一个 Pi package 分发，一个主扩展入口装配业务能力。内部按职责分模块，不另建插件平台。

- 不维护独立 CLI、终端渲染器、模型登录、模型配置或主会话循环。必要的确认组件通过 Pi 原生 custom UI 显示。
- 接受 Pi 原生会话恢复，不另建通用任务调度、持久重放或跨会话任务扫描。
- 不兼容历史工作区、配置、会话、数据库、命令或扩展声明。不建立旧格式适配、转换或默认补全。检测到不支持的格式时拒绝启用，不自动迁移、重建或删除用户数据。
- 不删除用户工作区、凭据、历史资料或交易记录。
- 不增加后台监控、定时研究、自动交易、强隔离系统或文件哈希校验。

自动启用投资能力，不等于自动推进工作。模型在用户触发后工作；读取待办不构成新任务或交易授权。

## 2. 职责分配

```text
Pi 原生 CLI、主 Agent 与会话
  ├─ Pi 模型配置、登录、交互、文件工具、Bash、codemode
  ├─ FFA 角色文档、专业技能与投资工作区资料
  ├─ 原生数据 CLI / MCP 与服务使用手册
  └─ FFA 扩展
       ├─ 工作区启用与初始化
       ├─ 必要的资料检索和计算记录工具
       ├─ 按需专家协作
       └─ 受控变更与工作区级持久账本
```

| 事项 | 责任与限制 |
| --- | --- |
| 输入、流式输出、模型选择、登录、会话选择、压缩 | 直接使用 Pi，不保留 FFA 平行实现 |
| 主助手 | 当前 Pi 会话中的协调者，负责知识学习、问答、投资分析与操作协调 |
| 职责与方法 | 角色文档与技能；改变普通研究方法通常不改代码 |
| 文件、Bash、codemode | 优先使用 Pi；只为已确认的业务边界增加检查 |
| 工具来源 | 完整发现和分析原生能力；FFA MCP 使用受控私有连接，不建立统一行情接口 |
| 专家 | 分离上下文的研究分析员或独立复核员，按需创建 |
| 计算 | 普通 Python 加必要计算库，保存可追溯产物 |
| 业务变更 | 程序验证精确准备、必要复核、用户授权、发送与回执；交易属于需独立复核的一类 |
| 会话与研究恢复 | Pi 会话、资料和已保存结果，不保证恢复原工具调用位置 |
| 跨会话交易事实 | 独立持久账本，不随聊天分支变化 |

### 2.1 代码责任与依赖

`index.ts` 只装配依赖和注册宿主入口。`tools/` 拥有完整工具契约和结果转换；`services/` 维护业务规则与操作顺序。工具和命令调用同一服务，不直接访问数据库或交易传输。

`model/` 使用无业务行为的数据类。实例进入 JSON、身份计算、存储和工具返回边界前，显式转成普通数据，不放宽 JSON 校验。

Pi 上下文留在工具与宿主接入中。服务只接收请求范围、分支引用等普通数据，以及必要的窄调用能力。`integrations/` 实现实际调用；`storage/` 负责事务与可靠保存；`ui/` 负责确认队列和展示。

`extension/` 管理工作区实例与事件。工具绑定一个实例，关闭后旧引用拒绝调用，不自动切换到新实例。请求级许可、专家证据和持久交易事实分别管理。

主要模块按下列责任维护：

| 模块 | 责任 |
| --- | --- |
| `services/source-service.ts`、`source-config.ts`、`source-access.ts`、`source-catalog.ts` | 来源配置、完整目录、调用约定、绑定与查询证据 |
| `services/initialization-service.ts`、`workspace-files.ts` | 初始化条件、用户资料保留与完成状态 |
| `services/execution-service.ts`、`execution-ledger.ts` | 变更准备、复核、授权、发送顺序与意图状态转换 |
| `services/expert-service.ts` | 分支引用、研究员追问与独立复核证据 |
| `services/research-service.ts`、`record-service.ts` | 计算产物与受限记录读取 |
| `integrations/` | CLI、私有 MCP、进程、专家会话与资源加载 |
| `storage/` | 工作区状态、所有权、SQLite 事务与可靠保存 |
| `extension/` | 命令、事件、请求范围与工作区实例寿命 |
| `ui/` | 确认队列、窗口与来源摘要 |
| `common/` | JSON、校验、文件与包资源路径 |

账本服务判断业务状态转换；存储层不作业务决定。确认只返回用户选择，服务在确认后复查请求、绑定、取消和存储状态。

关闭时先使实例与许可失效，再取消调用并释放连接和存储。单个清理失败不能跳过其他资源释放。确认队列携带取消信号，不展示已失效的请求。

工具集合显式维护，不扫描目录。共用执行输出放在 `tools/schemas/execution.ts`，来源结构放在 `tools/schemas/source.ts`。专属输入输出与执行适配保留在所属工具文件。

`npm run check` 同时执行 TypeScript 和 dependency-cruiser 检查。依赖规则放在 `.dependency-cruiser.cjs`，检查类型、动态导入和循环依赖：

- 模型、基础模块和存储不反向依赖业务或宿主。
- 服务不依赖工具、UI、装配入口或 Pi SDK。
- 服务只直接使用无 Pi 依赖的进程接入；其他宿主能力通过窄约定传入。
- 工具和命令不直接访问底层存储或来源传输。
- 接入可引用服务约定的类型，但不运行服务实现。专家接入负责装配专家工具。

包资源路径由 `common/paths.ts` 定位。源码加载与 `dist` 测试导入都必须能访问角色、技能、提示词、文档模板和计算库。

`resources/templates/workspace-agents.md` 提供工作区根 AGENTS.md 的初始正文，以独占创建保留用户已有文件。`resources/prompts/initialization-request.md` 在初始化命令执行时读取；`resources/prompts/tool-guidelines.md` 在工具注册时按空行分段读取，每段作为一条公共指导。资源读取不在扩展导入时发生，缺失资源直接报错，不回退到代码内副本。

这些文件由 FFA 显式读取，不作为 Pi 原生提示模板自动发现。工具描述与输入输出契约仍保留在工具模块，动态数据由代码组装；不增加模板引擎或占位符协议。

## 3. 安装、启用与初始化

### 3.1 加载范围

默认使用 Pi 的本地包安装方式，将包声明写入根目录的 `.pi/settings.json`。仅支持从投资工作区根目录启动 `pi`，不向父目录搜索 FFA 状态，不自动初始化子目录。

安装、Pi 项目信任、FFA 初始化、服务接入和交易授权是不同操作。安装包或授予项目信任不表示同意创建投资资料，更不授权交易。

包名为 `4-fire-assistant`，当前从本地路径安装，保持 private=true。安装方式见 README。内部工作区标识为 `ffa-pi/2`，业务数据库版本为 2，不读取旧格式。

### 3.2 启用状态

以下状态只控制 FFA 能力，不是研究任务阶段机。

| 状态 | 启动行为 | 用户触发后的行为 |
| --- | --- | --- |
| 未开始初始化 | 简短提示 `/ffa init`；保持普通 Pi 行为 | 命令展示根目录，请用户确认创建工作区 |
| 初始化未完成 | 仅提示“初始化未完成”，不自动继续 | 用户执行 `/ffa init` 后检查已有成果，补齐缺项 |
| 初始化完成 | 自动加载投资角色、技能和业务工具 | 等待用户请求；不自动继续旧研究或执行交易 |

未开始初始化时，除包安装声明、初始化命令和终端提示外，FFA 不应产生工作影响：

- 不注入角色、技能索引、工具指导或模型可见通知。
- 不注册业务工具，不改变 Pi 模型、活动工具和会话行为。
- 不连接 FFA 服务，不打开业务数据库或创建锁文件，不启动后台资源。
- 不创建 `.ffa/`、投资目录或修改用户资料。
- 不限制普通 Pi 工具，也不接管其他扩展。

检查当前根目录的状态可以只读进行。状态损坏或格式不支持时，报告问题并保持 FFA 业务关闭；不能当成全新目录覆盖。普通 Pi 工作仍可继续。

### 3.3 初始化过程

`/ffa init` 是 Pi 扩展命令，不是独立 CLI。用户确认根目录后，扩展记录初始化已开始，并仅加载初始化所需指引与工具。模型在当前 Pi 会话中完成引导，不创建独立初始化助手。

模型负责理解目标市场、读取服务说明、整合资料和解释真实查询结果。工具负责校验结构、记录调用证据、保存状态和请求用户确认。

完成条件：

1. 投资资料结构与必要入口可用，已有内容得到保留。全部可见能力均已分析；无法确认的能力说明依据，保持禁止执行。
2. 目标市场的数据服务已联通。
3. 已取得成功的真实行情与历史 K 线调用记录，绑定当前来源与参数。
4. 模型已解释数据语义并记录服务使用手册。
5. 完成工具核实必要条件，用户确认启用。

交易服务可选。CLI 与 MCP 都可作为数据或交易来源。服务故障和后续变更局部修复，不重做完整初始化。

初始化完成前，仅提供接入、资料准备和验证能力，不开放正常 FFA 研究与交易工具；这不限制用户在普通 Pi 中自行工作。

初始化中断后保留已创建的资料和证据，不自动删除、重装或继续。重启后不加载初始化角色和 FFA 服务，直到用户再次执行命令。用户仍可按 Pi 原生方式打开旧聊天，其历史不会被 FFA 擦除。

为防止中断状态影响普通 Pi：

- 未完成的 FFA 指引与配置暂存于非自动加载位置。
- 完成前不向 `AGENTS.md`、`.agents/skills` 或项目 MCP 自动加载配置写入 FFA 激活内容。
- 再次接续时核对现有资料、连接和证据，不把历史成功等同于当前可用。
- 完成状态可靠保存后再启用能力；任一步失败都不能误记为初始化完成。

### 3.4 资源与生命周期

使用显式 Pi package 清单，仅自动加载扩展入口。不能把 FFA 全部技能和提示模板静态声明为始终加载，也不能依赖默认目录发现绕过状态判断。

通过 `resources_discover` 按启用状态提供包内技能。通过 `before_agent_start` 加入适用的角色职责。业务工具按状态注册，执行入口再次检查业务前提。

活动中的 FFA 工具使用默认 direct exposure，并归入 ffa namespace。Pi 自动将它们加入 codemode 的 ALL_TOOLS 与发现接口。确认和专家编排工具也可嵌套调用；不以 model-only 作为安全边界。关闭时重新注册为 hidden。FFA 不替用户开启 codemode。

所有业务工具声明具体 outputSchema，并返回 structuredContent。文本供用户和模型阅读，结构化值供脚本访问；动态服务数据保留 unknown 类型。分页记录的 text 字段仍是 JSON 文本。抛错拒绝调用；带业务数据的失败返回结构化对象和 isError，脚本须检查业务状态。

有依赖的调用按业务顺序 await。确认队列只排列窗口，不承担整组业务编排。脚本超时或取消传播到嵌套工具，已完成的外部副作用不回滚；交易不得自动重试。

初始化完成后提示用户执行 Pi 原生 `/reload`，或再次执行 `/ffa init` 刷新资源。工具不能调用仅限命令上下文的重载接口；不重建资源监视或热加载系统。以后启动自动启用。

工厂只注册必要入口，不启动连接、进程或计时器。资源在实际启用时打开，在退出、切换和重载时幂等关闭。旧上下文失效后不得继续使用。

## 4. 投资工作区与资料

| 位置 | 职责 |
| --- | --- |
| `.pi/` | Pi 本地配置和包声明；不由 FFA 重建宿主配置系统 |
| `AGENTS.md` | 用户工作约定与资料导航；先读再合并，不覆盖用户正文 |
| `areas/` | 长期投资目标、已确认约束、决策与复盘 |
| `projects/` | 有完成条件的研究、代码、证据和实验 |
| `knowledge/` | 可跨任务复用的方法知识与参考资料 |
| `sources/` | 每个服务一份使用手册，以索引导航 |
| `roles/`、`.agents/skills/` | 按需创建的角色补充和用户专业方法 |
| `scratch/` | 临时计算及可重建产物，不自动清理 |
| `.ffa/` | FFA 初始化状态、必要权限与连接绑定、证据和交易账本 |

`.ffa/workspace.json` 保存启用状态，`business.sqlite` 保存来源、回执和交易记录，`owner.lock` 保护工作区所有权。`.ffa/` 不保存另一套主会话、任务调度记录或模型认证配置。

包内角色与技能不复制到工作区。用户定制不能扩大程序权限。同名技能的选择须明确且可验证。

记忆是查找和更新所属资料的能力。正文只保留一份，由普通 Pi 文件工具维护，不建立独立知识库。

根 AGENTS.md 只维护资料导航和已确认的工作区约定。需要保留的过程放在具体项目；长期事务保存目标、约束与结论，引用必要证据。服务手册保存当前用法和验证依据。资料更新所属正文，包内规则不复制到工作区。简单问答不强制建立项目或保存文档。

个人信息不足时先完成公共证据分析，给出条件化方案并说明个人适配限制。分析假设不自动成为用户约定。模型在请求范围内完成必要查询与验证，以足以支持本次交付为完成条件；关键缺口阻止有效交付或下一步超出范围时询问。

资料可被其他助手阅读，但不保证各宿主的运行配置互通。不自动创建其他宿主的配置、符号链接或兼容入口。共享资料不能授予交易许可。

## 5. 专家协作与恢复

主助手自行判断是否委派。研究、技术分析、回测和机会比较通常是同一研究角色采用不同技能，不按功能名称创建固定 Agent 流程。

- 专家接收目标、必要限制和材料引用，不默认复制完整主会话。
- 角色文档定义职责；程序限定实际工具权限。研究员与复核员不能执行交易。
- 包内技能索引按职责选择：研究员不加载操作技能，复核员加载 trading。工作区技能保持加载和同名覆盖规则；索引不是访问权限。
- 普通报告使用自然语言及产物引用，不强制业务报告 schema。
- 独立复核绑定精确方案，自行核验事实，通过工具登记决定；报告中的“通过”不授予执行资格。
- 已保存的报告和资料可继续使用，易变事实重新核实。

委派工具使用 Pi SDK 的持久专家会话。复用 Pi 模型配置，不增加专家登录或模型配置系统。专家工具和资源集合显式选择，不自动继承全部用户扩展、交易工具或初始化入口。

只记录追问和查找结果所需的专家会话引用，不建立独立任务运行时。专家引用须遵守当前会话分支；真实交易事实则独立于分支。

用户接受 Pi 现有恢复方式。主会话和专家会话可以根据已有记录继续，不保证中断请求、原工具调用或未落盘结果精确恢复。已完成结果不得因恢复而无理由重算；中断的普通计算可重新运行并形成新记录。

专家会话的创建、取消、引用和接续须独立验证，不以委派工具可用代替真实模型验收。

## 6. 数据接入与计算

FFA 先确认连接，再发现当前凭据可见的全部 MCP 工具分页。CLI 按完整帮助和文档建立已知目录，必须记录资料依据和覆盖缺口。不按当前任务、服务名称或预设业务类别裁剪接口。

来源目录保留原生定义、用途、判断依据、后果和跨接口关系。状态影响为 observe、change、unresolved；理解状态区分 unassessed、uncertain 和 understood。用户禁止或服务已撤下的工具仍保留。程序核对发现清单和分析目录，不能用挑选列表替代完整目录。

FFA MCP 统一使用私有连接，通过 ffa_sources 查看能力，通过 ffa_discover_source 刷新。不注册 Pi 原生工具，避免新增或变化的工具绕过调用约定。用户自有 Pi MCP 仍由 Pi 管理；FFA 不实现 OAuth 管理。

每次 MCP 调用前核对全部原生定义。新增、变化和重新出现的工具撤销原分析；发现失败保留旧目录但禁止调用。原生只读提示不是权限证明。目录变更、连接和调用约定变化使旧准备与复核许可失效。

服务手册记录能力地图、实际市场、参数、单位、分页、限制、错误和验证依据。模型分析是接入建议，不是服务行为的证明。详细字段与接入顺序见连接说明。

初始化和独立复核通过 ffa_source_read 调用已理解的 observe 操作，保存来源、参数、时间、结果和成功状态。FFA 工具的直接及 codemode 调用经过 Pi 工具管线；私有传输另有实际发送门禁。聊天描述不能冒充回执。

普通 Python 使用共享环境和必要计算库，保存源码、输入、依据、日志和产物。结果可归属于项目、长期事务或临时运行。包内指标和回测算法按实际用途使用，不限制模型只能调用固定计算协议。单次运行限时 30 秒，输出上限 2 MiB；失败、取消或超限保留记录，不报告成功。

使用 Pi 原生 codemode，不建立 FFA 通用脚本日志、store/load 或重放运行时。需要成为研究证据的计算产物仍显式保存。脚本失败不回滚已发生的外部副作用。

Python、Bash、codemode 和扩展按可信本地使用设计，不是沙箱。

## 7. 受控变更

ffa_prepare_change 与 ffa_execute_change 覆盖所有业务变更，交易是其中一类。confirmation 需要当前请求内的精确准备与用户确认；independent 还需要独立证据复核。资金、订单、后续自动执行、权限、重要资料破坏及其他声明的敏感影响要求 independent。影响不明确时禁止执行。

以下账本、授权和防重发规则适用于全部变更。execution 是必填字段，不对旧意图提供默认值；不兼容的工作区与数据库在启用前拒绝，不删除历史数据。交易必须独立复核。

```text
精确方案 → 必要独立复核 → 用户确认 → 发送入口校验
         → 可靠保存发送前记录 → 一次原生调用
         → 明确回执或未知执行义务
```

所有 FFA 确认共用一个入口，串行排队。TUI 使用 Pi 原生 custom UI：详情放在可滚动区域，取消与确认固定在底部。默认选择取消；滚动不改变选择。窗口过小时禁止确认。取消信号关闭窗口，并阻止排队中的已取消请求打开新窗口。

D 切换摘要和完整配置，并重置选择为取消。复杂类型简写，完整说明、参数限制、CLI 绑定与回执规则保留在完整配置中。ffa_sources 使用同一摘要格式，支持按来源和操作查看完整约定；结构化输出保留原始说明与 schema。服务文本中的终端控制字符转义显示，但摘要不把换行转成字面的反斜杠 n。

RPC 使用 Pi 原生 confirm 请求，分别传送标题和完整详情；接入请求在完整配置前附加接口摘要。客户端负责布局。FFA 不修改 Pi 自带的 MCP OAuth 登录窗口。

变更确认显示服务、操作、判断依据、实际影响和全部参数。没有可用且经验证的用户确认通道时拒绝变更，不以模型回答、默认同意或会话级许可替代。

所有 FFA 原生来源操作只通过受控入口调用，未知能力没有调用权限。私有 MCP 对观察与变更都在实际传输入口消费单次许可；变更还要求账本发送前记录。不得通过其他 MCP 配置重复公开同一受控服务。

`tool_call` 检查用于阻止已接入交易操作的直接调用，不能替代实际发送入口的绑定校验。检查覆盖可达的 MCP、工具搜索和 codemode 嵌套路径；隐藏声明或移出活动工具集不等于不可调用。

授权绑定当前操作、完整参数、服务连接、方案版本和有效调用范围。复核通过与用户授权分开保存。并发确认与执行不得重复发送；参数改变必须重新复核和确认。

持久交易账本独立于 Pi 聊天历史：

- 发送前记录可靠提交后才能调用外部服务。
- 回执受理不表示成交；超时、异常、冲突或不完整回执保持未知。
- 发送前记录存在而可靠回执缺失时，重新打开账本须转入待核对状态，不重发。
- 存储失败关闭交易写入路径，不将未保存回执当成未执行。
- 未知义务阻止本工作区所有新变更，允许观察和研究。
- 模型可以查询核对，用户确认后人工结案；结案不授予重发许可。
- `/tree`、fork、clone、会话切换和重载不回退账本，也不复制或恢复旧许可。
- 重启、重载、取消和相关会话变化使未消费许可失效。

交易存储使用真实事务与可靠同步，并保护同一真实工作区的写入所有权。只提供受控变更所需的存储与并发约束，不建立通用任务存储体系。不声称提供账户级跨工作区防重或外部服务恰好成交一次。

扩展与任意本地代码共享宿主权限。受控路径不保证阻止恶意扩展、Bash 或 Python 绕过。不能靠解析任意 shell 字符串建立完整安全边界。

- 真实包安装、源码加载、资源路径与未启用时无干扰。

- 变更准备、用户确认、独立复核要求、取消、请求失效和绑定变化。

- 账本事务、工作区所有权、未知义务、重启恢复与人工结案。
- 不支持的工作区和数据库格式拒绝启用，原数据保留。
