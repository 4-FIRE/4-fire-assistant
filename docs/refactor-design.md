# 模型自主组织工作的交易助手重构设计

状态：设计共识已确认，正在实施。本文保留 Q1—Q28 的目标决定；实际落地与验证范围见 [实施进展](refactor-progress.md)。

核心目标：**模型理解目标、阅读专业方法、自主组织工作；程序提供工具和必要约束。**

当前实现见 [技术设计](technical-design.md)，配置格式见 [配置说明](configuration.md)。实施以本文为目标，不以代码已编译或单元测试通过代替行为验收。领域术语见 [CONTEXT.md](../CONTEXT.md)。

## 1. 目标、优先级与非目标

### 1.1 产品定位

产品仍是专注交易的终端助手。保留交易、研究、技术分析、回测、交易机会分析、Agent 协作和投资工作区。

优先解决两个问题：

- 助手像在执行固定程序，而不是理解目标后主动推进。
- 改变专业方法或工作方式，需要修改应用代码。

减少维护复杂度、降低服务接入成本和精简代码应随之实现。代码行数不是首要验收指标，不承诺在技术核实前达到某个删减比例。

保留业务能力，不要求保留当前模块、文件格式、协议或调用路径。

### 1.2 明确不做

- 不再实现一个 Pi，也不复制 OpenClaw 的完整平台。
- 不建设通用 Agent 框架、插件市场、网关或常驻自动化系统。
- 不建立统一行情接口或覆盖所有市场的业务数据模型。
- 不把固定业务状态机改写成必须逐项执行的长提示词。
- 不增加强隔离、bubblewrap、cgroup 或自动降级方案。
- 不新增文件哈希校验。
- 不兼容旧数据和旧配置格式，不建设长期兼容层。

无需兼容不等于允许删除旧数据。实施和试运行使用新工作区；旧数据保留或由用户明确决定如何归档。

## 2. 防止“换皮重构”

每项现有逻辑先判断其职责，再决定去向。

| 问题 | 应归属 | 示例 |
| --- | --- | --- |
| 本次目标是什么，下一步做什么 | 模型 | 直接回答、补查数据、委派专家或停止 |
| 怎样开展可靠的专业工作 | 技能 | 样本划分、偏差检查、技术分析方法 |
| 具体外部服务怎样使用 | 接入知识 | 标的代码、复权、分页、原生参数、订单状态 |
| 怎样完成确定性的本地操作 | 工具或计算库 | 运行 Python、保存产物、费用计算 |
| 操作是否获准，结果是否确定 | 程序边界 | 精确确认、复核绑定、发送记录、未知结果阻塞 |
| 工作怎样跨进程中断继续 | SDK 运行机制及必要适配 | 任务、子 Agent、已保存工具结果 |

技能可以说明前提、方法、常见顺序和完成依据，但必须允许按当前目标裁剪。不能通过提示词要求普通问答一律创建项目、委派专家或进入交易流程。

工具不应为了减少行数而合并成一个难以验证的万能业务入口。也不应为每个业务步骤创建专用工具。只保留真实操作边界所需的工具。

调整研究方法、交付要求或角色职责，通常只改文档和技能。出现新的外部副作用、权限要求或确定性算法时，才考虑代码变更。

## 3. 工作区、角色与自主判断

### 3.1 投资工作区

沿用现有定义：投资工作区独立组织接入、研究与执行记录，可覆盖多个市场。它不是单个会话，也不等于真实交易账户。

一个工作区可包含多个研究项目和多次会话。专家使用该工作区的相关资料，不默认各自复制完整工作区。

工作区级交易阻塞不等于账户级全局协调。不同工作区连接同一账户时，不能声称已经防止跨工作区冲突。

### 3.2 保留三个角色

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 交易协调者 | 理解目标，直接完成简单任务，组织专家，准备方案并跟踪结果 | 不为所有任务强制委派；交易仍走受控工具 |
| 研究分析员 | 完成研究、技术分析、回测和机会比较，交付依据与限制 | 不执行交易 |
| 独立复核员 | 独立核实精确方案的事实、计算、约束及可执行性 | 复核通过不是用户授权；不执行交易 |

角色职责用文档定义，专业方法用技能定义。保留一个主助手，加按需委派的独立专家。只有隔开上下文或独立判断确有价值时才创建子 Agent。

研究专家收到目标、必要限制和材料引用，不默认复制整个主会话。专家可以读取相关接入手册和研究材料。主助手能追问原专家，恢复时能找回原任务。

普通专家报告使用自然语言，附产物和依据引用，不强制固定 JSON、检查矩阵或复杂报告对象。必要的任务身份和结果关联由运行机制保存。

独立复核额外绑定精确交易方案。复核员自行核实关键事实，不把主助手报告当作独立证据。通过或拒绝须经工具登记，不能仅凭报告中的文字取得执行资格。

### 3.3 用户规则与模型能力

用户没有明确交易规则时，助手仍可分析并提出交易方案。用户规则是个人偏好和补充，不是分析前置条件，也不替代模型的专业判断。

助手应说明影响结论的假设。只有缺失信息会实质改变目标、风险判断、交易参数或授权范围时才澄清，不要求用户先填写完整投资规则。

已明确的用户限制必须遵守。一次方案的假设不自动成为长期规则。分析请求不授权交易，复核结论也不授权交易。

删除旧默认投资规则，包括现有年化收益率、VIX、止盈比例、报价方式和截止时间等默认偏好。不把它们搬进技能后继续默认生效。

正确的公式、计算口径、市场制度、账户事实和接口限制不是个人投资偏好。保留必要知识，并按任务核实其来源和适用范围。

## 4. 目标结构与 SDK 复用

### 4.1 职责结构

```text
终端：输入、显示、用户确认、恢复选择
                    |
主助手与按需专家：模型自主组织工作
         |                       |
角色文档、技能、接入知识       基础工具与受控交易工具
                                  |
                         CLI / MCP / Python / 存储

SDK 运行机制支撑会话、工具调用、子 Agent 和任务恢复。
```

这是职责图，不要求照图创建等量目录或抽象层。保留单向依赖和清楚边界，合并没有实际用途的转发层。

### 4.2 已核实事实与待核实适配

当前主运行时使用 `pi-durable` 的 `Harness`，不是直接薄封装 `createAgentSession()`。初始化另行调用模型并自行分发工具。

已安装的 Pi 1.1.0 文档说明：

- `pi-durable` 提供持久任务、会话、子 Agent、恢复和工具重放分类。
- 中断工具只有声明为可安全重放时才会被重跑；其他调用返回中断结果。
- `pi-coding-agent` 提供会话、技能、上下文文件和资源加载能力。
- SDK 会话需要显式装配 codemode、工具搜索和 MCP 扩展，不能假设等同于 CLI 默认行为。
- codemode 在 QuickJS 中运行，通过暴露的工具访问外部；工具副作用不会因脚本失败而回滚。

目标是优先复用上述能力，不重新编写 Agent 循环、技能框架或持久任务调度器。

**不能假定两个 SDK 的扩展与生命周期可直接互换。** 实施前核实资源加载、codemode、MCP 与持久工具执行的适配方式。明确由一个运行机制拥有任务、取消和恢复，不维护两套竞争的任务状态。

任务恢复是硬需求。不能为直接使用 `AgentSession` 而退化成聊天记录恢复，也不能为保留当前 `Harness` 包装而拒绝精简。

### 4.3 必须保留的运行保障

- 同一真实工作区的存储所有权与必要实例锁。
- 用户输入、任务身份、专家关联和已完成结果的可靠记录。
- 取消、关闭与恢复的明确区别。
- 工具调用是否可重放的分类。
- 交易发送前记录和回执记录的可靠提交。

SDK 的默认存储设置不能直接视为交易所需的持久保证。当前代码使用 SQLite WAL 与 FULL 同步；实施时验证等效保障，不因删代码而悄悄降级。

## 5. 文档、技能、记忆与工作区资料

### 5.1 文档职责

| 文档或资料 | 用途 |
| --- | --- |
| 工作区 `AGENTS.md` | 日常工作约定、资料入口和记忆使用指引 |
| `BOOTSTRAP.md` | 首次初始化指导，由同一个主助手执行 |
| 角色文档 | 协调者、研究分析员、独立复核员的职责 |
| `skills/<名称>/SKILL.md` | 按需加载的专业方法及支持材料 |
| `sources/AGENTS.md` | 接入来源索引，说明何时阅读哪份手册 |
| `sources/<来源>/GUIDE.md` | 一个服务的实际使用知识与验证记录 |
| 工作区记忆 | 用户纠正、稳定偏好、研究结论等保留知识 |
| 研究项目资料 | 问题、实验源码、输入、日志、结果和详细报告 |
| 程序状态 | 连接权限、初始化完成记录、任务与交易账本 |

`BOOT.md` 只在确有用户定制启动任务时加入。`SOUL.md` 只在身份、风格或行为定位确有独立内容时加入。不为模仿 OpenClaw 而创建重复或空文件。

上述路径说明职责和文档约定，不锁定所有物理目录。实施时明确产品工作区根目录，避免覆盖代码仓库或其他工具的同名文件。

### 5.2 加载与修改

- 包内默认角色和技能与工作区定制分开；冲突和生效方式应明确可见。
- 启动提供必要的角色指引、技能索引和资料入口，详细内容按任务阅读。
- 显式接入 `sources/AGENTS.md` 的发现或引用路径，不假设 SDK 会自动扫描所有嵌套同名文件。
- 不把所有服务文档、技能和历史记忆每轮全部注入上下文。
- 研究产物和普通记忆可按约定保存。
- 修改长期角色、技能和行为指引前征求用户确认。
- 接入事实的更新属于知识维护；改变长期行为或权限时仍须确认。
- 文档和记忆不能授予权限，也不能覆盖程序保存的交易回执。

### 5.3 接入手册内容

每个服务保存一份手册，以 `sources/AGENTS.md` 为索引。服务名称和入口由实际接入决定，不预设外部工具名。

手册按服务实际情况记录：

- 用途、适用市场、支持能力和限制。
- 标的身份、代码查询、行情和历史 K 线的取得方式。
- 时间、时区、单位、复权、分页、缺失值和错误含义。
- 原生命令、MCP 工具及参数的使用方法。
- 交易副作用、订单身份、状态含义和查询核对方法。
- 已验证的调用示例、资料来源、验证时间和实际回执引用。
- 尚未验证的内容及已知缺口。

模板用于提醒模型理解必要事项，不要求所有服务有相同字段，不强制每轮重写手册。

接入手册本身属于工作区保留知识。不再生成一份内容重复的“接入记忆”；其他记忆引用该手册即可。

## 6. 初始化与日常启动

### 6.1 初始化不是独立助手

模型认证等运行前提仍由程序处理，凭据不进入模型对话。

首次创建工作区后，由同一个主助手阅读 `BOOTSTRAP.md`。引导说明目标、可用工具和完成条件，不规定固定问卷、对话轮次或强制回答格式。

模型按情况阅读资料、澄清必要问题、安装或发现服务、提出接入配置、执行获准验证并保存手册。这些是可用动作，不是一条所有用户都必须逐项走完的流程。

初始化未完成时允许接入、文档阅读、验证和必要修复，不进入正常业务工作。不能把首次业务请求当成跳过初始化的理由。

### 6.2 完成条件与分工

完成初始化必须满足：

1. 工作区已经准备好，并保存必要接入知识。
2. 数据服务实际联通。
3. 已查询目标市场的真实行情和历史 K 线，不是仅列出工具或执行帮助命令。
4. 模型已说明验证结果和限制，完成工具核实必要条件与实际调用记录。
5. 用户确认完成。

交易服务可选。接入交易服务时核实连接与获准的查询能力，不通过真实下单验证接入。未接入交易服务不妨碍初始化完成后的研究。

两类服务均支持 CLI 和 MCP。不要把“研究就绪”扩大为支持所有市场、所有周期和全部历史数据。

| 参与者 | 负责 | 不保证 |
| --- | --- | --- |
| 工具 | 记录实际入口、原生调用、时间、回执和执行状态；核实验证记录确实存在且与当前接入对应 | 通用理解任意服务的行情语义 |
| 模型 | 按文档选择查询，理解标的、字段、时间、错误状态和可用性；指出缺口 | 凭一句“已验证”创建真实调用证据 |
| 用户 | 确认接入与初始化结果 | 因完成初始化而自动授予交易许可 |

完成工具接受实际记录的引用，不接受模型自造的成功回执。具体记录结构在实施时确定，不为此引入统一行情解析层。

程序保存完成状态。删除 `BOOTSTRAP.md`、存在配置文件或模型声称完成，都不能独立构成完成条件。

### 6.3 安装与接入变更

安装、接口发现、接入权限和交易执行分别处理，不能合并成一次永久授权。

本地软件缺失时，模型按可信说明提出并实际执行获准安装。远端服务无需盲目安装；已有软件不重复安装。安装回执不能替代当前可用性核实。

临时断线、接口变化或新增能力采取局部修复，不重新初始化整个工作区。已有研究和其他可用来源继续保留。

连接目标或权限变化须重新确认。历史验证不证明当前可用；受影响操作需要重新查阅资料和验证。不要因无关文字变更停止所有服务。

### 6.4 日常启动

程序加载工作区，展示未完成任务和未知交易事项。用户确认后才继续未完成任务。

默认不调用模型检查所有服务，不自动研究、交易或轮询。发现实际任务需要的服务不可用时，再局部修复。

首次引导与日常启动分开；是否存在引导文件不改变任务恢复和交易授权边界。

## 7. 原生服务与最小机器配置

使用方法属于文档。程序只保存连接和操作保障必需的机器信息。

| 类别 | 最小内容 |
| --- | --- |
| 来源连接 | 来源身份、CLI 可执行入口或 MCP 连接入口、必要参数和凭据引用 |
| 操作权限 | 获准操作、角色范围、查询或交易写入的分类 |
| 原生调用 | MCP 的工具和参数；CLI 的实际程序、完整参数及必要输入绑定 |
| 交易要求 | 独立复核、精确确认与最小回执判读约定 |

MCP 使用实际工具描述和原生 schema。CLI 按实际文档调用，不假造 JSON 输入通道。模型可用 Python 或 codemode 整理查询结果，不需要核心代码先统一字段。

交易确认绑定实际执行内容，而不只是“买入某标的”的摘要。CLI 不以模型可变的 shell 字符串代替已确认的精确调用。

不要求所有行情查询建立额外结果 schema。计算库可定义自身确有需要的输入结构，这不等于统一外部行情接口。

配置保存凭据引用，不把凭据值写进提示词、手册或记忆。保存示例与回执时注意敏感信息，不因归档完整性而复制秘密。

接入文档、服务返回文本及工具注解都是待核实材料，不能自行提升权限。

## 8. 基础工具与研究计算

### 8.1 最小工具契约

以下是能力边界，不是已经确定的工具名称或强制一对一模块划分。

| 能力 | 输入与结果 | 必要程序职责 |
| --- | --- | --- |
| 文件与知识 | 路径、资料或记忆引用；返回内容或保存结果 | 正确读写、错误处理、必要的修改冲突处理 |
| 服务接入 | 原生入口、拟议权限、资料引用 | 连接、发现、获准变更和真实调用记录 |
| 原生查询 | 服务、操作、原生参数 | 权限检查、调用、来源与结果记录 |
| 初始化完成 | 当前接入和真实验证记录引用 | 核实必要条件、用户确认、保存完成状态 |
| Python 执行 | 源码、输入或数据引用、项目位置 | 运行、取消、日志和产物保存 |
| 专家委派 | 角色、任务、必要限制和材料引用 | 原任务身份、子 Agent 生命周期、结果关联 |
| 交易准备与执行 | 精确原生操作及其引用 | 复核、确认、发送防重、回执与未知义务 |
| 人工结案 | 未知义务及核对依据 | 用户确认、保存结案事实、不重发 |

普通对话和报告不强制结构化输出。工具参数和程序状态可以使用必要的结构化契约。

### 8.2 Python 与计算库

研究采用普通 Python 执行工具、专业技能和必要计算库。

- 所有工作区共用客户端管理的固定依赖环境，实验分别保存。
- 工具保存源码、输入或可追溯引用、环境信息、日志、结果和状态。
- 运行器提供合理的超时、输出上限和取消；这些不是宿主隔离。
- 失败、超时和取消不能记录为成功实验。
- 模型负责研究设计、查询组合、数据整理、统计方法和解释。
- 必要计算库保留可靠公式、费用计算、指标或成交模拟逻辑。
- 不要求模型每次重新编写全部金融计算，也不把全部研究限制为 `indicators`、`backtest` 两种请求。

回测模型的限制、费用假设和适用市场必须说明。删除投资默认规则不等于删除计算正确性检查。

### 8.3 codemode

codemode 用于组合已暴露工具、并行查询和过滤大结果。不能通过 codemode 暴露另一个未经检查的交易入口。

脚本失败不回滚已发生的工具副作用。记录和恢复以实际调用边界为准，不承诺从 JavaScript 中断语句继续。

含交易、安装或其他副作用的整段脚本不能标记为无条件安全重放。恢复时先读取实际记录，再决定后续动作。

## 9. 受控交易与最小回执判读

### 9.1 执行约束

默认真实交易操作经过独立复核，用户确认单独保留。当前没有批准自动绕过复核的紧急例外。

```text
精确交易方案
  → 独立复核
  → 用户确认
  → 检查参数、权限和来源绑定
  → 可靠保存发送开始
  → 执行一次原生调用
  → 保存回执或未知结果
```

这是交易执行边界，不是研究、分析和普通查询的固定业务流程。

确认后不再追加一次模型复核。修改精确参数、连接目标或批准前提时，原复核与确认不能自动适用于新方案。补充受影响的核验，不默认重做全部研究。

用户拒绝后不自动重复请求同一许可。取消不能撤销已发生的外部副作用。

### 9.2 最小回执约定

仅对交易写入保留确定性判读。模型在接入时依据服务文档提出约定，确认后保存。不得通过真实交易试验猜测含义。

| 实际结果 | 程序处理 |
| --- | --- |
| 有可靠依据证明未发送 | 记录未发送，不宣称远端拒绝 |
| 完整回执明确受理 | 记录受理；不等于成交 |
| 完整回执明确拒绝 | 记录拒绝，不自动重试 |
| 判据冲突、回执不完整、通信中断或无法确定 | 记录未知义务 |

CLI 返回码为零或 MCP 协议成功都不能独立证明交易受理。批量结果不能用一个成功条目代表全部成功。

不为所有服务建立庞大结果 schema。具体判据表示法在实施时核实，必须能表达当前接入服务的可靠原生含义。

缺少可靠判据时不编造成功或失败。模型可以分析回执和查询状态，但不能仅靠自然语言判断自动解除程序阻塞。

### 9.3 未知义务与存储失败

结果不明时，阻止该工作区的新交易写入；查询、分析和研究继续可用。

模型核对外部事实、整理依据，由用户确认结案。结案不授权重发，也不把未知交易记录改写成从未发生。

交易记录保存失败时，不得静默继续新交易。重启后，已保存发送开始但缺少可靠回执的操作按未知处理。不得因换请求、参数或连接而绕过已有未知义务。

该机制防止助手自动重复发送，不承诺在任意外部服务上实现端到端恰好一次成交。

## 10. 任务恢复

任务恢复是已确定要求，不能退化为只恢复聊天记录。

| 中断位置 | 恢复行为 |
| --- | --- |
| 主任务仍未完成 | 展示任务，用户确认后继续原任务 |
| 专家已交付结果 | 复用结果，不重新委派同一工作 |
| 专家尚未完成 | 恢复原专家任务和上下文，不创建重复任务 |
| 工具结果已可靠保存 | 继续使用；实时信息仍需判断时效 |
| 普通 Python 计算中断 | 可从该次计算开头重跑，不承诺内存或中间检查点恢复 |
| codemode 脚本中断 | 检查已发生的工具调用，不盲目重放整个脚本 |
| 交易已经发送或可能发送 | 先核对实际状态，不自动重发 |
| 交易尚未发送 | 重新判断条件；不自动沿用旧执行许可或旧复核结论 |

打开工作区本身不启动业务任务。确认继续任务不是授予新的交易许可。

恢复任务不代表所有底层工具可重放。SDK 的重放分类必须与工具副作用一致。对外部 Python 进程也要区分仍在运行、已完成和已中断，避免未核实就重复启动。

关闭用于保留未完成工作，明确取消用于停止该任务；二者均保留记录和已经发生的副作用。取消后的工作不能被当作待恢复任务自动继续。

## 11. 可信本地助手边界

开放研究所需文件、普通 Python 和 codemode。不新增强隔离系统。

- 正常交易路径统一走受控工具。
- 不主动向研究计算传入交易凭据。
- codemode 中的交易调用同样经过复核和确认检查。
- 普通 Python 具有当前用户的宿主访问能力，可能读取本机文件或调用本地程序。
- 不向模型直接暴露原生交易写入工具，仍不能单独防止本地代码绕过。

因此，系统保证正常工具路径的执行约束，不声称可以对抗任意本地代码。若未来要求不可绕过的交易边界，须另行决定外部服务权限或执行环境方案，不在本次重构中隐式加入。

## 13. 实施顺序与交付物

以下是工程实施顺序，不是未来助手的业务流程。

### 阶段一：核实 SDK 复用边界

核实持久任务、子 Agent、资源加载、codemode 和 MCP 的组合方式。给出单一任务所有者、工具重放分类和最小适配方案。

交付：能力对照表与目标模块图。对缺少直接支持的能力明确说明适配代价，不先搭新框架。

### 阶段二：统一运行入口与资料加载

同一主助手承担首次引导和日常工作。实现角色、技能和接入索引的明确加载。使用新工作区，不改写旧格式。

交付：可交互的统一运行入口；未完成初始化不会进入正常业务。

### 阶段三：原生接入与初始化闭环

实现 CLI/MCP 接入、手册保存、真实查询记录及完成工具。数据服务必需，交易服务可选。后续变更支持局部修复。

交付：可核实的研究就绪工作区，无统一行情适配层。

### 阶段四：研究与专家恢复

接入普通 Python、必要计算库和 codemode。专家交付自然语言报告及产物。验证中断恢复不会重复已完成委派。

交付：真实研究任务与计算产物；明确的工具重放边界。

### 阶段五：受控交易闭环

精简并保留复核、确认、最小回执判读、发送记录、防重和人工结案。交易入口仅在这些保障完整时启用。

交付：确定性逻辑验证与无真实交易的故障恢复检查。不能用真实下单作为验收捷径。

### 阶段六：清理与行为验收

删除已被替代的初始化循环、旧协议、重复状态和默认投资规则。检查是否出现文字版状态机或第二套运行机制。

交付：更新后的当前架构、配置与使用文档；旧数据保留说明；验收记录。

每个阶段先保证边界完整，再删除旧路径。无需兼容旧格式，也不意味着可以在中间版本开放不受控交易。

## 14. 验收场景与验证方式

### 14.1 行为验收

这些场景验证产品行为，不是提示词或文档文字匹配测试。

| 场景 | 预期结果 |
| --- | --- |
| 改变研究方法或交付要求 | 通常只修改技能，不新增业务状态或 TypeScript 分支 |
| 新增数据服务 | 通过 CLI/MCP 配置、验证和手册使用，不写专用行情适配器 |
| 初始化只有帮助输出或工具列表 | 不能视为完成行情和历史 K 线验证 |
| 数据服务可用，未接交易服务 | 用户确认后完成初始化，可开展研究 |
| 数据返回错误或历史 K 线不可用 | 说明缺口，不虚报研究就绪 |
| 初始化尚未完成就提出业务任务 | 继续解决必要接入，不默认跳过初始化 |
| 已初始化后只查询行情 | 直接查询回答，不强制创建项目、专家或交易意图 |
| 复杂研究 | 模型按目标决定委派数量、方法和顺序 |
| 没有用户投资规则 | 能分析和提出方案，说明必要假设，不套旧默认阈值 |
| 用户明确给出限制 | 方案和复核遵守限制，不以模型自主性忽略限制 |
| 专家已完成一部分工作后退出 | 确认恢复后复用已有结果，继续原未完成任务 |
| 日常打开终端 | 显示待恢复任务和未知事项，不自动执行业务 |
| Python 或 codemode 中断 | 不谎报成功，不盲目重复有副作用的调用 |
| 修改交易参数或连接目标 | 旧复核与确认不能直接用于新操作 |
| 用户拒绝交易 | 不自动重复提交同一许可请求 |
| CLI 返回码为零但业务结果不明 | 不能视为受理或成交，保留未知义务 |
| 发送后崩溃且缺少可靠回执 | 恢复为待核对状态，不自动重发 |
| 已有未知义务 | 阻止本工作区新交易写入，允许查询和研究 |
| 用户确认人工结案 | 保存结论、解除相应阻塞，不自动重发 |
| 服务断线或接口变化 | 局部修复，不重走完整初始化 |
| 修改长期技能或角色职责 | 先征求用户确认；权限不随文本自动改变 |

### 14.2 必要自动验证

按仓库规范，只为具体逻辑风险增加测试：

- 精确调用绑定、确认失效、防重复发送和拒绝处理。
- 交易回执分类、未知阻塞和人工结案状态变化。
- 初始化完成工具对真实记录引用、缺失条件和确认结果的处理。
- 任务身份与恢复、专家结果复用、取消和关闭差异。
- 配置解析、原生参数传递、权限检查和存储故障处理。
- Python 计算正确性、产物保存和失败状态。

使用明确输入、真实本地逻辑和必要的真实子进程。不使用 mock、stub、假模型或模拟服务，不使用真实交易或个人凭据。

模型自主行为通过真实模型的受控人工验收观察，不用伪造模型输出来证明。真实服务验证需要用户提供可信来源并授予相应权限；缺少条件时明确记录未验证。

运行 `npm run check`、`npm test`、`git diff --check`。计算相关变更另运行适用的真实 Python 测试。不得增加文件哈希检查或验证提示词措辞的测试。

## 15. 尚待技术核实的事项

以下是实施调查，不是重新打开已经确认的产品决定：

- `pi-durable` 与技能加载、codemode、MCP 的最小适配方式。

- 产品工作区的物理布局、资料更新生效方式和与宿主同名文件的关系。
- 普通 Python 进程与任务关闭、取消、恢复的生命周期衔接。
- 现有计算库的正确性、适用范围和许可；不可直接宣称支持任意市场。
