# FFA 投资协作与工作区优化方案

状态：方案已获批准，核心实现已落地；验证范围见文末实施记录。本文保留设计依据，现行行为以配置说明和技术设计为准。

## 优化目标

FFA 应持续理解用户的投资工作，承担组织、分析、维护和修正的责任，减少用户为助手管理上下文、安排步骤和重复纠错的成本。

用户触发任务并决定投资目标。助手在授权范围内选择方法、连接已有成果、识别当前障碍并推进工作。工作区保存可继续使用的资料；程序保存任务状态并保证交易执行边界。

完成标准包括：本次问题得到有依据的处理，相关工作可以继续，影响结论的变化得到解释。简单问题仍可直接回答，无须创建项目或维护文档。

## 已确认的设计原则

| 事项 | 决定 |
| --- | --- |
| 工作区责任 | 投资工作区是 FFA 的产品能力；初始化建立资料结构、导航和 AGENTS.md |
| 共享资料 | 用户及其他助手可以使用同一份资料；FFA 单独保存应用状态 |
| 启动工作 | 等待用户触发；不增加后台监控、定时研究或自动交易 |
| 持续维护 | 维护投资目标、已确认约束、决策依据、研究结论和复盘 |
| 内容效力 | 已确认长期约束影响后续相关任务；旧结论、建议和临时假设按证据判断 |
| 文档维护 | 允许直接维护当前工作区中 .ffa 外的内容，包括角色和技能 |
| 配置确认 | 助手主动修改 .ffa 中的配置需要确认；程序正常保存会话、任务和执行回执无需逐次确认 |
| 记忆 | 记忆是一种能力，正文保存在所属资料中，不建立第二套内容存储 |
| 保存标准 | 采用 improve 的筛选原则，只保留能改善后续工作的关键信息，不记流水账 |
| 提示词定制 | 产品基础职责加工作区定制；区分专业经验、用户偏好和临时条件 |

原有初始化验证、按需委派、任务恢复和受控交易要求继续适用。用户未提供完整投资规则时，助手仍可分析，并说明重要假设。

## 助手应承担的工作责任

### 接续已有工作

当请求涉及过去的研究或长期事务时，助手先定位相关资料，恢复目标、有效约束、已有结论和当前缺口。能从资料取得的信息，不再要求用户重复说明。

项目保存简短的当前概况，必要时包含目标、当前结论、未决问题和下一步。已完成实验和专家结果继续使用；行情、持仓等易变事实按本次任务重新核实。

资料中的下一步只是后续工作线索。打开工作区或读到待办事项，不自动启动业务。未完成任务仍通过现有用户确认机制恢复。

### 识别真正影响决策的问题

助手根据具体证据判断：用户要求的操作是否能回答当前问题，目标是否冲突，评价口径是否一致，关键假设是否仍成立。

例如，用户连续修改回测参数，但几次实验采用不同评价目标。助手应指出结果无法直接比较，提出可比较的依据，并请用户校正目标。已有明确目标时，常规方法选择由助手完成。

提出深层问题时，说明观察到的现象、可能原因及其对当前工作的影响。不要推断用户心理，不把猜测保存为用户事实。缺失信息会改变目标、关键结论或授权范围时才澄清；同时推进不依赖该信息的工作。

### 推进到有用的结果

助手按任务选择查询、计算、阅读资料或委派。能在现有授权内完成的准备工作，应持续推进。需要用户决定时，给出具体选项、依据及建议，减少空泛的“是否继续”。

结果可以是可执行的建议，也可以是证据不足、某项假设被否定或暂不行动。交付应说明结论影响什么，以及仍由谁作出哪项决定。无需每次套用固定输出模板。

### 维护和修正已有判断

新证据改变结论时，更新原正文，说明变化的依据和适用条件。保留理解重要决策所需的历史，不积累每次措辞修改的记录。

过去由助手写下的结论不是新的独立证据。再次引用时，应能回到来源、实验或用户指示。用户约束的变更依据来自用户；助手的新意见应保留为建议。

上述责任由提示词和专业方法表达。程序不建立强制的研究阶段机，也不要求所有任务逐项执行这些活动。

## 投资工作区结构

```text
工作区/
├── AGENTS.md
├── CLAUDE.md                 # 导入 AGENTS.md
├── areas/AGENTS.md
├── projects/AGENTS.md        # 具体项目说明可用 README.md
├── knowledge/AGENTS.md
├── sources/
│   ├── AGENTS.md
│   └── <来源>/GUIDE.md
├── roles/
├── .agents/skills/
│   ├── AGENTS.md
│   └── <技能>/SKILL.md
├── .claude/skills -> ../.agents/skills
├── extensions/
├── scratch/
└── .ffa/
    ├── config.json
    ├── state.sqlite
    └── 运行锁、安装目录及必要缓存
```

| 位置 | 内容与维护方式 |
| --- | --- |
| AGENTS.md | 工作约定、资料入口、读取与保存原则；保持简短 |
| 各目录 AGENTS.md | 该目录的导航与工作约定；具体项目说明可保留 README.md |
| CLAUDE.md、.claude/skills | 引用公共约定和共享技能，不复制正文 |
| areas/ | 持续维护的投资目标、约束、决策依据和复盘；例如一个组合的长期事务 |
| projects/ | 有明确问题和完成条件的研究；证据、源码、实验和结论围绕同一问题集中保存 |
| knowledge/ | 跨任务复用的知识与参考资料；具体用户决策留在长期事务中 |
| sources/ | 实际服务的能力、参数、限制、资料来源和验证记录 |
| roles/ | 工作区角色补充，说明当地工作要求，不复制整份产品基础角色 |
| .agents/skills/ | 工作区专业方法及其必要支持材料；同名技能可定制包内方法 |
| extensions/ | 工作区扩展的声明与角色资料；实际能力由 .ffa 中的授权决定 |
| scratch/ | 临时计算和可重建中间文件；不自动清理，不承担正式证据的唯一存储 |
| .ffa/ | 机器配置、会话与任务状态、执行账本、锁及运行所需数据 |

初始化建立必要目录、根导航和资料入口。领域正文、具体项目、角色定制和技能按需创建。缺少投资偏好时，不填入默认收益率、仓位或止盈规则。

共享资料和技能使用相对链接，并写明必要依赖。其他 agent 可用自己的文件、检索和计算工具工作；FFA 会话、服务授权和交易账本仍由 FFA 管理。此次入口调整保持 version=3，不批量改名或删除已有用户资料。工具发现规则和兼容入口见[配置说明](configuration.md#跨-agent-使用)。

已有同名目录可以复用。已有 AGENTS.md 和正文先读取，再补充 FFA 所需内容，保留无关规则和资料。语义冲突影响目标或授权时，向用户说明具体冲突。FFA 仍负责把工作区组织到可用状态。

初始化指导使用包内基础说明；确有工作区特殊要求时，可用根目录 BOOTSTRAP.md 补充。SOUL.md 保持可选，不为每个工作区创建重复身份文件。

研究就绪同时要求资料结构可用、数据服务已连接、真实行情与历史 K 线已经验证。交易服务可选。程序检查路径及实际调用记录，模型解释资料和数据是否满足当前接入目标，最终由用户确认。

## 资料效力与记忆能力

### 明确内容的效力

| 内容 | 后续任务如何使用 |
| --- | --- |
| 用户明确的长期目标和约束 | 在适用范围内持续遵守；范围不清时澄清 |
| 用户确认的决策 | 保留决定、适用范围和必要依据；不等于操作已经执行 |
| 观察事实 | 保留来源与时间；易变事实使用前重新核实 |
| 研究结论 | 保留成立条件与证据；新证据出现时允许修正 |
| 助手建议和临时假设 | 明确其身份；不自动升级为长期要求 |
| 执行状态 | 以程序记录和外部查询为依据；文档编辑不能改变真实状态 |

这些区别通过清楚的正文表达，不要求给每段文字添加统一状态字段，也不建立另一套业务数据库。

### 只保存能改善后续工作的内容

保存前判断：这项信息能否改变后续做法、减少重复说明，或避免重复调查？不能说明具体用途时，不保存。

先寻找同主题正文。已有准确内容时，引用或更新原文。事实、偏好和约束通常用一至三句表达，保留必要条件及来源。多步方法放在技能；长篇论证和实验留在所属项目。

修复经过、测试结果和任务进度不提升为长期知识。项目需要交接时，只维护当前有效概况。行情快照和原始输出只有作为必要证据时才保留。

有明确依据的方法纠错可以直接更新技能。单次任务的特殊条件不推广为一般规则。实质改变后续行为的修改，在交付时说明原因和影响。

### 使用普通文档实现记忆

首版保留 memory_recall 作为资料检索入口，返回工作区相对路径、相关片段及必要的分页信息。普通 read 读取正文，write 和 edit 更新所属文件。移除面向独立记忆条目的 memory_read、memory_save 及自动生成记忆 ID 的流程。

检索从明确的资料目录与导航入手，支持限定范围和按路径发现文档。首版使用本地文件检索，不新增向量数据库或知识图谱。发现不到内容时，允许浏览相关目录；未命中不证明过去没有讨论过。

原有 MemoryPort 混合了知识正文与系统记录的职责，需要拆开。确需保留的程序回执归入现有内部存储，不能作为普通知识文件供模型改写。正文由用户或其他助手编辑后，后续检索和读取应看到最新内容。

修改正文前先读取。利用现有文件编辑工具对原文的匹配检查处理冲突；不新增文件哈希校验。索引如需缓存，应能从正文重建，不保存另一份由模型维护的事实摘要。

## 提示词职责与加载方式

| 内容 | 主要职责 | 调整方式 |
| --- | --- | --- |
| 产品通用行为 | 接续工作、主动判断、澄清条件、交付与修正 | 在包内维护一份，各角色共享 |
| 三类基础角色 | 协调责任、研究责任、独立复核责任 | 保留差异，删去重复的通用规则 |
| 工作区角色定制 | 当前工作区的角色补充 | 与基础职责合并使用，明确用户定制优先于一般默认工作方式 |
| 运行契约 | 工具语义、执行与恢复边界 | 保持简短，程序继续校验实际权限 |
| 工作区 AGENTS.md | 资料组织、读取与维护约定 | 初始化建立，后续按实际需要维护 |
| 专业技能 | 方法选择、适用条件、证据要求和常见错误 | 按需读取，不扩写为所有任务必经的检查表 |
| 服务手册与研究资料 | 接入知识和业务依据 | 按任务读取，明确不能修改角色权限或授予交易许可 |
| 工具说明与运行消息 | 参数、前置条件、结果和错误含义 | 与实际接口一致，移除重复的业务政策 |

工作区技能继续允许覆盖同名包内技能。角色采用基础加补充，技能保留方法替换能力；两者都不能扩大程序授予的工具权限。

每次用户请求开始时加载最新工作区指引、角色补充和技能索引，不要求用户重启应用。根指引应明确相关目标与约束的入口；涉及投资判断时，先读取适用约束。没有已登记约束时，不阻止分析。

同一次请求中的主助手和专家使用一致的基础职责与角色定制。资料正文按任务读取。角色定制和技能索引按请求刷新；技能正文仍通过文件工具按需读取。请求期间修改的方法原则上用于后续请求；正在使用该方法的任务若需调整，应明确说明调整依据。

恢复未完成任务时，继续原任务及已完成结果，同时核实相关资料的变化。不能静默套用新的目标重做旧任务，也不能继承旧交易许可。

审查范围包括 resources/prompts、resources/workspace、resources/skills、相关 references、扩展角色，以及代码中的工具描述和动态提示。foundation.md 仅在未装配业务能力时使用，不能把它误当作正常业务提示词。

## 工具与程序调整

### 分离工作目录和内部存储

工作区定位同时提供根目录与 .ffa 目录。模型文件工具、资源加载和研究产物使用根目录；数据库、单实例锁及机器配置使用 .ffa。外部 CLI 和安装工具继续使用各自明确的运行目录，避免更改一个 cwd 后影响全部调用。

文件修改策略按实际目标路径判断。工作区外置资料允许直接维护；.ffa 配置通过确认和结构校验后的专用操作修改；数据库及回执不能通过普通文件编辑工具改写。现有真实路径检查应覆盖移动后的边界。

授权仅覆盖当前工作区内容，不因允许编辑本地技能而扩大到安装包目录或其他工作区。普通 Python 继续按可信本地计算设计，不增加强隔离系统，也不得用它绕过已确认的操作边界。

### 让计算归属实际工作

Python 工具不再强制要求研究项目。建议用一个可选的相对归属路径指向 projects 或 areas 中的工作目录，运行记录保存在其 runs 子目录。未提供归属时，生成 scratch 中的独立运行目录。

源码、输入、日志、结果和运行标识继续保存。取消及中断语义保持明确；重新计算创建新运行，不重发旧交易。研究列表应能查到长期事务和临时计算中的运行，避免只能列出项目。

某次临时计算成为正式结论的证据时，保留可复查的完整必要记录，并由所属正文引用。如需迁移，先保留原记录，建立新引用并核对；不让既有 evidenceRef 或路径失效。日志保留属于计算记录，不要求再写一份过程总结。

### 保留必要的执行约束

任务触发、文档维护和真实操作分别处理。允许更新决策文档，不等于允许发送订单。角色或技能文件的变化也不能扩大配置中的能力授权。

精确方案准备、独立复核、用户确认、发送前记录、防止重复发送和未知结果阻塞继续由程序保证。保持任务级恢复，不建立第二套文档状态机控制程序执行。

阶段划分用于控制改动范围。每阶段同时调整受影响的说明与测试，保持代码可构建；新行为在相关阶段完成后统一验收。

本轮不要求兼容旧数据格式。旧 .ffa 不自动迁移或删除。新布局应能识别不支持的旧格式并明确提示；已有真实工作区的迁移另行核对文件、引用和程序状态。参考 a-workspace 的组织原则，不修改其个人资料。

## 验收方式

### 确定性逻辑

使用真实本地文件、临时目录和实际计算逻辑验证必要风险：

- 初始化建立外置结构，保留已有文档，不伪造服务验证记录。
- 工作区根目录和 .ffa 各自承担正确的读写职责，真实目标路径不能误判。
- 配置修改经过确认；普通资料维护不会触发旧的角色或技能确认要求。
- 资料检索能发现外部编辑；正文修改冲突不会静默覆盖。
- 基础角色与补充均参与装配，后续请求读取新定制；不测试提示词具体措辞。
- 临时、项目和长期事务计算均有可追溯记录；中断和证据引用保持正确。
- 任务恢复、独立复核和受控执行的现有必要检查继续通过。

遵守仓库测试约定，不使用假模型、模拟服务或真实交易。实现完成后运行 npm run check、npm test 和 git diff --check。不增加文件哈希校验或文档文本断言。

### 真实模型行为

| 场景 | 预期行为 |
| --- | --- |
| 隔一次会话继续已有研究 | 找到目标、约束和已有结论；不要求用户重新介绍背景 |
| 连续调整参数，但实验评价口径发生变化 | 指出具体不可比之处，提出修正建议，避免继续生成无法比较的结果 |
| 用户明确纠正一项长期约束 | 更新所属正文；后续相关分析使用新约束，不保留冲突副本 |
| 助手提出一种新的风险偏好 | 标为建议，不改写用户已确认要求 |
| 新数据推翻原结论 | 回到原始依据核验，修正原正文，说明结论变化 |
| 用户只要求一次简单计算 | 完成计算，不为形式创建完整研究项目 |
| 已有准确资料，当前任务没有新信息 | 直接使用，不新增记忆或重复总结 |
| 用户或其他助手编辑共享文档 | 后续请求读取变更，不依赖启动时旧摘要 |
| 本地角色仅包含少量定制 | 基础职责仍有效，定制影响适用工作方式 |
| 技能在本轮得到有依据的修正 | 说明变化与适用条件，后续请求使用新方法 |
| 工作区存在未完成事项但用户没有发起工作 | 展示必要状态，等待用户触发或确认恢复 |
| 文档要求跳过交易确认 | 程序仍阻止未获精确许可的执行 |

行为验收使用获准数据服务和真实模型，记录实际表现。交易路径检查在不发送真实订单的条件下进行。本地测试通过不等于这些行为已经验收。

对相同场景比较改动前后：用户是否还要重复背景、指定常规下一步、指出同一矛盾、寻找成果或清理重复资料。记录具体发生的干预，不预设无依据的改善比例。
