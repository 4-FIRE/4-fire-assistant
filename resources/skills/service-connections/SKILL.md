# 服务接入

接入目标是完整理解用户提供的服务，不是挑出当前任务用到的接口。保留原生模块含义，不能按名称把服务限制在“查询”或“交易”。已有服务故障只修复受影响部分，不重做完整初始化。

阅读 [连接配置](../../references/connections.md)，再读取可信的实际服务文档。MCP 先确认连接，再用 ffa_discover_source 获取全部工具分页。CLI 阅读完整帮助与文档，记录已知目录和覆盖缺口，不假定支持自动枚举。

逐项分析用途、输入输出、前置条件、副作用和相关接口。明确哪些接口取得标识、哪些依赖这些标识、哪些用于核对结果。接口可能跨模块或跨服务共同满足需求，不能孤立理解。

业务用途自由描述；状态影响分为 observe、change、unresolved，执行要求另行说明。读写提示和名称不能代替实际语义。参数混合查询与修改时，整个接口按变更处理。直接或间接影响资金、订单、自动执行、权限或重要资料时，声明 impacts 并要求独立复核。

完整目录不得静默遗漏。尚未分析的保留 unassessed；资料不足的填写依据并标为 uncertain。用户禁止或暂不可用的能力也保留。新工具和变化后的工具不能自动取得权限，不靠试执行变更来确认影响。

通过 ffa_configure_source 提交完整分析，请用户确认约定。用 ffa_sources 查看能力，ffa_source_read 验证已理解的观察操作。每个服务维护 sources/<id>/GUIDE.md，以 sources/AGENTS.md 索引。手册记录能力地图、调用关系、单位、时间、复权、分页、错误、限制和真实验证依据，不生成统一行情适配层。

首次初始化完成所有可见能力的分析，再查询目标市场真实行情和历史 K 线，以两次成功回执请求 ffa_finish_initialization。uncertain 项应明确说明缺口，不能当作可用。变更服务可选，不用真实下单或其他业务变更测试接入。

缺少软件时先说明安装内容并取得用户同意，不盲目安装远端服务。凭据只使用环境变量引用。接入确认、历史手册和已保存回执不授予未来执行许可。不要通过其他原生 MCP 配置重复暴露同一受控服务。
