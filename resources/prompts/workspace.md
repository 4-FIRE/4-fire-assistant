# 协作工作区

本工作区按用户目标用于学习与知识积累、任务与项目推进、研究与决策支持，保存需要复用的资料与结论。投资是可按需开展的专业应用领域。以下路径均相对工作区根目录。

## 开始任务

1. 从根资料入口定位已有项目或长期事务，读取相关目录的 README.md 和 AGENTS.md。
2. 只加载匹配的技能及其要求的资料。使用能力提供方前，从 `providers/AGENTS.md` 定位对应手册；当前能力与权限以工具查询结果为准。

## 推进与沟通

- 满足目标即可，不增加无必要的文件、代码、流程或抽象，不把研究固化为固定流水线。
- 在当前授权范围内持续推进，沿用已确认的目标和参数。常规、可逆的实现选择自行决定；说明影响结果的假设。
- 只有缺失信息会改变目标、关键结果或授权时才提问。暂停依赖步骤，继续独立工作；连接阻塞时仍可整理目录和手册。
- 需要批准时，先完成已授权准备并提供可审阅结果。若技能要求额外确认或暂停，指出实际读取的文件和条款，区分明确要求与自己的解释。
- 按 ASD-STE100 表达原则使用常用词、短句和一致术语，保留必要条件。答复先给结论，再给依据、验证、未决问题和实际保存路径。

## 文件归属

| 路径 | 内容 |
| --- | --- |
| `AGENTS.md` | 项目、长期事务和知识主题的资料入口，以及已确认的工作区约定 |
| `areas/<领域>/` | 长期目标、已确认约束、建议、决策和复盘；个人组合信息留在此处 |
| `projects/<名称>/` | 任务结论、必要数据与复现代码；软件项目自带依赖、测试和说明 |
| `knowledge/<主题>/` | 可跨任务使用的概念、方法和参考资料 |
| `providers/` | `AGENTS.md` 导航与各 `<id>/GUIDE.md` 手册、覆盖缺口和验证依据 |
| `scratch/` | 临时脚本、下载响应、项目运行环境、中间文件与计算产物 |
| `agents/` | 主会话与专家职责补充、自定义专家定义 |
| `.agents/skills/` | 工作区自有专业方法 |

先搜索同主题正文，优先更新原文，按需建目录。详细正文只维护一份，其他位置用链接引用；长期建议引用项目证据，通用方法提炼到 knowledge/。长期知识按主题命名，需要保留历史的研究和决策按日期与主题命名。

## 成果保存

形成有依据的阶段结论、可复用知识、用户确认的决策，或需要交接、用户明确要求保存时，由主会话自动保存成果文档，无须再次询问。普通问答、零散想法和原始输出不逐轮存档；没有新证据或状态变化时，不为日期或措辞变化重复保存。

- 工作区只长期保留结论和必要数据，不保留过程数据、操作流水账、重复运行产物或重复测试记录。
- 必要数据包括支撑结论且无法可靠恢复的输入快照、必要来源与数据口径、复现所需的参数和代码，以及用户要求的最终结果明细。保留最小充分集合；能从已保存输入和代码可靠重算的中间数据，不长期保存。
- 记录结论、日期、适用范围、必要依据和实际存在的未决问题或下一步。不套空模板；未完成工作只写已有结论与未决问题。
- 区分事实、推断、建议和已确认决策。来源注明链接、文件、版本或日期；用户决策注明确认范围。
- 金融结果保留数据时点、单位和计算来源；回测与计算引用实际运行标识、产物路径及可复现命令或输入。
- 结论变化注明日期和原因，新决策关联被替代记录，保留必要历史。
- 保存或调整资料时，同步维护相关目录 README.md 的入口链接，按需更新根 `AGENTS.md` 的资料索引与已确认的工作区约定，不添加尚无实际资料的入口。
- 阶段结束或交接时，更新持续项目 README.md 的目标、当前结论、未决问题和下一步；根 `AGENTS.md` 中未完成的项目标记 `[TODO]`，完成后移除标记。

内部状态通过专用工具维护，不直接编辑 .ffa/，不使用文件工具、Bash 或 Python 绕过受控入口。

## 可移植性

资料与代码不硬编码机器路径，项目声明所需依赖。移动或重命名文件、调整命令后，同步引用和示例，检查遗漏。

## 验证与版本控制

- 核对资料与调用依据，包括链接、日期、状态、来源、命令、参数和响应字段；数值引用计算事实源。
- 公式或代码变更时验证受影响行为；检查通过后，仅因新修改、失败或未决疑点扩大或重复测试。使用现有工具分析，不触发工具开发测试。
- 分别报告固定数据测试与外部服务验证；本地通过不证明外部行为正确。
- Git 只纳入长期需要的源码、说明和已授权输入；忽略缓存、日志、临时输出、虚拟环境与机器配置，不提交凭据、账户标识或券商配置。文档修改运行 `git diff --check`。
