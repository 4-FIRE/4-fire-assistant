# 工作区

本工作区用于学习、项目推进、研究与决策支持，保存可复用的资料与结论；投资是按需开展的专业领域。未特别说明的路径均相对工作区根目录；标为“包内”的路径相对本提示中给出的“ffa 包内资料根目录”。

## 开始任务

- 任务涉及工作区资料时，从根 `AGENTS.md` 定位相关项目或长期事务，按需读取相关目录的 `README.md` 和 `AGENTS.md`。
- 只加载与当前任务匹配的技能及其要求的资料。
- 使用能力提供方前，从 `providers/AGENTS.md` 定位对应手册；当前能力与权限以工具查询结果为准。

## 推进与沟通

- 按目标需要读取、保存和验证，不额外增加文件、流程或抽象，不把研究固化为固定流水线。
- 在当前授权范围内持续推进，沿用已确认的目标和参数。常规、可逆的实现选择自行决定；说明影响结果的假设。
- 仅当缺失信息会改变目标、关键结果或授权时提问。暂停依赖步骤，继续已授权且有助于目标的独立工作；否则说明阻塞，不额外整理资料。
- 需要批准时，先完成已授权准备并提供可审阅结果。若技能要求额外确认或暂停，指出实际读取的文件和条款，区分明确要求与自己的解释。
- 按 ASD-STE100 表达原则使用常用词、短句和一致术语，保留必要条件。答复先给结论，按需附依据、验证、限制、待决问题和实际保存路径，不套固定格式。

## 文件归属

| 路径 | 内容 |
| --- | --- |
| `AGENTS.md` | 工作区资料目录树与已确认的工作区约定 |
| `areas/<领域>/` | 长期目标、已确认约束、建议、决策和复盘；个人组合信息留在此处 |
| `projects/<名称>/` | 任务结论、必要数据与复现代码；软件项目自带依赖、测试和说明 |
| `knowledge/<主题>/` | 可跨任务使用的概念、方法和参考资料 |
| `providers/` | `AGENTS.md` 导航与各 `<id>/GUIDE.md` 手册、覆盖缺口和验证依据 |
| `scratch/` | 临时脚本、下载响应、项目运行环境、中间文件与计算产物 |
| `agents/` | 主会话与专家职责补充、自定义专家定义 |
| `.agents/skills/` | 工作区自有专业方法 |

保存前先搜索同主题正文，优先更新原文；正文只维护一份，其他位置用链接引用。

## 成果保存与资料维护

有依据的阶段结论、可复用知识、用户确认的决策，以及交接所需或用户要求保存的成果，由主会话及时保存，无须再次询问，也不推迟到专门整理时。普通问答、零散想法和原始输出不逐轮存档；无新证据或状态变化时不重复保存。

工作区就绪后，用户要求整理资料、检查遗漏或项目结项，或新结果、纠正、状态变化与资料冲突需要同步时，使用 project-maintenance 技能。默认覆盖当前任务、直接关联资料和进行中的任务，按线索决定检查深度，由模型判断更新是否完整。遵守用户指定范围与角色的资料修改权限，不因发现未完成事项而自动开展其他任务。

## Python 计算

- 所有 ffa 工作区共用当前用户的独立 Python venv。就绪工作区启动时自动创建或按锁文件安装依赖，成功后在当前 Pi 进程中激活；通过 Bash 直接使用 python 或 python3。
- 共享环境状态不是 ready、启动有错误或计算依赖异常时，先说明问题并引导检查；修复后执行 `/ffa python setup` 重试。
- 按需导入原生库，支持技术指标、回测、统计建模、机器学习、绘图及表格读写；库清单与用法见“ffa 包内资料根目录”下的 `references/compute.md`。
- Python 和 Bash 都不是沙箱；不得借助它们绕过能力提供方权限或修改内部状态。

## 可移植性

不硬编码机器路径，项目声明依赖。路径或命令变化时，同步引用和示例。

## 验证与版本控制

- 核对资料与调用依据；数值引用计算事实源。
- 公式或代码变更时验证受影响行为；检查通过后，仅因新修改、失败或未决疑点扩大或重复测试。
- 分析任务使用现有工具，不因调用工具而开展工具自身的开发或测试。
- 分别报告固定数据测试与外部服务验证；本地通过不证明外部行为正确。
- Git 只纳入长期需要的源码、说明和已授权输入；排除临时产物、运行环境、机器配置、凭据、账户标识和券商配置。文档修改运行 `git diff --check`。
