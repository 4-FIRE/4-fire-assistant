
# 期权策略分析

产出可比较、有规则依据的期权方案，供用户判断或主 agent 交给独立复核。此流程只分析，不执行交易或再委派 agent；用户当前的分析范围优先。

## 策略依据

从用户目标和已确认资料确定适用策略与规则，从当前角色目录选择查询核对持仓。若来源提供远端策略或规则查询，再按任务需要读取；不假设存在固定的策略服务。读取 [规则与回退](../../references/strategy-rules.md) 以区分明确规则、助手默认、不适用及无法核验；解释持仓/订单或形成执行方案前核实当前工具描述、schema 与返回字段含义，计算或验证数值时读取 [计算口径](../../references/calculations.md)。

策略已经明确且主 agent 提供了仍适用的持仓快照时可复用，缺失或过期才补查。按当前返回结构读取完整规则；规则缺失时交付事实和缺口，不能输出“符合规则”的执行建议。

使用已核实范围与数量含义的当前剩余头寸，并核对数据完整性、警告和时间；与订单明细中的同一成交不重复计数。开仓核实适用的覆盖或担保证据，可卖张数不代表现金充足。相关订单剩余量或资金无法核验时说明具体缺口，不因此停止仍可完成的候选分析。

对 Wheel/CC，结合规则及实际持股数判断阶段：无股通常分析现金担保 PUT，持股通常分析 Covered Call；已有未平仓期权也必须计入覆盖数量、资金和 Delta。核实成本字段的实际含义，不能把现价或缺省值当作买入成本。其他策略以其规则为准，不强套 Wheel 阶段。

## 技术输入与候选查询

使用主 agent 传入的技术报告支持行权价选择，保留关键价位与时间。缺技术报告时可选择当前目录中适用的行情查询取得现价，继续能够完成的持仓、规则和期权分析并标明缺口；只有依赖缺失技术信号的结论不可下定论，不因此终止整个分析。

从当前目录选择期权查询，获取有效到期日及规则 DTE 区间内适合持仓阶段的期权链。查询范围随问题确定：指定合约就聚焦该合约，比较机会时选择有代表性的到期日和行权价。可行时覆盖周/月期权，不为凑数量强行越过 DTE 约束。没有合适候选时报告筛选范围和淘汰原因；区间外合约只能作为明确标注的比较资料。

按规则检查 Delta、收益、评分、流动性、价差、行权价、财报及风险档位等适用条件；链查询已有适用 VIX/Skew 时复用，不只依赖综合风险等级。按包内公式自行计算交易前后组合 Delta、收益和止盈参数，先统一服务字段与本地公式口径；保留计算输入与单位，便于独立复核。

## 交付标准

报告应让读者能判断候选为何适合或被排除，详略随任务调整：

- 策略、持仓阶段、现有订单与止盈单、行情时间，以及适用规则和默认值。
- 候选合约的实际代码、到期日、行权价、方向、数量、Bid/Ask、Delta、IV、流动性、收益及评分；仅列实际取得且与比较相关的数据。
- 推荐或不操作的理由、交易前后敞口、各项合规结果、依赖的技术结论及数据缺口。
- 若准备交给复核，提供可定位的策略/合约/订单 ID、市场、价格、数量和退出方案，同时保留用户限制与授权范围。合约代码沿用工具返回值，不手工拼接。分别说明策略合规、证据缺口与接口能否准确执行；接口不支持的退出方案也可交付分析，但不包装成可执行指令。

已有止盈单时展示新方案如何影响它，按共享规则标注执行前所需的具体确认。分析完成即交付；可行方案是否执行由主 agent 根据用户授权及独立复核结果决定。
