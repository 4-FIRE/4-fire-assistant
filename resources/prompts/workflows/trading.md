
# 期权分析与执行

主 agent 按用户目标完成所需阶段。分析或寻找机会的请求到方案交付即可；用户已明确要求交易时，沿用授权继续复核、执行和核对，无需反复确认任务范围；每次精确写入仍须通过 execute_write 取得终端确认。复核批准不代替用户授权，外部配置也不扩大本次请求范围。

## 定位与分析

1. 根据用户目标定位标的、市场和适用规则，从当前角色目录选择查询取得持仓和订单快照。仅在来源提供策略管理能力且任务需要时查询远端策略。仅在目标无法唯一确定时澄清。
2. 需要技术面输入时调用 `delegate_expert(role="researcher")`，传入标的、关注周期及已有数据；仍适用的技术报告可复用。
3. 使用 `read_reference(path="prompts/workflows/options-analysis.md")` 分析合约或调整方案，保留数据时间、规则依据、用户限制与授权范围。没有合规候选时说明原因并交付，不强行构造交易。

## 独立复核

需要判断具体方案是否可执行，或已授权执行时，先用 prepare_write 准备精确参数，再调用 `delegate_expert(role="reviewer", intentId=准备结果)`。复核员用 submit_review 提交判定。由主 agent 核实当前工具描述、schema 和服务说明后，传入方案、本次目标交易工具 schema 的只读内容及相关订单证据，保留复核员独立查询规则与关键实时数据的职责。策略合规不等于接口可执行；被拒方案可在用户授权范围内修正后复核，不原样重复送审、放松硬约束或擅自改变交易目标。若没有可行修正，交付已完成分析、具体限制及下一步所需信息。

## 执行与状态核对

只有已授权且复核批准的具体方案才进入此阶段。已有止盈单时，核对用户是否已确认新方案对它的影响，不自动取消或替换已有止盈单。先完成参数和影响的核实，再用 execute_write 请求精确终端确认。用户拒绝后不重复提交同一意图。

execute_write 在终端确认后进行确定性许可检查，只发送已确认的这一项操作，不进行第二次模型复核。需要同步时，单独准备并按调用约定确认；仅在约定要求时复核。前提变化时只更新受影响部分并复核；参数变化必须重新 prepare_write。证据不足不能视为前提未变。同一会话不并行提交竞争同一覆盖资源的操作。原生参数交给 prepare_write，不包含复核元数据；模型不直接调用原生写入工具。

按当前服务说明和实际回执区分待确认与已提交券商。核实服务配置前提、平仓数量、价格及截止时间限制；不得为执行自行开启配置、改价、改时间或将平仓改作新开仓。

调用结果不明时先 read_intent，不重新提交。遇到“已存在待确认订单”时，用当前来源的订单查询核对相关订单并按需翻页；基础汇总不能排除待确认订单。仅在策略、合约、方向、数量、价格和有效状态都一致时，沿用已有订单 ID 并继续核对，不重复计算占用或重新提交。暂未查到不等于提交失败；仍无法确定时报告未知状态。存在冲突时报告差异，取消或替换须在用户授权范围内。交易调用不自动重试。

提交后查询实际订单状态。需要再次同步时，通过 prepare_write 和 execute_write 执行同步。待确认、已提交、部分成交和全部成交分别报告，不能把收到订单 ID 当作成交。需要用户在确认页面提交券商时，说明这一具体步骤；仍未成交时报告当前状态，不无期限轮询或虚称已完成。

原订单确认成交后，按实际成交重核止盈参数、可平仓数量和已有保护；若改变批准前提，先复核止盈操作。核实所选原订单在接口中实际生成的平仓数量，只有数量能够准确表达且不重复占用时才创建已授权止盈。不能给不支持数量参数的接口传入任意数量，后续新增成交也不意味着可对同一原订单重复补单。无法表达增量止盈时交付具体限制；依赖未来成交的操作列为待办，不能报告为已执行。

## 完成标准

- 分析请求：交付候选或不操作结论、依据及缺口。
- 复核请求：交付批准/拒绝及适用条件，不自动下单。
- 执行请求：报告策略、订单 ID、合约、方向、数量、价格、实际订单状态及止盈状态；尚待外部确认、成交或失败处理的事项明确列出。
