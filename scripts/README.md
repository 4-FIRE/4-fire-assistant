# 维护脚本

ffa 插件只支持当前工作区格式，不加载或调用本目录的升级脚本。插件安装和更新仍由 Pi 包管理或用户维护的源码目录负责。

## Python 环境准备

`setup-python.py` 是当前计算依赖的准备脚本，不是工作区格式升级。就绪工作区启动时自动调用，用户也可独立执行或通过 `/ffa python setup` 重试。它创建当前用户的共享 venv 并按 requirements.lock 安装依赖，不接受解释器路径，不修改工作区设置、业务资料或交易记录。路径、自动激活与失败处理见 [Python 说明](../python/README.md)。

## 0.3.0 基线

`upgrade-0.3.0.mjs` 是空的基线参考，无需参数。可从任意目录运行：

```bash
node /绝对路径/4-fire-assistant/scripts/upgrade-0.3.0.mjs
```

脚本只报告不执行升级，不读取、创建、修改或删除工作区文件，不需要 Pi 或包依赖。本版无需运行。

0.3.x 共用 `ffa/0.3` JSON 工作区，不支持旧 SQLite 或旧文件工作区，也不提供到基线的转换。不要修改旧格式标识、删除旧状态或在原目录重新初始化。旧数据继续保留，查询时使用匹配的旧版插件；新工作区在独立目录初始化。

## 后续迭代

同一兼容线保持同一持久化契约，不因补丁发布增加升级脚本。需要改造数据时切换兼容线，再提供独立转换脚本；兼容线规则见[技术设计](../docs/technical-design.md#31-加载范围与格式)。

转换脚本命名为 `upgrade-<源基线版本>-to-<目标基线版本>.mjs`，例如 `upgrade-0.3.0-to-0.4.0.mjs`。适用性检查以工作区 format 为准；文件名中的基线版本不是要求源工作区停留在某个补丁版。已发布脚本保留固定的源、目标和用途，不随当前插件版本重新解释。本目录目前只有无源版本的 0.3.0 空基线，没有实际转换脚本。

不建立通用升级平台，不把旧格式读取放回 `src/`。

每个实际升级脚本需明确：

- 支持的源与目标、工作区路径参数、变更范围和运行方式。
- 若更新 Python 依赖，单独声明共享环境依赖的目标版本、影响范围与恢复方法；停止所有使用该环境的计算，不仅是当前工作区。不得因恢复旧插件而静默降级依赖。
- 执行前要求工作区停止，并在改写前取得同一工作区的排他所有权。
- 先只读检查，再保存不可覆盖的备份；不得删除历史记录、用户资料或已有备份。
- 逐步验证真实文件与关联；全部完成后才提交目标格式，不能仅更改标识。
- 失败时保留已完成事实，支持用户显式接续，不自动恢复或回放外部调用。
- 用真实本地文件和进程验证失败与中断路径，不使用文件哈希校验。

升级完成后由用户重新启动 Pi 或执行原生 `/reload`。插件不保存、读取或接续升级批次。
