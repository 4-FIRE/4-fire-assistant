# 4-FIRE Assistant

按工作区启用的 Pi 投资扩展。模型负责分析与规划；FFA 提供资料入口、可追溯工具和执行保障。

提供研究、技术分析、回测、交易机会分析、专家协作和受控业务变更，包括交易。不维护独立 CLI、模型登录或任务调度器。

## 安装

需要 Pi 1.1.0、Linux、Node.js 22.19+。普通计算需要 Python 3.11+。

先在本仓库安装依赖：

```bash
npm ci --ignore-scripts
```

再从目标投资工作区根目录安装本地包：

```bash
pi install --local /绝对路径/4-fire-assistant
pi
```

按 Pi 提示确认项目信任。模型、认证和会话继续使用 Pi 原生配置。本地包直接加载 TypeScript，不需要先构建。

本包保留 private=true，不提供 npm 发布版本。只支持从投资工作区根目录启动，不向父目录搜索 FFA 状态。

## 初始化与使用

| 状态 | 行为 |
| --- | --- |
| 未初始化 | 仅提示 `/ffa init`，不加载投资角色、技能或业务工具，不创建业务文件 |
| 初始化未完成 | 仅提示，执行 `/ffa init` 才接续 |
| 已完成 | 启动时自动加载投资能力，等待用户请求 |

执行 `/ffa init`，确认当前目录后通过对话准备资料和来源。需验证真实行情及历史 K 线，由完成工具核实记录，再由用户确认。交易服务可选。

完成后执行 Pi 原生 `/reload`，刷新角色、技能和业务工具。以后从根目录启动会自动启用。重载或退出会暂停未完成初始化，不自动继续。

直接向模型说明目标。研究、技术分析、回测和机会比较由模型组织；包内技能提供 FFA 服务接入与交易操作约定。个人信息不足时可先分析公共证据，给出条件化建议并说明个人适配限制。

角色提供职责和关键边界，服务手册与计算参考按需读取。研究员不加载包内操作技能索引；复核员只加载交易技能。用户工作区技能保持原有加载方式。技能随整个 FFA 包分发，单独加载时仍需相关 FFA 工具与共享参考，不保证复制单个目录即可使用。

| 命令 | 用途 |
| --- | --- |
| `/ffa init` | 开始或接续初始化；已完成时刷新资源 |
| `/ffa status` | 查看启用状态与待核对变更 |
| `/ffa revoke` | 撤销当前准备和未消费的复核许可 |
| `/ffa resolve ID 核对依据` | 用户确认人工结案，不重发 |
| `/ffa python /绝对路径/bin/python` | 确认共享 Python 解释器 |

所有 FFA 确认窗口默认选择取消。TUI 窗口完整显示详情，详情可滚动，底部操作区保持可见。

使用 ↑↓ 滚动，PgUp/PgDn 翻页，Home/End 到首尾。使用 Tab 切换取消与确认，Enter 执行选择，Esc 取消。窗口过小时只能取消，放大终端后才能确认。

确认窗口居中显示，宽度最多 100 列。来源接入默认显示连接、凭据引用、操作影响、执行要求、操作名称、短说明和参数签名。短说明只取首个非空行，最多 80 列；完整返回字段、公式和多行说明不放入摘要。

按 D 切换摘要与完整配置；切换后重新选择确认。摘要不代替完整 schema、CLI 参数绑定或交易实际参数。

RPC 使用 Pi 原生确认请求，标题与完整详情分开传送；布局由 RPC 客户端负责。没有确认通道时，初始化、接入变更和业务变更均不能授权。Pi 自带的 MCP OAuth 登录窗口不由 FFA 修改。

## 资料与工具

根 `AGENTS.md` 提供资料导航与已确认的工作区约定。`areas/` 保存长期目标与结论，`projects/` 保存需要保留的研究过程和证据，`knowledge/` 保存可复用知识，`sources/` 保存服务手册，`scratch/` 保存临时计算。包内规则不复制到工作区，已有用户正文保留。

服务手册记录文档依据、数据含义、接口关系、覆盖缺口和验证回执；当前定义与许可状态通过 `ffa_sources` 获取。`.ffa/` 保存初始化状态、来源、回执与独立交易账本。

主要工具：

- `ffa_status`、`ffa_sources`、`ffa_source_read`、`ffa_record`：业务状态、原生查询与真实回执。
- `ffa_configure_source`、`ffa_discover_source`、`ffa_finish_initialization`：连接确认、完整发现与初始化完成。
- `ffa_python`、`ffa_delegate`：可追溯计算与按需专家。
- `ffa_prepare_change`、`ffa_execute_change`：业务变更准备与受控执行，包括交易。

`ffa_sources` 展示完整已知能力目录，包括待分析、禁止和不可用项目。指定 `source` 筛选来源，再指定 `operation` 查看原生定义、分析和执行要求。

MCP 先确认连接，再发现全部工具并逐项分析。CLI 根据完整帮助和文档建立已知目录，记录覆盖缺口。不能按当前任务或模块名称挑选接口。

操作分为 `observe`、`change`、`unresolved`；业务用途自由描述，不能代替权限判断。新发现的能力不自动授权。所有可见能力均已分析后才能完成初始化；仍无法确定的项目保留并禁止执行。

FFA 管理的 MCP 使用私有连接，不再向 Pi 注册原生工具，也不显示在 `/mcp`。通过 FFA 目录和工具调用。用户自行配置的 Pi MCP 仍由 Pi 管理。FFA 只支持环境变量凭据，不提供 OAuth 管理。

所有活动中的 FFA 工具均可直接调用，也可由 Pi 原生 codemode 调用。它们自动进入 `ALL_TOOLS`，并归入 `ffa` namespace；没有另建注入机制。工作区未启用或工具关闭时不可调用。FFA 不强制开启 codemode。

每个工具声明 `outputSchema`，脚本直接取得结构化对象。例如：

```js
const catalog = await tools.ffa_sources({});
return catalog.sources.map(source => source.id);
```

`ffa_record` 的对象包含分页 JSON 文本 `text`，这一字段仍是字符串。失败抛错会拒绝调用；带业务数据的失败结果仍返回对象，应检查 `success`、`state` 或 `failed`。同一来源的发现、配置和调用按顺序执行；跨来源的独立查询可用 `Promise.allSettled()` 收集异常。

有依赖的调用按业务顺序 `await`。确认与专家任务需要等待时间，不设置过短的脚本截止时间。脚本失败不撤销已完成操作，变更不得自动重试。

来源配置见[连接说明](resources/references/connections.md)，Python 环境与限制见[计算说明](resources/references/compute.md)。

## 变更与恢复边界

所有变更都需要精确准备与用户确认。普通变更使用 `confirmation`；涉及资金、订单、后续自动执行或其他敏感影响的变更使用 `independent`，还需独立复核。

发送前记录可靠提交后才调用服务。超时、异常或不完整回执保持未知，阻止本工作区所有新变更，仍允许观察和研究。

聊天分支、重载和重启不能回退账本或恢复许可。人工结案不授予重发许可。服务受理不等于成交，也不保证同一账户跨工作区防重。

专家使用 Pi 持久会话，研究员可按当前分支的 expertId 追问；复核使用新的独立上下文。接受 Pi 原生恢复，不保证精确恢复中断的工具调用。已保存产物可以继续使用，未确认副作用不自动重放。

Python、Bash 和扩展具有宿主权限，不是沙箱。不要通过其他 MCP 配置重复暴露已接入的交易服务。

当前工作区格式为 `ffa-pi/2`，业务数据库版本为 2。不兼容历史工作区，不转换旧来源，也不为旧意图补默认执行要求。不支持的格式会报错，不自动迁移、重建或删除历史数据。请使用新的独立工作区；旧工作区有结果不明操作时，先核对外部事实。

## 验证状态

类型检查、依赖检查与测试覆盖真实 Pi package 加载、无干扰状态、CLI 查询、Python 计算、服务校验、旧调用失效和交易存储约束。没有使用假模型、模拟服务、个人凭据或真实交易。

工具 API 定义放在 `src/tools/`，业务规则放在 `src/services/`。`npm run check` 使用 dependency-cruiser 检查依赖方向和循环。开发原则见[架构要求](docs/architecture-guidelines.md)，模块责任与验收边界见[技术设计](docs/technical-design.md)，来源与执行规则见[能力接入设计](docs/capability-design.md)。

**真实模型协作、实际行情服务初始化、MCP 服务与交互确认仍需获准环境验收。** 本地测试通过不等于可以直接投入实盘。

```bash
npm run check
npm test
git diff --check
```
