# 4-FIRE Assistant

按工作区启用的 Pi 协作扩展，用于学习与知识积累、任务与项目推进、研究与决策支持，并提供投资分析与受控交易能力。

模型负责分析、规划与任务协调；ffa 提供资料入口、专家协作、可追溯计算和受控调用。投资能力包括技术分析、回测与机会比较。不提供独立 CLI，不自动开展任务或交易。

## 安装

使用 Linux、Node.js 22.19+。先安装 Pi，确保 `pi` 命令可用，并配置原生模型与认证。仓库锁定的 Pi 开发与测试版本为 1.1.0；其他宿主版本的兼容性需另行验证。Python 计算需要 Python 3.11+。

推荐从目标工作区根目录通过 GitHub 安装，并使用 `--local`：

```bash
pi install --local git:github.com/4-FIRE/4-fire-assistant
pi
```

`--local` 将包声明写入当前工作区的 `.pi/settings.json`，避免在其他项目全局加载。Pi 管理 Git 仓库检出和包依赖，无需手动克隆或构建。按 Pi 提示确认项目信任；模型、认证和会话使用 Pi 原生配置。

本包不提供 npm 发布版本。每次从工作区根目录启动；ffa 不向父目录查找状态。

本地开发时，在源码仓库执行 `npm ci --ignore-scripts`，再从目标工作区执行 `pi install --local /绝对路径/4-fire-assistant`。本地路径安装直接加载原目录，不复制源码；请保留该目录及其依赖。

## 初始化

1. 执行 `/ffa init`，确认工作区目录。模型工作前，程序从 `resources/templates/workspace-agents.md` 创建缺失的根 `AGENTS.md`，以目录树提供初始资料索引；已有文件不覆盖，插件更新也不会自动替换。
2. 通过对话说明目标，整理相关资料与工作约定。不要求接入外部服务，也不强制设置目标市场。
3. 助手主动询问已有或希望接入的 CLI/MCP 工具，引导提供名称、用途、官方文档或现有配置位置，不索取凭据值。可以暂时跳过或以后再接入；目录、连接验证或手册未完成不阻塞初始化。
4. 完成工具检查根资料入口与权限、展示已注册能力，再由用户确认启用。未完成的接入分别报告，不当作已验证或可执行。不要求行情或历史 K 线回执；投资工作区可提交已确认的目标市场。
5. 执行 Pi 原生 `/reload`，加载完整能力。

根 `AGENTS.md` 必须非空，内部权限配置必须有效。能力接入按需维护 `providers/AGENTS.md` 和各 `providers/<id>/GUIDE.md`，完成目录与查询验证；这些接入工作可在启用后继续。程序检查结构，不证明接口可用或数据含义正确；验证结论仍须由助手核验，实际调用仍检查权限、参数、目录与连接绑定。

投资数据和交易能力提供方均为可选。安装包、信任项目、启用工作区、接入能力和批准交易是不同操作。

| 工作区状态 | 启动行为 |
| --- | --- |
| 未初始化 | 仅提示 `/ffa init`，不创建业务文件，不接管普通 Pi 工作 |
| 初始化未完成 | 保留已有资料；执行 `/ffa init` 才接续 |
| 已完成 | 自动加载工作区能力，等待用户请求 |

重载或退出不会自动继续初始化。公共协作提示词保存在包内 `resources/prompts/workspace.md`，显式初始化期间及已启用工作区的主会话与专家自动加载，与工作区 `AGENTS.md` 共同使用。工作区文件独立维护，不同步包内规则。更新插件后，执行 `/reload` 或重新启动加载新版提示词，无须为此执行 `/ffa update`；提示词更新不自动改造已有工作区。重载会取消正在运行的专家，请先完成或停止任务。

## 日常使用

直接向模型说明目标。以下用途可以组合，不是必须选择的工作区类型：

| 用途 | 范围 |
| --- | --- |
| 学习与知识积累 | 理解概念、练习、总结与沉淀方法 |
| 任务与项目推进 | 明确目标、整理资料、协作执行、交接与复盘 |
| 研究与决策支持 | 收集证据、分析比较、提出方案与核验结论 |

投资是专业应用领域，可以同时涉及以上用途。模型按任务选择方法、资料和专家，不执行固定流程。个人信息不足时，可以先分析公共证据，再说明个人适配限制。

| 命令 | 用途 |
| --- | --- |
| `/ffa init` | 开始或接续初始化；已完成时重载资源 |
| `/ffa update` | 将已初始化工作区适配到已安装插件的目标版本；中断后显式接续 |
| `/ffa status` | 查看启用状态与待核对调用 |
| `/ffa agents` | 查看当前分支专家、报告和会话，或停止执行 |
| `/ffa resolve ID 核对依据` | 使用 `ffa_provider_call` 返回的 `intentId` 确认人工结案，不使用专家 `runId`，不重发 |
| `/ffa python /绝对路径/bin/python` | 确认共享 Python 解释器 |

| 工具 | 用途 |
| --- | --- |
| `ffa_providers` | 查看全部已知能力摘要、当前权限；指定接口取得完整调用定义 |
| `ffa_provider_manage` | 读取可编辑配置、注册或更新连接、增量维护 CLI 目录、刷新 MCP 目录、修改结果契约与权限 |
| `ffa_provider_call` | 发送一次显式业务调用 |
| `ffa_provider_record` | 分页读取意图和回执，不发送 |
| `ffa_finish_initialization` | 核实初始化条件并请求完成确认，仅在初始化时提供 |
| `ffa_update_workspace`、`ffa_finish_update` | 在 `/ffa update` 后确认资料修改方案、执行程序阶段和确认每版完成 |
| `ffa_status`、`ffa_python` | 查看状态、保存计算产物，初始化后提供 |
| `ffa_agent` | 委派专家，查询、等待、停止或补充指令，初始化后提供 |

以上是模型工具，不是终端命令。未启用时不提供业务工具；显式初始化期间只提供管理、目录查询、调用、记录读取及完成初始化工具，完成后通过 `/reload` 加载其余能力。

活动工具可直接调用，也可由已启用的 Pi 原生 codemode 调用。ffa 不强制开启 codemode；启用方法按所用 Pi 版本的原生配置处理。脚本须检查结构化结果中的业务状态，为批准或专家任务留足等待时间。有依赖的操作按顺序等待；脚本失败或超时不撤销已完成操作，也不能作为重发依据。

能力接入使用管理工具的 read/register/update/discover；修改前按对象读取可编辑数据及版本，CLI 目录仅提交本次新增或替换的接口。MCP 只提交连接，原生目录由程序发现。配置、权限和发现分别报告结果；配置已保存但发现失败时只需刷新，不重复注册。字段与示例见[配置参考](resources/skills/provider-connections/references/configuration.md)。

### 专家协作

用 `ffa_agent { action: "list" }` 查看职责和当前分支执行。内置 `general-purpose`、`researcher`、`reviewer`；工作区 `agents/<name>.md` 补充同名职责或定义新专家。名称使用字母开头的字母、数字、`_` 和 `-`；`coordinator` 不可委派。旧 `roles/` 不读取、不自动搬迁，已有文件保留。

模型工具为 `ffa_agent`；目录和管理列表使用复数 `agents`。参数为 `action`、`agent`（职责名）、`runId`（执行 ID）、`message`（任务或补充信息）、`mode`（`foreground/background`）。按操作严格校验字段，不接受与该操作无关的参数。

| action | 必要参数 | 行为 |
| --- | --- | --- |
| `start` | `agent`、`message` | 新建执行，可选 `mode`，默认前台阻塞 |
| `continue` | `runId`、`message` | 从已结束执行的可用检查点新建一轮，继承职责，不传 `agent`；可选 `mode` |
| `steer` | `runId`、`message` | 给已启动的运行任务补充信息，不重启 |
| `list` | 无 | 返回 `agents` 职责定义和 `runs` 当前分支执行 |
| `read/wait` | `runId` | 读取或等待结果，可选 `offset/limit` 分页 |
| `stop` | `runId` | 请求取消排队或运行任务 |

前后台与接续共用 5 个名额，超额排队。所有目标操作都使用结果中的 `runId`，且目标必须属于当前主会话分支。接续产生新 `runId`，不能与同一会话的活动执行并发；运行中追加信息必须用 `steer`，排队、启动或已结束时不能补充。`messageStatus=queued` 只表示补充信息入队，在工具批次后的安全边界交付，不表示模型已阅读；`handled` 表示输入入口已处理。

结果包含 `runId/agent/message/mode/state`、报告、错误、用量，以及可用的只读 `checkpoint`。报告分页使用 `offset/limit` 和 `nextOffset`。领取完成结果后不重复通知；查看器只观察，不领取模型结果。

后台完成后自动推进原请求。按 Esc 中断主会话时，后台专家继续，但自动推进和新的批准请求暂停；下一次普通输入后恢复。对话框中的 Esc 只取消或关闭该对话框。需要彻底停止时使用停止入口。切换会话、fork、树导航、重载或关闭会取消专家，恢复聊天不自动重跑。

专家启动时跟随主模型和原生认证，不需要单独登录。研究员和通用专家可接续当前分支检查点；复核每次新建独立上下文。`state=completed` 仅表示交付成功，不表示复核通过或获得调用许可。失败、取消和中断保留已有产物，不能自动重跑。

专家读取包内技能和工作区 `.agents/skills/`，同名工作区技能优先；不继承任意扩展，也不提供继续委派专家的工具。主会话职责可通过 `agents/coordinator.md` 补充，但 `coordinator` 不可委派。

所有专家都能使用原生基础工具。默认交回报告与产物引用，由主会话汇总；仅用户要求修改资料时才直接修改相应内容。计算产物可正常保存。write/edit 保留内部状态保护和工作区外修改确认；共享工作区不提供文件副本或沙箱，同文件写入串行不能防止分析结论互相覆盖。明确委派写入时应分配文件责任。Bash、Python 仍具有宿主权限。

专家执行和子会话检查点保存在 Pi 会话历史中，不另建任务数据库。报告与接续按当前分支读取；用量通过工具结果归集，不保证后台即时进入宿主统计。

详细边界与验证限制见[专家协作设计](docs/feat/agent-collaboration.md)。

### Python 计算

默认解释器为 `/usr/bin/python3`。需要其他依赖时，由用户准备共享 Python 或 uv 环境，再用 `/ffa python /绝对路径/bin/python` 确认；ffa 不自动安装依赖。

`ffa_python` 接受 `code`、可选 `inputs` 和 `owner`。省略 `owner` 保存到 `scratch/runs/<id>/`；指定 `projects/名称` 或 `areas/名称` 时保存到对应目录的 `runs/<id>/`。每次运行保存源码、输入、状态和可用输出，失败或取消也保留已有产物。单次运行限时 30 秒，进程输出上限 2 MiB。

包内可选 `ffa_compute` 提供指标和 A 股单标的、多头日线回测，不代表全部研究能力或实盘规则。依赖、产物格式与算法限制见[计算参考](resources/references/compute.md)。

### 工作区升级

`/ffa update` 不下载或安装插件。GitHub 安装可从目标工作区执行 `pi update git:github.com/4-FIRE/4-fire-assistant`，再在 Pi 中执行 `/reload`。本地路径安装需更新来源目录的源码；锁定依赖变化时，先在包仓库执行 `npm ci --ignore-scripts`。不要把 Pi 自身更新与工作区升级混用。当前目标工作区版本为 1，现有有效工作区属于基础版本 1。无需升级时，不写入版本记录、不备份、不启动模型任务。

有后续版本要求时，程序逐版检查脚本与说明。模型先读取资料并提交文件方案。用户确认后，程序备份并完成内部变更，模型再合并资料。完成工具检查程序阶段与资料条件，用户确认后才记录该版版本。

中断后不自动继续；再次执行 `/ffa update` 接续。新增范围或改变方案须补充确认。升级期间建议暂停日常业务，但没有强制业务锁。

备份在内部状态目录中永久保留，包含一致的数据库快照。不提供回滚，不能用旧备份覆盖后续交易记录。最后一版完成后，手动执行 Pi 原生 `/reload`。

本功能不转换不支持的存储格式，不发送交易，也不重放外部调用。模型资料合并与跨会话接续仍需获准环境验收。详细边界见[工作区升级设计](docs/feat/workspace-update.md)。

### 确认操作

确认窗口默认选择取消。↑↓ 滚动详情，PgUp/PgDn 翻页，Home/End 到首尾。Tab 切换选择，Enter 执行，Esc 取消。窗口过小时不能确认。

能力提供方配置可按 D 切换摘要与完整配置；切换后需重新选择确认。RPC 使用 Pi 原生确认请求，布局由客户端负责。没有确认通道时，需批准的操作不能执行。

## 工作区资料

| 位置 | 内容 |
| --- | --- |
| `AGENTS.md` | 资料导航与已确认的工作约定；已有正文不覆盖 |
| `areas/` | 长期目标、约束与结论 |
| `projects/` | 需要保留的任务过程、代码、证据与结论 |
| `knowledge/` | 可复用知识 |
| `providers/` | `AGENTS.md` 导航与各 `<id>/GUIDE.md` 手册、覆盖缺口和验证依据 |
| `scratch/` | 临时计算与可重建产物 |
| `agents/` | 主会话与专家职责补充、自定义专家定义 |
| `.agents/skills/` | 工作区专业方法；专家读取此处技能，同名定义优先于包内技能 |
| `.ffa/` | 内部状态、权限、能力目录、回执和调用账本 |

包内角色与技能不复制到工作区；新初始化创建空 `agents/` 目录，不复制内置职责。资料按任务保存，简单问答不强制创建项目。模型通过专用工具修改内部状态，不直接编辑 `.ffa/`。

工作区就绪后，可直接要求“整理当前项目及进行中任务的资料”或“检查交付并结项”。助手使用 [项目资料维护技能](resources/skills/project-maintenance/SKILL.md)，根据已有结果同步正文、状态和导航；正常工作中发现相关变化时也可调用。是否遗漏由模型检查，不保证自动发现所有问题。

目标市场可在初始化时写入状态；不涉及目标市场时可省略，不写入默认市场。维护投资资料后应核对 `ffa_status` 的市场字段；当前没有初始化完成后的专用市场修改入口。资料与状态不一致时报告缺口，不直接改写内部状态。

## 权限与安全边界

`.ffa/permissions.json` 是唯一工具权限来源。用户可用外部编辑器维护，不要在确认期间修改。管理工具的权限 suggest 模式只补缺失规则；set 模式可经确认修改规则，null 恢复继承默认权限。

| 权限 | 行为 |
| --- | --- |
| `allow` | 直接调用，不要求本次批准 |
| `ask` | 请求用户批准本次调用 |
| `review` | 助手事先组织方案独立复核；调用仍需用户批准 |
| `deny` | 禁止调用 |

未配置工具使用 `default`，初始为 `ask`。交易接入建议 `review`。**程序不核验独立复核是否完成。** 权限不证明接口的业务影响；交易工具设为 `allow` 后，也不再要求复核或本次批准。

- 注册成功不等于验证成功，验证成功不等于获得执行许可。连接失败时，可以继续整理目录和手册。
- CLI 必须通过 PATH 直接执行，配置只保存命令名，不接受绝对路径或 shell 别名。每台机器需准备软件与 PATH；已有绝对路径配置通过接入工具重新确认，不自动转换。
- 先检查能力提供方原生认证及已有 profile。配置中的凭据字段只接受环境变量引用，不保存凭据值。
- ffa MCP 使用私有连接，不显示在 `/mcp`。官方 MCP 调用不受 ffa 审批和记录。
- Python、Bash 和扩展具有宿主权限，不是沙箱。ffa 权限只约束自己的调用路径。

### 结果不明与恢复

每份调用记录最多发送一次。相同参数的新调用是新请求，不自动去重，也不得因失败自动重发。

超时、异常或结果不明时，先保存并核对记录。受理不等于成交；没有业务结果契约时，成功只表示协议调用完整返回。回执保存失败会停止后续发送。

取消、聊天分支切换、重载和重启不回滚外部操作，也不恢复批准。交易账本独立于聊天分支。未知记录不自动阻塞其他调用，但不授权重发；人工结案只保存核对结论。

聊天使用 Pi 原生恢复，例如 `pi --continue` 或 `pi --resume`。恢复未完成的专家记录时标为 `interrupted`，不自动恢复执行；协调者检查已有交付后显式决定后续。

工作区格式为 `ffa-pi/1`，业务数据库版本为 1。不支持旧格式转换或自动迁移，不重建或删除历史数据。不支持的工作区应保留；有结果不明操作时，先核对外部事实。

## 开发与验证

```bash
npm run check
npm test
git diff --check
```

`check` 检查 TypeScript、依赖方向和循环；`test` 构建 `dist/` 后运行 Node 测试。不要手工修改 `dist/`。用 `npm pack --dry-run` 检查包内容。

Node 测试不安装可选 Python 计算库依赖，也不替代算法测试。准备 `python/requirements.lock` 中的依赖和 pytest 后，可执行 `PYTHONPATH=python/src python -m pytest -q python/tests`；环境与许可要求见 [Python 计算库说明](python/README.md)。

本地测试使用真实文件、SQLite、进程和 Pi SDK，不使用假模型、模拟能力提供方、个人凭据或真实交易。真实模型协作、外部 MCP、按需接入和宿主交互仍需获准环境验收。本地测试通过不代表可以投入实盘。
