# 4-FIRE Assistant

按工作区启用的 Pi 投资扩展。模型负责分析与规划；ffa 提供资料入口、可追溯工具和受控调用。

支持研究、技术分析、回测、机会比较、专家协作和交易操作。不提供独立 CLI，不自动开展研究或交易。

## 安装

使用 Linux、Node.js 22.19+。仓库锁定的 Pi 开发与测试版本为 1.1.0；Python 计算需要 Python 3.11+。

在本仓库安装依赖：

```bash
npm ci --ignore-scripts
```

从目标工作区根目录安装本地包并启动 Pi：

```bash
pi install --local /绝对路径/4-fire-assistant
pi
```

按 Pi 提示确认项目信任。模型、认证和会话使用 Pi 原生配置。包直接加载 TypeScript，无需先构建。

本包为私有包，不提供 npm 发布版本。每次从工作区根目录启动；ffa 不向父目录查找状态。

## 初始化

1. 执行 `/ffa init`，确认工作区目录。
2. 通过对话准备投资资料，接入目标市场的数据能力提供方。
3. 查询真实行情和历史 K 线，整理数据含义及使用手册。
4. 由完成工具检查回执、目录和资料，再由用户确认启用。
5. 执行 Pi 原生 `/reload`，加载完整能力。

交易能力提供方可选。安装包、信任项目、接入能力和批准交易是不同操作。

| 工作区状态 | 启动行为 |
| --- | --- |
| 未初始化 | 仅提示 `/ffa init`，不创建业务文件，不接管普通 Pi 工作 |
| 初始化未完成 | 保留已有资料；执行 `/ffa init` 才接续 |
| 已完成 | 自动加载投资能力，等待用户请求 |

重载或退出不会自动继续初始化。更新本地源码包后也用 `/reload` 加载修改。

## 日常使用

直接向模型说明目标。模型按任务选择方法、资料和专家，不执行固定研究流程。个人信息不足时，可以先分析公共证据，再说明个人适配限制。

| 命令 | 用途 |
| --- | --- |
| `/ffa init` | 开始或接续初始化；已完成时重载资源 |
| `/ffa update` | 将已初始化工作区适配到已安装插件的目标版本；中断后显式接续 |
| `/ffa status` | 查看启用状态与待核对调用 |
| `/ffa agents` | 查看当前分支专家、报告和会话，或停止执行 |
| `/ffa resolve ID 核对依据` | 用户确认结果不明调用的人工结案，不重发 |
| `/ffa python /绝对路径/bin/python` | 确认共享 Python 解释器 |

| 工具 | 用途 |
| --- | --- |
| `ffa_providers` | 查看完整能力目录、当前权限和原生定义 |
| `ffa_configure_provider`、`ffa_discover_provider` | 确认配置与初始权限、刷新 MCP 目录 |
| `ffa_provider_call` | 调用能力提供方，或分页读取已有调用记录 |
| `ffa_finish_initialization` | 核实初始化条件并请求完成确认，仅在初始化时提供 |
| `ffa_update_workspace`、`ffa_finish_update` | 在 `/ffa update` 后确认资料修改方案、执行程序阶段和确认每版完成 |
| `ffa_status`、`ffa_python` | 查看状态、保存计算产物，初始化后提供 |
| `ffa_agent` | 委派专家，查询、等待、停止或补充指令，初始化后提供 |

活动工具可直接调用，也可由 Pi 原生 codemode 调用。脚本须检查结构化结果中的业务状态。有依赖的操作按顺序等待；脚本失败不撤销已完成操作。

### 专家协作

用 `ffa_agent { action: "list" }` 查看职责和当前分支执行。内置 `general-purpose`、`researcher`、`reviewer`；工作区 `agents/<name>.md` 补充同名职责或定义新专家。名称使用字母开头的字母、数字、`_` 和 `-`；`coordinator` 不可委派。旧 `roles/` 不读取、不自动搬迁，已有文件保留。

唯一工具名为 `ffa_agent`（单数，操作一次执行），目录和管理列表仍使用复数 `agents`。主要参数统一为 `action`、`agent`（职责名）、`runId`（执行 ID）、`message`（任务或补充信息）、`mode`（`foreground/background`）。

| action | 必要参数 | 行为 |
| --- | --- | --- |
| `start` | `agent`、`message` | 新建执行，可选 `mode`，默认前台阻塞 |
| `continue` | `runId`、`message` | 从已结束执行的检查点新建一轮，可选 `mode` |
| `steer` | `runId`、`message` | 给已启动的运行任务补充信息，不重启 |
| `list` | 无 | 返回 `agents` 职责定义和 `runs` 当前分支执行 |
| `read/wait` | `runId` | 读取或等待结果，可选 `offset/limit` 分页 |
| `stop` | `runId` | 请求取消排队或运行任务 |

前后台与接续共用 5 个名额，超额排队。所有目标操作都使用结果中的 `runId`，不再另传会话标识。接续产生新 `runId`，不能与同一会话的活动执行并发；运行中追加信息必须用 `steer`。`messageStatus=queued` 只表示补充信息入队，在工具批次后的安全边界交付，不表示模型已阅读；`handled` 表示输入入口已处理。

结果包含 `runId/agent/message/mode/state`、报告、错误、用量，以及可用的只读 `checkpoint`。报告分页使用 `offset/limit` 和 `nextOffset`。领取完成结果后不重复通知；查看器只观察，不领取模型结果。

后台完成后自动推进原请求。按 Esc 中断主会话时，后台专家继续，但自动推进和新的批准请求暂停；下一次普通输入后恢复。对话框中的 Esc 只取消或关闭该对话框。需要彻底停止时使用停止入口。切换会话、fork、树导航、重载或关闭会取消专家，恢复聊天不自动重跑。

专家启动时跟随主模型和原生认证，不需要单独登录。研究员和通用专家可接续当前分支检查点；复核每次新建独立上下文。`state=completed` 仅表示交付成功，不表示复核通过或获得调用许可。失败、取消和中断保留已有产物，不能自动重跑。

所有专家都能使用原生基础工具。默认交回报告与产物引用，由主会话汇总；仅用户要求修改资料时才直接修改相应内容。计算产物可正常保存。write/edit 保留内部状态保护和工作区外修改确认；Bash、Python 仍不是沙箱。

详细边界与验证限制见[专家协作设计](docs/feat/agent-collaboration.md)。

### 工作区升级

`pi update` 更新插件；`/ffa update` 不下载或安装插件。当前目标工作区版本为 1，现有有效工作区属于基础版本 1。无需升级时，不写入版本记录、不备份、不启动模型任务。

有后续版本要求时，程序逐版检查脚本与说明。模型先读取资料并提交文件方案。用户确认后，程序备份并完成内部变更，模型再合并资料。完成工具检查程序阶段与资料条件，用户确认后才记录该版版本。

中断后不自动继续；再次执行 `/ffa update` 接续。新增范围或改变方案须补充确认。升级期间建议暂停日常业务，但没有强制业务锁。

备份在内部状态目录中永久保留，包含一致的数据库快照。不提供回滚，不能用旧备份覆盖后续交易记录。最后一版完成后，手动执行 Pi 原生 `/reload`。

本功能不转换不支持的存储格式，不发送交易，也不重放外部调用。模型资料合并与跨会话接续仍需获准环境验收。详细边界见[工作区升级设计](docs/feat/workspace-update.md)。

### 确认操作

确认窗口默认选择取消。↑↓ 滚动详情，PgUp/PgDn 翻页，Home/End 到首尾。Tab 切换选择，Enter 执行，Esc 取消。窗口过小时不能确认。

能力提供方配置可按 D 切换摘要与完整配置；切换后需重新选择确认。RPC 使用 Pi 原生确认请求，布局由客户端负责。没有确认通道时，需批准的操作不能执行。

## 工作区资料

| 位置 | 内容 |
| --- | --- |
| `AGENTS.md` | 资料导航与已确认的工作约定；已有正文不覆盖 |
| `areas/` | 长期目标、约束与结论 |
| `projects/` | 需要保留的研究、代码与证据 |
| `knowledge/` | 可复用知识 |
| `providers/` | 能力提供方手册、覆盖缺口与验证依据 |
| `scratch/` | 临时计算与可重建产物 |
| `agents/` | 工作区专家职责补充与自定义定义 |
| `.ffa/` | 内部状态、权限、能力目录、回执和调用账本 |

包内角色与技能不复制到工作区。资料按任务保存，简单问答不强制创建项目。模型通过专用工具修改内部状态，不直接编辑 `.ffa/`。

## 权限与安全边界

`.ffa/permissions.json` 是唯一工具权限来源。用户可用外部编辑器维护，不要在确认期间修改。接入工具只添加缺失规则，保留已有用户设置。

| 权限 | 行为 |
| --- | --- |
| `allow` | 直接调用，不要求本次批准 |
| `ask` | 请求用户批准本次调用 |
| `review` | 助手事先组织方案独立复核；调用仍需用户批准 |
| `deny` | 禁止调用 |

未配置工具使用 `default`，初始为 `ask`。交易接入建议 `review`。**程序不核验独立复核是否完成。** 权限不证明接口的业务影响；交易工具设为 `allow` 后，也不再要求复核或本次批准。

- 注册成功不等于验证成功，验证成功不等于获得执行许可。连接失败时，可以继续整理目录和手册。
- 先检查能力提供方原生认证及已有 profile。配置中的凭据字段只接受环境变量引用，不保存凭据值。
- ffa MCP 使用私有连接，不显示在 `/mcp`。官方 MCP 调用不受 ffa 审批和记录。
- Python、Bash 和扩展具有宿主权限，不是沙箱。ffa 权限只约束自己的调用路径。

### 结果不明与恢复

每份调用记录最多发送一次。相同参数的新调用是新请求，不自动去重，也不得因失败自动重发。

超时、异常或结果不明时，先保存并核对记录。受理不等于成交；没有业务结果契约时，成功只表示协议调用完整返回。回执保存失败会停止后续发送。

取消、聊天分支切换、重载和重启不回滚外部操作，也不恢复批准。未知记录不自动阻塞其他调用，但不授权重发。人工结案只保存核对结论。

工作区格式为 `ffa-pi/1`，业务数据库版本为 1。不支持旧格式转换或自动迁移，不重建或删除历史数据。不支持的工作区应保留；有结果不明操作时，先核对外部事实。

## 开发与验证

```bash
npm run check
npm test
git diff --check
```

`check` 检查 TypeScript、依赖方向和循环；`test` 构建 `dist/` 后运行 Node 测试。不要手工修改 `dist/`。用 `npm pack --dry-run` 检查包内容。

本地测试使用真实文件、SQLite、进程和 Pi SDK，不使用假模型、模拟能力提供方、个人凭据或真实交易。真实模型协作、外部 MCP、行情初始化和宿主交互仍需获准环境验收。本地测试通过不代表可以投入实盘。
