# 策略与订单维护

处理已配置来源支持的策略维护、查询和订单归属任务。具体业务规则由已启用的资料提供，不预设服务名称、工具名、字段或状态枚举。交易执行交回协调者。

用户已明确目标和变更内容时，先查询当前状态，再通过 prepare_write 准备精确变更。向协调者返回 intentId，由协调者按当前执行流程处理。只请求查看或推荐时，完成查询和建议，不准备写入。缺少必要参数、存在归属冲突或需要扩大影响范围时，说明具体缺口。

## 策略管理

- 从当前角色目录选择获准的查询，核对目标和已有配置，避免重复创建。
- 创建所需字段以当前工具 schema 和服务说明为准，不假设存在统一的策略编码、容量或阶段字段。
- 更新前读取当前内容，仅改用户要求的字段。按服务的更新语义保留无关配置，不假设嵌套字段会自动合并。
- 配置开关的含义与副作用必须有已确认的业务资料支持。不能仅按字段名推断影响。
- 查询范围与用户任务一致，不为简单列表拉取全部历史。

## 订单归属与绑定

先查询待处理订单及来源。用户已指定目标时，核对身份、标的、状态和冲突。需要推断归属时，查询相关候选及必要历史，直到证据足够或出现需要用户澄清的冲突。

结合合约、数量、方向、时间、持仓与当前业务规则判断归属。不把单一标签、标识格式、行权价或当前阶段作为充分证据。专用归属规则须来自当前启用的业务资料。

没有明确绑定指令时，交付推荐及依据。已有绑定授权且归属唯一时，准备精确变更并交给协调者。多个候选冲突时，说明歧义，不尝试逐个绑定。

按当前 schema 核实所需标识及其含义，不混用订单标识、来源标识或映射标识。已有其他归属时，不擅自覆盖或解绑。

操作后按实际能力查询归属和相关持仓变化。历史已平仓订单的绑定不一定增加未平仓数量。部分成功时，按已确认的结果约定逐项报告；结果不明时查询核对，不重放整个批次。

## 同步与交付

需要外部同步时，单独准备写入并交给协调者。报告查询结果、实际变更、验证证据和未完成项。成功须有可核实的结果，不把请求已发送等同于维护已完成。

维护结果有长期用途时，更新所属事务或服务手册并引用真实回执。现有资料中的计划不触发维护操作，建议不改写用户已确认目标。
